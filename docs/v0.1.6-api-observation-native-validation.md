## UI 干扰控制实验

接入前先获得 p1 snapshot，再停留在 p2。native attach 和 Network.enable 的前后，原生 listTabs 均显示 p2 active。随后 UI 直接使用原 p1 引用，计数由 0 到 1。

UI 保存合成值后，再获得 p1 snapshot 并停在 p2。后台取得响应正文；读取前后 p2 active，下一轮 UI 调用也先读到 p2 active。该轮直接使用原引用成功，计数由 1 到 2。计数读回和截图发生在点击后，未用重新 snapshot 掩盖失效。

持续采集期间多个 UI 调用和原生正文/流读取并存；没有观察到回调所有权被替换或事件被 UI 调用抢走。这是本机实测，不推导为独立操作系统进程或所有宿主版本的隔离保证。

## 正文与协议对账

两类 SSE 均有 51 字节非空初始缓存，后续为 13、63、61 字节，总计各 188 字节；SHA-256 均为 b98db25fea21596aa079fdf4896662a397505646108079094ef851138388c225。与服务端逐消息原始字节完全一致，无重复、缺失或乱码。

EventSource 有两个增量块在服务端关闭前落盘，最后一块关闭后落盘；POST 的三个增量块均在响应结束前落盘。不能声称所有事件都在连接存续期间落盘。

WebSocket 的服务端实际发送两个网络分片，浏览器向监控提供一条完整文本消息；适配器没有重复重组。双向二进制含 0、127、128、255 等字节，按 Base64/原始字节核对。文本、二进制、消息顺序和方向均与独立 oracle 一致。

合成 HTTP 409 的正文保留 SYNTHETIC_CONFLICT；状态、正文和业务结论保持分开，采集器没有生成业务通过或缺陷结论。

## 控制权与清理

交接后，listTabs 和一次只读原生发送均返回 EGO_TASK_SPACE_USER_IN_CONTROL。采集器在 handOff 返回后 29 ms 记录拒绝，随后停止并清除自有回调；未发现 handOff 返回后新增网络事件记录。

29 ms 是调用返回到本地记录拒绝的间隔，不是浏览器权限改变瞬间的精确延迟，也不是原子撤销保证。服务端继续发出两条时，采集文件的大小和 SHA-256 完全不变，证明本次停止落盘有效。

恢复由用户已明确批准的 UI 步骤发起，采集器没有自动 claim/takeOver。新会话取得读回响应后正常释放；补测正常 WebSocket 的会话也正常释放。失去控制时无法发出 detach 的原会话只记录延后释放，不能宣称宿主已原子撤销旧订阅。

最终自建 Space finish，独立枚举确认只剩原有两个 Space。第一个服务按时限退出，第二个经停止接口退出；PID 与监听端口均独立读回为不存在。仍缺少首段原生会话的宿主级释放回执。

## 首次异常与修正

最初合成 WebSocket 服务收到客户端关闭确认后重复发送关闭帧。监控真实记录 Close received after close，页面 close=1006、wasClean=false。

检查夹具及协议记录后，另存修订夹具并启动独立服务，复测相同文本、二进制与分片消息。正常结果为 code=1000、reason=complete、wasClean=true，监控无帧错误。原夹具、原异常、UI 结果与截图均保留。这是自建夹具问题，不登记为 Ego 或业务缺陷。

准备修订夹具的首次 shell 内联脚本因引号损坏而语法失败，没有执行修改；改成 UTF-8 文件后执行成功。它不计入接口能力结果。

## 实现候选与未覆盖范围

建议后续采用独立 native-only 适配器。空回调检查、单个待完成原生命令、自有 session、控制权检查和有界缓冲属于确定性数据处理；AI 继续自主决定查询、补测与业务判断。

未验证：正式 network 命令、完整安装包、真实业务、长期资源占用、导航重绑定、iframe/worker、磁盘/内存上限、敏感数据策略、不同浏览器版本、全部网络异常、产品级 SSE 解析。此原始字节探针未实现多行 data/CRLF 解析器，不把它们算作本轮通过。

上述控制与清理章节保留初次执行的观察；N8 的新补测结论另存，未修改原批次证据。后续实现应保留本机已验证的生命周期边界，并对未验证的异常路径和其他宿主版本公开限制。
