# v0.1.6 N8 原生资源释放与完整清理：补测记录

> 历史版本记录（v0.1.6）：以下“当前/尚未/待验证”等表述均以本文日期和阶段为准，不是 0.1.7 的最新状态。原始测试结果与限制保留；当前能力与契约见[格式说明](asset-formats.md)，分阶段验证见[云端审阅](v0.1.7-cloud-review.md)。

日期：2026-10-28。用户明确允许重新验证 N8；沿用已批准的自建 Space 受控交接、停止和显式恢复范围。

**当前结论：N8 已验证，限本机、本轮观察到的生命周期路径。** 本次补足了会话释放的独立状态证据，不再只以清空回调、停止写盘或结束 Space 作为旧会话已释放的依据。初测“无法判断”的原始结果与材料保留，不补造原批次的释放回执。

## 验证方法与依据

使用一个全新的自建 Space，在其中创建专用 about:blank 诊断页。该页不经过 Page.snapshot、Page.screenshot 或 Page.evaluate，避免 SDK 自身附着干扰判断。

独立观察上下文只通过官方 native bridge 定向读取该页的 Target.getTargetInfo，不对诊断页 attach。协议中 attached 的定义是目标是否存在已附着的客户端：[官方 TargetInfo 定义](https://github.com/ChromeDevTools/devtools-protocol/blob/master/pdl/domains/Target.pdl)。

先观察无附着基线，再用已知存活的采集会话校准 attached=true；正常 detach 后应回到 false。通过这个校准后，重复交接退出场景。观察端跨整个实验保持同一运行上下文，交接期间遵守控制权拒绝并暂停，显式恢复后再读状态。

本次不依赖“另一个上下文查询旧 sessionId 报不存在”来判断释放，因为校准发现：跨上下文在会话仍存活时就会收到同样的错误。

## 实际结果

同一诊断目标始终保持存在，直到最后显式关闭；观察到的 attached 序列为：

| 阶段 | 目标存在 | attached | 证据说明 |
| --- | --- | --- | --- |
| 观察端初始基线 | 是 | false | 独立观察端自身没有给诊断页增加附着 |
| 正常采集会话存活 | 是 | true | 已知存活会话的正向校准 |
| 正常 disable/detach 后 | 是 | false | 取得命令回复及匹配 sessionId 的 detached 事件 |
| 第二个采集会话存活 | 是 | true | 交接前确认该会话确实附着 |
| 交接、采集上下文退出、显式恢复后 | 是 | false | 旧会话没有执行越权 detach；恢复后目标仍开放，已不存在附着客户端 |

正常释放读回为 15:41:06.155（Asia/Shanghai）。第二个采集上下文在 15:42:25.830 结束；显式恢复后，15:42:26.463 读到诊断页仍存在且 attached=false。它发生在最终关闭诊断页和 Space 之前，因此不是“关闭页面后附着自然消失”造成的混淆。

不能据此确定交接期间精确的释放时刻，也不能在交接、上下文退出、显式恢复这几个宿主阶段之间独立归因。已验证的是这一完整受控路径结束后，目标仍开放而原生附着已释放。

## 最终清理证据

15:44:51.109，关闭诊断页返回 success=true；随后的 Target.getTargetInfo 返回目标不存在，当前 Space 的页列表中也不再有它。

观察上下文随后结束，并确认其自有回调已清。15:45:50.746，独立枚举确认自建 Space 已不存在，原有 Space 0、1 保留；尝试列出已结束的测试 Space 页面返回 EGO_TASK_SPACE_NOT_FOUND。

没有启动合成 HTTP 服务或其他后台服务；本次新增的运行上下文均已结束。未终止共享的 Ego/Node 宿主进程，因为 PID 不是本次独占资源的边界。

## 用户最小化操作的处理

测试期间用户告知误将 Ego 窗口最小化，并允许重新观察。实际读取时窗口已经是 normal，没有执行恢复尺寸命令。只观察了默认页，没有给专用诊断页增加 SDK 会话。该窗口观察材料是用户界面上下文，不参与 N8 的释放判定，也不作为原生资源状态的替代证据。

## 结论边界

本次可以将 N8 能力结论从“无法判断”更新为“已验证”，并与原有 N1～N7 的限定验证范围汇总为八项已验证。

这不等同于证明：交接瞬间原子撤销、全部异常崩溃路径、所有 Ego 版本、内存/句柄计数绝对归零，或完整监控产品验收。原始批次没有取得的旧会话回执依然没有被补写；本次验证了相同问题类别的新受控生命周期。

本轮仅增加验证脚本、外部证据和文档更新，没有修改产品功能代码、Ego 安装、已安装 Skill，也未发布。
