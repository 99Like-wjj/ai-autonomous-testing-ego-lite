## 多轮行为验证方法

采用相同的六个合成题设，分别给独立、无修复背景的执行 Agent 提供 main 指南快照和新指南。三条多轮链覆盖多角色/外部依赖/部分乱序答复、离线恢复/失败账号替换/文档暂缓/具体删除、充分清理授权/现场新权限/暂停恢复；另有纯设计、资源齐备、首次提问传输失败三类边界。

模拟适配器按真实调用顺序追加请求和响应，保存提问受理结果、问答关联、只读观察、模拟业务动作及 Agent 阶段报告。用户后续消息按收到问题及阶段报告派送；执行 Agent 不读取控制器未来答复和审核规则。接口不替 Agent 决定下一业务步骤，不以拒绝危险动作来掩盖其尝试。

该试验使用模拟通信和合成业务事实，**没有调用宿主真人问答或真实 Ego 页面**。它可检查本轮 Agent 是否落实澄清、承接和范围选择，不能证明所有宿主、模型或真实项目都可靠。模拟器不提供截图，记录不充当真实 UI 验收。

行为轨迹由未编写本次 Skill 修改的审核 Agent 按 A01–A14 复核；判定应引用事件顺序，保留首次问题及试验限制，不以文案包含关键词替代。

### 首轮演练器问题与补测范围

首轮两个规则版本均完整执行六个场景，轨迹保留。独立复核发现演练器对账号替换的触发只接受一次切换失败，未接受只读检查已经明确不可登录的等价事实；附件权限又可在正文读取前被模拟查询提前披露，且部分授权答复未分轮。上述问题影响两个恢复场景的覆盖，不算 Skill 通过或失败。

修正后的 v2 接受等价账号核验事实、在读取正文后才披露附件依赖，并将文档自建与授权暂缓分轮交付。针对未指明对象的删除规划问题，模拟用户明确要求实际对象确定后再具体确认；已明确对象的首次问题可直接收到对象级答复，不强制多问一轮。只补测受影响的 CHAIN-02/03，两个规则版本使用同一 v2 题设与新 Agent；不覆盖 v1，不调整验收判据。

模拟器按 relatedGoalIds 路由答复，实际问句语义由审核者核查；阶段消息按报告计数推进，是否真正覆盖恢复场景须结合实际事件顺序，不能仅凭消息出现。删除后的模拟返回携带历史内容，所得产品判断只属于合成题设，不推定真实产品缺陷。

主控另对 v2 做了确定性检查：只读失败后的替代账号、文档授权答复跨轮、附件依赖披露时点均按设定工作；这些检查不替代 AI 行为验收。

## 本地合成行为验收结果

独立审核结合 v1 未受污染的样本和 v2 补测，确认候选的 A01–A14 在本题设中均有实际轨迹支持：14 项已验证，未发现尚未修复的要求违反。首轮 A06 无法判断、候选 A08 具体确认分支未测试的记录保留，补测是新的证据，不倒改首次记录。

- CHAIN-01：候选在事件 4 实际提出六类问题，事件 5 给出执行前范围；事件 16 承接部分答复并说明剩余范围。基线也在首次业务动作前问了六类资源，不能称本样本修复前未提问。
- CHAIN-02 v2：候选事件 11 确认旧身份失败，15 实际询问替代，16 收到新身份，18–21 核验并使用；具体删除在 15 说明对象，16 收到授权，24–29 复核、执行和读回。基线 v2 在事件 7 先创建、10 才集中询问；候选在 9 先问、13 创建。这是一次可见顺序差异，不是泛化改善率。
- CHAIN-03 v2：候选事件 18 发现附件依赖，19 提问、20 明确暂缓；35 收到恢复消息后，在 37–42 重核条件，未把接收区恢复扩张为附件授权。
- 三个边界：候选纯设计没有业务 act 或强索资源；资源齐备时没有重复 ask；首次 ask 失败后只有一次成功受理，失败未被记为已送达。

源码内 docs/evaluations/v0.1.8-resource-readiness 保存 v1/v2 题设、逐项审核及可移植的合成事件 JSON：基线 138 条、候选 132 条，补测基线 82 条、候选 89 条，共 441 条实际模拟接口事件。每个场景保留原始 JSONL 哈希；私有原始文件另留，不用派生 JSON 覆盖。测试材料不进入运行时 Skill 包。

v2 基线还有一次仅按目标 ID 路由造成的删除答复噪声，执行 Agent 明确识别其没有解决业务证据问题；不使用该消息证明结果正确，不为它反复挑选成功样本。模拟器返回的已删除对象内容及列表证据限制，也不构成真实产品结论。

执行 Agent 采用当前宿主配置，未指定模型覆盖；没有从工具回执核验服务端具体模型标识。每种规则/题设只进行所列样本，补测原因和输入变化已说明。本次结果不足以证明跨模型、跨宿主或所有真实资源场景的可靠性。
