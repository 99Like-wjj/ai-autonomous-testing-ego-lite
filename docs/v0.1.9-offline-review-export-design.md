# v0.1.9 离线 HTML 评审结果导出优化方案

日期：2026-11-03。状态：**已实现，工程自测及 Ego 实际导出验证通过**。其他宿主尚未独立验收，实际结果及限制见[验证记录](v0.1.9-offline-review-export-validation.md)。

用户要求：本地离线 HTML 自身能够导出评审结果，不启动服务器，移除必须通过服务器才能保存的设计。本文替代当前审阅保存方案中的服务依赖；历史设计、用例、反馈、运行及证据保留原样。

## 1. 目标与推荐方案

将用例审阅页做成完整的离线工具：打开 HTML → 填写意见 → 核对范围和结论 → 导出评审 HTML → 重新打开阅读或在用例页恢复意见。

主要交付是一份**可阅读、可恢复的评审结果 HTML**。文件中同时包含可直接阅读的正文和完整结构化评审数据。JSON 作为可选的数据导出，不再要求用户通过双击 JSON 阅读评审结果。

页面的导出由浏览器本地完成。删除本机 HTTP 服务、能力探测、会话地址、端口和连接状态。CLI、Ego 及 Node 不参与用户点击导出的过程，也不要求常驻进程或额外安装。

保留当前场景总览、逐条评审、意见暂存、范围校验和人工确认边界；普通测试执行和业务目标四态不在本次修改范围内。

## 2. 用户操作与界面

顶部统一使用“导出评审结果”。预览对话框先显示总体意见、逐条意见、导出范围、未填写意见数量和拟提交结论。

| 操作 | 行为 |
| --- | --- |
| 保存评审结果 HTML | 默认操作；生成一份独立可读、可恢复的 HTML |
| 导出 JSON 数据 | 可选操作；输出与 HTML 内嵌数据一致的结构化内容 |
| 复制完整评审数据 | 提供完整 JSON，包含范围、版本、指纹、意见及拟提交结论；不依赖剪贴板权限时可手动选中复制 |
| 恢复评审记录 | 通过文件选择读取评审 HTML 或 JSON，校验后恢复意见 |

只有无导出范围、未记录任何意见或明确的“无修改意见”、以及有意见未纳入范围时阻止导出，并就地说明原因。浏览器不支持某种保存 API 时改变保存方式和说明，不让用户面对一个没有可执行替代操作的禁用按钮。

“未填写意见”不等于“无修改意见”。文件中的拟确认结论仍只是评审反馈意图；导出不登记正式审阅、不修改用例、不启动测试。

## 3. 浏览器本地保存

采用一个小型保存模块，根据实际能力选择两种无服务器方式，不建立插件或适配器注册体系。

### 3.1 支持文件选择器时

用户点击后立即调用 `showSaveFilePicker()`，由用户选择文件名和位置，再写入生成的文件。写入关闭后，通过所获句柄重新读取，比较实际字节与本次导出快照，核对通过才提示“已保存并核对内容”。默认建议独立的新文件名，避免正常导出覆盖用例原件和旧评审文件。

该 API 有用户操作、安全上下文和来源方面的限制，不能仅凭存在同名函数就认定当前宿主可用；需要处理实际调用被拒绝的情况。[Chrome 文件访问文档](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[File System Access 规范](https://wicg.github.io/file-system-access/)

`file://` 是否按可信上下文处理存在浏览器实现差异，必须在真实离线文件及目标宿主中验证。[Secure Contexts 规范](https://www.w3.org/TR/secure-contexts/)

### 3.2 不支持或不允许文件选择器时

提供“下载评审结果 HTML”和可选 JSON 下载，文件仍在当前离线页面内生成；另保留完整数据的复制/手动选中路径。

浏览器下载只能提示“已发起下载”，不能宣称已经写入、读回或可在 Windows 中打开。若选择器调用被拒绝，页面保留快照和草稿，展示可再次点击的下载操作；不在失去用户操作上下文后偷偷重试下载。用户主动取消保存时只提示取消，不自动触发其他导出。

一次默认操作只保存一个 HTML，避免连续要求多个文件选择或触发多文件下载拦截。需要 JSON 时由用户另行点击。

### 3.3 Windows 可打开性是验收条件

**更换扩展名、改 MIME 或使用文件选择器，都不能直接当作 Windows 拦截已解决。** Chromium 的文件写入实现也可能执行安全检查并添加来源标记。[Chromium 实现说明](https://chromium.googlesource.com/chromium/src.git/+/main/content/browser/file_system_access/file_system_access_safe_move_helper.h)

开发先用最小合成文件验证目标宿主上的两种保存方式，再接入正式审阅页。当前用户使用的 Codex 内嵌浏览器必须列入实际检查；Ego、桌面 Edge/Chrome 另行记录结果，不能相互代替验收。

在声明支持的宿主中，至少要有一条路径完成“离线页操作 → 实际保存 → Windows 正常重新打开 → 恢复相同评审数据”。仅得到下载成功提示不通过。如果当前内嵌宿主的所有纯网页保存路径仍被限制，应明确报告该宿主尚未验收，不能改用服务器或把它包装为已解决。

## 4. 评审文件与数据完整性

HTML 正文由完整评审快照生成，展示项目、用例版本、范围、拟提交结论、总体意见、测试点编号/标题及对应意见。将完整 `ReviewFeedback` 嵌入唯一的 `review-feedback-data` 惰性 JSON 区。

评审结果 HTML 使用内联样式和静态正文，阅读不依赖脚本、原用例文件、浏览器存储或外部资源。恢复时只提取并解析数据区，不执行文件脚本或加载其中资源。用户文本按文本转义，不能插入可执行 HTML。

继续使用现有 v9 反馈结构，保留 `projectId`、`caseVersion`、`sha256`、`expectedReviewNumber`、`pointIds`、全部 `comments`、`decision` 及来源说明。用例定义和内部用例文档模型不因保存方式改变而升版。

每次点击导出固定一个不可变快照，HTML、JSON和核对依据均使用该快照。保存期间的新编辑继续保留，完成时若当前内容已变化，明确说明“已保存的是导出时的版本，当前还有新修改”。

生成文件前执行相同范围和字段校验，并对生成的 HTML/JSON 做内存解析往返核对。该检查证明生成内容一致，不冒充磁盘读回或 Windows 打开验证。

恢复文件时拒绝项目、版本、指纹、编号或范围不匹配；现有不同意见保留并显示冲突。不能静默覆盖、丢弃范围外意见或把旧文件当成本次人工确认。

## 5. 代码及 Skill 调整范围

| 位置 | 计划调整 |
| --- | --- |
| `src/review-ui/app.ts` | 移除 `nativeBase`、连接探测和 HTTP 保存；改为离线导出快照、保存状态和明确错误处理 |
| `src/review-ui/` | 新增小型本地保存模块，处理文件选择器、下载及取消；不承载业务判断 |

| `src/report/case-reader-shell.mts` | 更新导出预览、按钮及提示；去掉服务器连接和“当前是离线副本所以不能保存”的交互 |
| `src/report/case-reader.mts` | 离线 HTML 内联全部导出能力；删除回执中的服务器启动指引；页面 `connect-src` 收紧为 `none` |
| `src/report/review-session.mts` | 删除该 HTTP 审阅服务实现 |
| `src/scripts/ego.mts` | 删除 `cases serve` 的导入、分发、参数和帮助，不保留启动别名 |
| `src/contracts/layout.mts` | 从运行分发集合移除审阅服务，加入实际需要的共享纯模块 |
| `tests/` | 删除对应服务功能测试，保留反馈校验/CLI 文件事务测试，补充离线导出与真实浏览器验收 |
| Skill 和当前文档 | 同步更新 SKILL、case-authoring、local-toolbox 中英文、语言来源说明、README 中英文、架构、格式说明、当前审阅指南和 AGENTS 导航 |

`cases export-review` 可以保留为无服务器的可选 CLI，用于 AI 接收到反馈文件后的数据整理；它不是 HTML 导出成功的必要步骤，也不作为浏览器导出故障的默认替代流程。

版本化历史设计保留，并注明新方案已替代服务依赖；不能为了文案统一重写历史验证结论。

Skill 中当前要求启动 `cases serve` 的段落改为以下原则：

> 用例 HTML 自身提供完整离线评审、导出和恢复。用户直接从页面导出可读 HTML，可选导出 JSON；不启动审阅服务器。导出前核对全部意见及所选范围，保留用例版本和指纹。文件保存不登记正式确认、不启动测试。AI 接收实际反馈后，核对来源和内容，再按原机制登记审阅。

## 6. 验证与完成标准

| 检查 | 必须看到的结果 |
| --- | --- |
| 无服务、断网、直接打开本地 HTML | 能填写、核对并导出，页面不发送 HTTP 请求、不探测 localhost |
| 有一条意见、总体意见、明确无修改意见、多条长意见 | 范围和全部内容完整进入 HTML，选用 JSON 时与内嵌数据一致 |
| 文件选择器保存 | 通过真实用户点击保存，关闭写入后实际读回相同内容；取消不误报成功、不清空草稿 |
| 下载保存 | 实际找到下载原件并重新打开，不用下载通知代替验证 |
| Windows 重新打开 | 在目标宿主产生的文件可正常阅读；记录是否仍受安全策略影响，原文件标记不改动 |
| 独立可读与恢复 | 移动导出 HTML 后仍可阅读，导回同版本用例页后意见、范围、拟提交结论一致 |
| 数据拒绝和冲突 | 错项目/版本/指纹、未知编号、范围遗漏、损坏内容、特殊字符均正确处理，已有意见不丢失 |
| 存储不可用、保存期间继续编辑 | 仍能通过显式导出保存意见；保存完成不会将新编辑误报为已保存 |
| 服务器移除 | CLI、运行文件清单、当前指南及页面运行行为均无审阅服务入口 |
| 历史保护 | 原用例指纹、旧 HTML/JSON、已下载反馈、审阅记录及运行证据保持原样 |

先验证保存能力，再抽取共享生成器、接入离线交互、移除服务并同步文档。完成相关工程测试后按仓库要求执行 typecheck、npm test、check:public 和 diff 检查。真实宿主保存与打开验收单独记录，工程通过不能替代它。

## 7. 对当前资料的影响

旧 HTML 不会因升级自动获得新功能。实施完成后，使用原用例 JSON 在新的交付目录重新渲染，不覆盖旧文档，不改变已确认目标和用例指纹。

用户已写意见仍属于原浏览器草稿或实际导出文件。重开、换浏览器或交付新版页面前，先保管完整结构化反馈；从已保存的 HTML/JSON 或完整数据显式恢复，不假定不同页面与浏览器自动共享存储。

用户随后已确认按本方案实现、自测，并用最新构建在新目录重新生成原用例审阅页。安装、候选包和真实业务测试不在本次实现范围内；原用例、旧文档及业务测试记录保持原样。
