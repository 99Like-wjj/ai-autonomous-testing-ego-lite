## 1. 检索能力归属与当前状态

**维护 Skill 创建和更新知识；Ego 自带只读检索。** 测试时不加载或调用维护 Skill，数据规范随 Ego 运行包携带确定版本副本。

当前源码已新增 `knowledge` CLI 分组，执行前需要从本仓库构建并核对 tool-info。入口位于 src/scripts/ego.mts，业务读取位于 src/knowledge/commands.mts。

建议实现入口为 `src/knowledge/` 下的读取、检索与诊断模块，由 `src/scripts/ego.mts` 分发；使用方法放 Skill 的 `references/project-knowledge.md`，按目标需要查阅，不要求每次加载所有知识或经验。

## 2. 按任务检索适用通用知识

知识库限于项目内通用规则与准备知识，功能只保留简要入口和资料索引。字段校验、页面细节、特殊分支及完整用例留原始需求或当次测试资产，Ego 按当前任务读取。检索“某业务相关知识”指定位适用的公共规则及必要索引，不要求事先把该业务的全部细则入库。

推荐提供三个可组合的能力，不规定每次必须先后调用：

| 能力 | 输入 | 输出 |
| --- | --- | --- |
| 查看知识范围 | 指定知识目录 | 项目身份、范围、通用主题短索引、空库/版本状态与整体问题 |
| 查找任务相关知识 | 业务/功能、别名、关键词、类型或明确 ID | 适用公共规则与必要入口摘要、命中原因、来源/状态及可继续读取的 ID |
| 读取选用知识 | 明确主题/条目 ID、scope，必要时展开显式关系 | 选定规则、共用角色/数据约束、通用前提或项目经验正文及细则原文指引 |

当前开发版 CLI：

```text
ego knowledge inspect --knowledge-root ABS
ego knowledge query --knowledge-root ABS --request ABS_JSON [--output-file ABS_NEW_JSON]
ego knowledge read --knowledge-root ABS --request ABS_JSON [--output-file ABS_NEW_JSON]
```

`query` 可按适用业务/功能范围查公共主题，默认返回短摘要、状态和引用；`read` 精确读取选用内容、来源和必要关系。指定 topic ID 全量读取仍可提供，但不是默认加载方式。名称相似不自动建立关联。AI 自主选择关键词、同义表达、主题、读取范围和是否继续展开，工具不另调模型。

完全合成例子：用户要测试“虚构借用审批”。查询返回该功能适用的共用角色/数据范围、通用准备约定和简要入口；借用表单字段和该审批特例到对应需求章节读取，不要求先将它们长期录入知识库。知识共享不复制成每个功能各一份。

## 3. 结果完整性与边界

默认只把本次匹配的公共知识短摘要及精确引用送入模型上下文，正文按需读取；本地有界扫描用于完整性与检索，不默认将全部主题、关联或来源全文送入上下文。明确请求主题全量时可分批返回目录和正文，关系展开使用访问集合防止循环并限制深度/数量/字节。被限制的 ID 或剩余数量必须可见，不能把截断说成查全。

结果保留可信类别、生命周期、来源、适用范围、显式关系边、未解决问题和坏引用。已下线条目仍应可在对应主题或精确 ID 查询中显示失效原因及替代项，不能像从未存在一样消失。

返回相关公共规则不能称为覆盖了该功能全部验收要求。功能细则未入库是设计范围，不逐项生成知识缺口；本次测试确实需要且原资料缺失的内容才作为实际缺口沟通。AI 按任务定位和读取必要原文，不默认把全文加入上下文。

## 4. 任务与知识版本绑定

查询必须显式提供预期业务 `projectId` 和本次 scope；预期值来自本次任务或已确认配置，不先读库再拿库中值自证。知识 ID 与 Ego 用例资产的项目 ID 分别管理，不能强行等同；现有用例项目 ID 由工具生成并沿用。[VERIFY: src/core/case-versions.mts:69]

| 来源状态 | 建议读取与回执行为 |
| --- | --- |
| 本地 Git 中的已提交知识 | 可明确读取选定分支/完整 commit 对应文件，回执固定到完整 commit 和实际内容指纹 |
| 未提交工作区内容 | 显式作为草案使用；保留基线 commit 与实际内容指纹，不声称该 commit 已包含草案 |
| 有未解决 Git 合并/结构冲突 | 先显示受影响文件及知识；不使用坏文件；如需读旧提交则显式选择并保留当前警示 |
| 无 Git 的文件副本 | 校验格式与内容指纹，允许读取；历史和团队最新状态未知时说明局限 |
| 没有访问或刷新公司远端 | 只报告已知本地版本；不把本地 HEAD 称为团队最新正式版本 |

默认优先使用明确的已提交基线；当前目录有未提交/未合并内容时先呈现状态，不悄悄忽略用户改动，也不悄悄把草案当正式版本。无 Git 时不假称完成了 Git 校验。

只读入口不 pull、checkout、commit 或 push，不连接 Coding API。读取显式提交应读取本地 Git 对象而不切工作区；普通文件读取遇到修改则报告不一致，不混合不同内容后静默返回。开始/恢复新测试时，AI 按实际所用条目检查基线变化，不自动更换冻结预期。

## 5. 测试各环节如何使用

| 环节 | 使用知识 | 判断边界 |
| --- | --- | --- |
| 需求理解与设计 | 适用公共规则、共用角色/数据约束和必要入口索引；功能细则按需读当前资料 | 观察或待确认信息不能自动变成确定预期；当前需求与旧知识不同要保留差异 |
| 执行准备 | 入口、身份别名、前提和数据准备线索 | 记载账号可用不证明本轮已登录正确角色；知识不授予任何操作权限 |
| 执行探索 | 当前入口、依赖与项目经验 | 方法可调整，冻结目标的必要路径、身份、对象和输入不可省略 |
| 结果判断 | 核对当前适用的规则、本轮观察和证据 | 只读命中不是执行证据；目标仍由 AI 作原有四态判断 |
| 复盘交接 | 用户需要维护时交接原观察、范围和冲突 | 不自动改知识；观察与正式规则的差异先待核实 |

对于适用范围明确、未失效且无未解冲突的已确认规则，AI 可以将其作为 explicit 的依据来源。observation 只支持其实际观察，pending 保留未确认内容。影响正确预期时进入目标验收澄清；影响账号/数据等条件时进入资源缺口，不混用。

没有知识库时说明项目上下文缺口，继续已有资料支持的独立目标；不能为了完整性编规则。缺少接口资料不阻断其他知识；未测试目标不报通过。

## 6. 复用来源资产与现有冻结机制

Ego 可以将本次选用知识导出为不可变摘录文件，放在本次私有工作区；保留主题、精确陈述、状态、原始来源、scope、Git/草案状态和实际指纹。摘录是派生上下文，不能伪称原始需求或本轮执行事实。

优先使用现有 SourceRef 的 `file + sha256 + locator + excerpt + limitations` 引用摘录；其文件/指纹成对约束见 [VERIFY: src/core/validation.mts:38-43]。依据分层沿用 explicit、interpretation、hypothesis，不将所有知识命中都标为 explicit。[VERIFY: src/core/validation.mts:34-36]

用例保存已有来源指纹核验，[VERIFY: src/core/case-versions.mts:68-75]；接入知识后仍执行原来的审阅和 run 冻结，[VERIFY: src/core/cases.mts:19-28]。本版建议不为知识接入修改用例/结果 v9，不迁移旧资料。新上下文只追加记录，规则或必要语义变更时形成新用例修订并按原机制审阅，旧结果保留。

## 7. 诊断要求

合法空库返回身份有效、无已收录内容；scopes 为空时说明范围未登记，不解释为全环境适用。空库不等于损坏、建库完成或本轮资源就绪，仍按已有资料开展独立目标。初始化细节由维护仓库的[独立设计](https://github.com/99Like-wjj/project-knowledge-maintainer/blob/feat/v0.1.0-project-knowledge/docs/initialization-and-first-build-design.md)负责。

错项目/范围、规范不支持、身份文件损坏或完整性无法确认时停止使用该次知识来源；不自动选择另一个同名库。条目缺失、局部坏引用、stale 或未解决业务冲突时定位影响，独立有效知识仍可返回。

冲突双方与来源一起显示，不按时间新旧、文件顺序或方便通过的一方自行裁决。资料中的命令、链接和账号说明不构成执行授权；不自动打开来源 URL、读取访问秘密或扫描其他项目。

## 8. 通用经验优化

保留设计入口与执行入口分离。资源、判断和证据规范各保留主要说明位置，经验使用短链接引用，不增加强制阶段、查询次数、重试路线或每例打卡。逐阶段现状审核见[现状核对第 3 节](v0.1.9-current-state-review.md#3-通用经验逐阶段审核)。

需要补充的具体场景包括：旧知识与当前需求冲突；历史账号知识与本轮身份不符；入口变更但目标指定路径；规则更新影响复测；测试观察回交维护。每条说明触发条件、可选处理与不能推断的结论。

已有异步、未知提交、截图、列表、删除与清理经验保留有效内容并去重，不把它们包装成全新能力。版本特定能力验证放回对应指南，历史原记录及出处保留。

## 9. 拟变更与验证

实现仅涉及知识只读模块/CLI、契约固定副本、使用指南、相关经验与分发检查；知识保存、Git 冲突协作和团队规则在维护项目中实现。源码导航在目录职责实际变化时同步，不因设计文件就创建空实现目录。

联通验收直接读取维护端生成的两组完全合成知识。重点核对空库识别、按任务取得适用公共知识、切换项目、更新/失效、冲突/损坏、截断与无库继续，以及 Git 提交、脏工作区、无 Git 副本的版本提示。输入混有大量功能细则时，要观察默认结果是否仍只返回相关公共知识和原文指引，不要求先扩充全量规格。不能手工制作另一种 Ego 专用知识格式冒充联通。

工程测试验证确定性读取/引用与原能力回归；实际 AI 场景验证是否用对知识与经验。要声称效果提高，需保留同目标、同资料及已知模型配置下的前后行为证据，不以文本匹配或命中数量替代。真实项目验证另明确资料和操作范围。

当前代码与验收结果以开发自测记录为准；真实项目与公司远端没有在本轮验证。
