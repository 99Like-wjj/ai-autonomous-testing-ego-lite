## 环境与范围

- Windows，Ego 0.6.1.13、Chromium 156.0.8078.48、内嵌 Node v24.22.1，官方 Skill v2.1.0。
- 只使用 127.0.0.1 合成服务器和本轮自建 TaskSpace；没有访问真实 UAT 或生产系统。
- 使用公开的 taskSpace、Page.cdp、Page.events、snapshot、元素动作和截图等 API；没有私有 CDP 连接、代理或页面请求函数注入。
- 先冻结八个技术目标，再运行受控采集与 UI 操作。原始脚本、日志、截图、冻结目标与对账产物保存在仓库外，本轮报告交付对应私有绝对路径。

## 干扰复现与控制

第一轮：UI 保存并取得 snapshot，采集器延后读取已完成的响应正文，随后原 ref 点击失败，计数 0。重新 snapshot 后，在没有中间正文读取的控制中，点击成功至 1。

第二轮：采集器初始化结束后重新 snapshot p1，再停留在 p2；后台读取正文后，下一 UI 动作前已变为 p1 active，原 @8 再次失效，计数保持 1。点击前没有执行 evaluate/waitForFunction。停止采集后的控制同样经过 p2 snapshot，原 p1 ref 仍成功点击到 2，反驳了“仅切页必然使 ref 失效”的解释。

这证明当前接入方式与无干扰要求冲突，不证明 Chrome CDP 协议本身有缺陷。Ego 的 Page.cdp 包装层激活和 refs 失效是符合源码线索的解释，但本轮没有独立隔离协议与包装层根因。

两份采集器 ready 记录的 process.pid 相同，故仅确认独立 Ego 调用/采集段，不声称两个独立操作系统进程。第一段结束后第二段才启动，中间采集空档明确保留。

## 内容核验

对照服务端逐消息/逐字节发送记录，离线确定性校验确认：

- EventSource：242 字节，SHA-256 `7ec241680bf13593cb5074222286febcb9d515f5ed9d2e8b2204536b5d3f3d58`。
- POST SSE：57、15、78、69 字节四块，共 219 字节，SHA-256 `9c97c0a5053b2eae7b1d2b846e760a13bded6fd428902f2c6b057c8ba3cf5098`。前两块确实拆开一个 UTF-8 中文字符，合并后无乱码、重复或缺失。
- WebSocket：客户端 1 条，服务端 echo 加 3 条，文本顺序与内容完全一致；UI 显示正常关闭。

EventSource 的 ERR_ABORTED 来自页面收到 done 后主动关闭，未自动当作业务缺陷。SSE 的 streamResourceContent 在本次返回空初始缓冲，因此非空前缀场景仍有证据缺口。

## 限制与后续

未验证：非空 SSE 初始前缀、WebSocket 二进制/分片、长流、大正文、缓冲/磁盘上限、敏感数据处理、范围过滤、网络异常/HTTP错误、跨导航绑定、iframe/worker、弹窗/下载并存、用户接管、性能基准。既有其他版本的测试不能补为本轮通过。

最小后续接入合同：官方支持的被动观测能力，取得正文与流数据时不激活页面、不改变 snapshot refs，仍遵守 Space 控制权，并明确会话、事件缓冲和缺失信息语义。当前尚未证明现有公开入口符合这一合同，需要确认受支持入口或上游依赖后再提交接入调整方案。

后续核对与候选方案见[官方 native bridge 接入修订稿](v0.1.6-api-observation-native-adapter-design.md)，用户批准后的执行结果见[原生隔离验证记录](v0.1.6-api-observation-native-validation.md)。该替代候选的结果不改变本记录中的两项失败及其证据。

不能以每步强制重拍 snapshot、自建复杂 UI 调度器、注入 fetch/XHR 包装、连接私有 CDP 或缩减已批准的流式正文范围来包装为通过。
