## 4. 查询开销对比

以下对比均使用最终同一构建、Node v24.19.0、相同有效合成台账。每组预热 3 次、计时 10 次；标准台账覆盖五种合法视图／检查组合，其余规模组对比同一 summary 的两种检查范围。共 13 组、130 个计时样本；不把预热或造数时间算入结果。

| 历史 note 数 | 保留证据正文 | 轻量摘要中位数 | 严格摘要中位数 | 轻量／严格持锁中位数 |
| ---: | ---: | ---: | ---: | ---: |
| 1000 | 0 | 131.39 ms | 144.48 ms | 28.77／42.43 ms |
| 1000 | 3,510,000 B | 129.19 ms | 198.17 ms | 28.02／94.63 ms |
| 1000 | 50 MiB | 137.05 ms | 251.08 ms | 27.98／145.87 ms |
| 100 | 3,510,000 B | 122.44 ms | 184.64 ms | 17.13／81.51 ms |
| 5000 | 3,510,000 B | 197.05 ms | 266.21 ms | 87.34／156.51 ms |

标准台账单分派查询：metadata 130.11 ms、full 206.82 ms；原完整输出 204.89 ms。轻量摘要为 5468 字节，完整核验后的摘要为 5345 字节，单分派分别为 3140／3017 字节；完整输出仍为 1,272,905 字节。新增检查范围说明使紧凑输出略增，仍未展开完整历史。

**所有 metadata 计时样本的保留证据和 worker 历史引用正文读取计数均为 0。** 严格模式继续读取保留证据：标准场景 50 次／3,510,000 B，大证据场景 50 次／52,428,800 B；另读取已有 worker 引用。基线、执行台账、运行锁及安装资源仍有读取，不能称为零文件 I/O。[VERIFY: tools/benchmark-read-preload.mts:20-77]

普通样本均无锁冲突；持锁区间记录成功创建锁到删除锁，包含锁初始化与释放核对。受控交错实验另证实：2 次锁冲突、1 次过期 revision 拒绝、1 次合法写入和查询，revision 从 11 到 12；没有业务动作或自动重试。证据文件 `interleaving/contention.json`。

最终 full 输出与 C 前基准的字节相同，SHA-256：`a4d33ad72d948ba41f464c885e7a0417dcb4304ff96391ae037956a9d935fab9`。C 前后阶段的端到端数据也保留，但主要性能结论采用最终同构建的两种检查范围对照，不把不同阶段的环境波动归因于某项改动。

测量用 promises.readFile、FileHandle 异步流和锁 open／unlink 探针，不包含 OS 缓存命中率、物理磁盘读取或函数级 CPU 占比。样本是合成文本和有效台账，3 个活动分派只是记录数据，不是真实子 Agent／Space 并发测试。上述差异不代表整批业务执行加速倍数，也不能解释全部既往 UAT 耗时；5000 条历史时轻量查询仍增加到约 197 ms，说明台账解析成本仍随规模增长。[VERIFY: tools/benchmark-execution-views.mts:15-46]
