# Ego项目知识轻量化接入方案

> 跨仓库链接指向维护项目开发分支；该仓库当前私有，需要已有访问权限，不是 Ego 运行时依赖。

日期：2026-11-03。状态：**设计已批准；已实现格式v3并完成合成自测，未安装或发布。** 更新：2026-11-04。

共用格式唯一设计源为[知识维护项目方案](https://github.com/99Like-wjj/project-knowledge-maintainer/blob/feat/v0.1.0-project-knowledge/docs/project-knowledge-lightweight-design.md)。本文只规定Ego的读取、检索及AI使用，不另造账号/项目格式。[v2 设计](v0.1.9-project-knowledge-v2-integration-design.md)保留历史基线；本方案中的轻量 v3 结构与筛选规则取代旧版相应约定。

## 1. 改动目标

Ego继续直接读取用户明确给出的本地知识库，不要求先调用维护Skill，也不建立自动发现或绑定服务。四类资料仍为project、modules、rules、accounts。

| 使用环节 | 读取方式与判断 |
| --- | --- |
| 需求分析与用例设计 | 按业务查询rules和modules，读取通用规则完整正文及适用边界 |
| 准备项目入口 | 读取用户登记的project记录，理解地址和登录说明；没有完整环境表也能使用 |
| 准备测试身份 | 读取accounts的用户声明，AI按任务判断是否足够；不要求预建角色档案 |
| 定位功能 | 读取地图中的应用、页面名称和模块路径；无需解析project.pages外键 |

这不是固定执行顺序。AI按当前任务选择资料，并可复用已读取且适用的上下文。用户未提供知识库或某类内容时，继续独立资料支持的工作。

## 2. inspect / query / read

继续使用现有knowledge子命令，不增加配置解释器或专用账号工作流。格式、读取结果版本均为3；用例/运行/报告格式不因此升级。

- inspect只返回项目身份、类别存在性、数量和版本摘要。
- query返回条目id、title、短summary、tags及可读定位，不展开配置正文。
- read返回所选记录的description/properties，保留用户字段名称、嵌套和值。
- 账号query不回显登录标识、命中原文或自由配置；summary由维护AI忠实概括用途/身份/限制，不抄登录标识。
- 配置记录不套规则确认状态；读到了用户声明，不代表核验了当前权限或部署。
- 保留实际快照、usedFiles哈希、Git状态和分页；需要时仍可显式导出不可变摘录及既有SourceRef。

配置类别下每个items条目就是一条可查询记录，数量按条目计算；不把properties中的每个字段拆成独立记录或强制归为环境/页面/角色类型。

账号和项目配置的检索以id、title、summary、tags为入口，按已有关键词能力搜索。信息不足时，AI可读取候选详情或列出短摘要；不为不同项目的properties设计字段映射、权限规则或查询语言。

规则与地图保留必要的业务关键词、kinds/moduleIds/domainIds及模块/规则关联检索。请求中移除environmentId、applicationIds、scopeIds、roleIds等结构化筛选条件；地图内部的roleIds仍可用于明确角色关联展开。传入已移除条件属于参数错误，不默默忽略或解释为其他含义。

账号不再依赖roleId筛选。若需特定身份，用用户别名、摘要、标签检索，再读详细说明；工具不把“普通管理员”等文字映射为一组权限。

完全合成请求：

~~~json
{
  "expectedProject": {"id": "fictional-library"},
  "category": "accounts",
  "query": "演示环境 阅览",
  "limit": 10
}
~~~

参数由AI准备，用户仍只需自然语言给任务和知识库路径。默认预算与分页沿用现有能力，不新增全库预加载步骤。

## 3. 地图与配置分别读取

地图入口改为直接描述应用/页面和模块路径，不要求project.json先登记对应页面。地址未知时不拼接路由；需要项目首页时再查询配置。

入口有特殊要求，例如从产品首页按UI进入，AI应结合用户指令和地图说明选择方法；工具不执行固定路径，也不因有URL自动绕过必要步骤。

多应用、多环境仍能表达，但通过用户说明、地图适用范围和多个入口记录表达；不要求登记层级或为每个环境预先准备一套对象。名称不一致或存在歧义时，由AI核对当前任务，不自动推定等价。

地图的环境与身份观察保留当时描述、来源、覆盖范围和时间；历史页面可达不能升级为当前完整业务通过。

## 4. Prompt调整

本节规定指南需要表达的意图，实际措辞在实现时保持简洁。

- 项目准备：用户已给入口或配置时按实际内容使用；不为字段不齐追问整套环境信息。
- 账号准备：查询登记的身份和限制；不要求用户为知识库建立正式角色矩阵。只有当前场景缺关键身份条件时才问。
- 规则使用：遇到跨功能权限、共享、数据归属等业务问题，主动考虑查询相关通用规则；不能从账号声明推导平台全局规则。
- 导航使用：按模块级地图减少页面探索；历史入口失效时，在原授权内探索或说明无法判断。
- 缺项处理：没有知识库、没有账号或只有少量配置，不自动报错、生成全项目补充清单或扩展当前任务。
- 实际验证：登录、身份声明与业务授权分别核对；不因账户标题写“管理员”就报告有全部权限。

分析需要准备哪些账号属于明确请求的测试准备任务，不是accounts记录的隐含要求；用户提供的账号登记也不授权换号、改角色或创建业务数据。

## 5. 可用性与隔离

沿用现有not_configured、available、partial、unavailable行为：缺少可选类别不是损坏，局部配置损坏不拖垮独立有效规则。JSON非法、项目不匹配或格式不支持仍明确说明，不能静默套用。

资料读取不解析凭据引用、不自动登录、不执行自定义配置值。真实账号、项目配置和观察继续留在用户知识库，设计和合成示例留在源码仓库。

实现只支持审核后的v3，不加旧格式兼容、双读或转换。不会自动更新实际知识库、历史摘录、冻结用例或已安装Skill；安装和发布按用户另行授权执行。

## 6. 改动与验证范围

修改集中在src/knowledge、共用Schema/类型、现有CLI中必要的版本与读取接入、Skill知识指南及相关合成回归。共用契约和副本指纹必须与维护端一致。报告、浏览器执行及其他测试业务不作无关重构。

合成验收关注：最小配置可读、自定义属性完整往返、无配置仍能读地图、账号摘要不展开详细配置、规则状态与用户声明区分、错项目隔离、预算分页和来源指纹仍真实。移除旧过滤条件后，非法请求应明确报错，不能悄悄忽略。
