# v0.1.8 轻量数据与接口（最终设计）

日期：2026-11-01。配套[最终设计方案](v0.1.8-design.md)，已进入开发候选实现；核验见[开发自测](v0.1.8-development-validation.md)。本稿完整替代上一稿的通用资产契约：只管理用例文件、审阅文件和运行文件。

## 1. 版本与唯一来源

主 schemaVersion/viewVersion 统一为 9，regressionVersion 为 2，networkVersion 保持 1。不再增加 assetVersion、AssetRef 或独立 point/design/rule/task/issue 版本对象。

用例 JSON 是规范定义的唯一来源；审阅文件说明哪个版本/范围被实际确认；run 的 baseline 是所用用例文件的冻结副本，结果仍进入现有账本。HTML/Markdown 和只读查询结果均为派生展示，不成为第二份规范。

以下为已确认的类型与校验语义。当前候选由 schemas 源文件生成类型，并验证引用和事务语义；0.1.7 正式版仍为 v8，不执行这些新请求。

## 2. 用例文件

```ts
interface CasesRef {
  projectId: string;
  caseVersion: number;
  sha256: string;               // exact published JSON file bytes
}
interface SourceRef {
  id: string;
  locator: string;
  file: string | null;
  sha256: string | null;
  excerpt: string;
  limitations: string[];
}
type PlanRef = `condition:${string}` | `step:${string}` | 'requiredPath';
interface CasesFile {
  schemaVersion: 9;
  projectId: string;
  project: string;
  pointPrefix: string;
  caseVersion: number;
  previous: { caseVersion: number; sha256: string } | null;
  nextPointNumber: number;
  retiredPoints: { pointId: string; reason: string; replacements: string[] }[];
  sources: SourceRef[];
  coverage: {
    id: string; sourceRefId: string; statement: string;
    state: 'mapped' | 'pending' | 'out_of_scope' | 'retired';
    pointIds: string[]; reason: string;
  }[];
  cases: TestCase[];
  changes: { pointId: string; kind: 'added' | 'modified' | 'moved' | 'split' | 'merged' | 'retired'; relatedPointIds: string[]; reason: string }[];
  writeRequestSha256: string;   // internal retry identification, not a new ledger
  savedAt: string;              // actual UTC publication time
}
interface TestCase {
  id: string;
  title: string;
  criticalConditions: { id: string; text: string }[];
  requiredPath: string | null;
  stepOrder: 'strict' | 'adaptive';
  steps: { id: string; action: string; dependsOn: string[] }[];
  parameters: { id: string; type: 'string' | 'integer' | 'decimal' | 'date' | 'object_ref' | 'account_ref'; purpose: string; constraints: string[] }[];
  goals: {
    id: string;
    pointId: string;
    title: string;
    basis: { kind: 'explicit' | 'interpretation' | 'hypothesis'; source: string; text: string; sourceRefIds: string[] };
    expected: string;
    requiredRefs: PlanRef[];
    clarificationQuestions: string[];
    planState: 'prepared' | 'unprepared';
    preparationGaps: string[];
    sourceAlias: string | null;
  }[];
}
```

projectId 在首次保存时生成，显示名与编号前缀分开。pointId 在同一文件及项目历史中唯一，caseId/goalId 在其原有局部范围唯一；历史跨轮匹配用 pointId，不用标题。

每个已定义目标都有依据、预期和编号。prepared 目标须有非空有效 requiredRefs，引用的条件、步骤及依赖存在；声明非空 requiredPath 的用例，其 prepared 目标必须保留该路径引用。不同路径约束宜由 AI 明确拆场景，不让程序猜路径适用性。

unprepared 表示定义/计划尚不完整，须说明 preparationGaps，可以暂缺步骤引用；不能分配执行任务或用空计划获得通过。资源本轮是否就绪不改变 planState，而在运行条件中说明。

dependsOn 只指同用例有效步骤，不得自环或循环；strict 不允许依赖后序步骤。条件使用稳定 ID，筛选不改引用含义。必要条件、顺序、输入和读回是否充分仍由 AI/人工审查。

coverage 是来源覆盖说明，不是新的业务四态。pending/未映射条目保留为缺口；已知但未整理的要求不能因没有 pointId 被当作已覆盖。changes 和 retiredPoints 保留变更关系，不能删除历史编号后复用。

## 3. 保存版本与分配编号

cases save 接收完整草案、expectedVersion 和前版文件指纹。首次 expectedVersion=0；草案新增目标的 pointId 为空，工具分配后才写入正式文件。既有目标保留原编号，sourceAlias 只保留外部编号来源，不自动代替正式选择键。

请求只提交业务定义及变更说明；caseVersion、previous、nextPointNumber、savedAt 和 writeRequestSha256 由工具生成。新增目标及拆分/合并说明可先用 caseId/goalId 局部定位，发布时一次转换为实际编号关系，不额外申请编号。

事务顺序：锁定指定 cases 目录，核对前版，检查完整草案，分配新编号，写新临时普通文件并同步，使用现有无覆盖原子发布方式生成 vNNN.json。新文件同时保存 nextPointNumber、退役编号及版本关系，无需另写分配文件或更新项目索引。

正式编号只在最终文件发布后返回。若发布后回执丢失，同一 expectedVersion/同一请求指纹找到同一目标版本，读回原编号映射；不同内容竞争同一下一版本返回冲突，不自动重排或合并。发布前失败且未对外公布的临时计算不形成已分配编号。

未改变用例定义时返回已有版本的只读引用，不写新文件。换实际账号、对象、日期、运行结果、截图或展示主题，不是自动生成新用例版本的理由。

文件字节哈希与版本定位一起构成 CasesRef。目标定义指纹另外从用例中派生，不存成单独对象：包括目标依据/预期/必要引用、依赖闭包、相应条件、路径、顺序及用例参数约束。归一化只排序结构键，不擅自改写业务字符串或舍入数值。

只有同一共享目录的协调者受此锁保护。复制后的独立目录不能保证互相编号，出现同版本不同指纹必须说明分叉，不把文件锁描述为分布式服务。

## 4. 审阅文件

```ts
interface CaseReview {
  schemaVersion: 9;
  cases: CasesRef;
  reviewNumber: number;
  decision: 'comment_only' | 'changes_requested' | 'approved';
  pointIds: string[];
  comments: { pointId: string | null; text: string }[];
  source: SourceRef;
  sourceKind: 'user_statement' | 'delegated_review' | 'feedback_file';
  delegationSource: SourceRef | null;
  reviewedTargets: { pointId: string; definitionSha256: string | null }[];
  recordedAt: string;
  writeRequestSha256: string;   // internal repeat-write protection
}
```

按 v001-review-01.json 等名称保存真实意见或确认；没有独立 reviews 目录、reviewId 注册服务或反馈对象生命周期。recordedAt 是本地登记时刻，不补造团队实际操作时间。

cases review 用同一请求格式记录意见或确认。approved 必须有实际用户/已明确委托审阅者的确认定位；离线 HTML 导出的字段不自动证明真实确认。程序计算 reviewedTargets，不能接受调用者任意填写一组“已匹配”指纹。

审阅写入也按预期序号和请求指纹发布一个不可变文件；回执丢失恢复同一记录，不重复登记。相同来源的原确认不能通过再次保存冒充较新的人工确认；feedback_file 自身不升级为真实人类确认。

审阅请求给出 expectedReviewNumber、决定、范围、意见和真实来源；reviewNumber、reviewedTargets、recordedAt 和写入指纹由工具从实际用例与事务生成。这样无需让用户填写技术指纹或维护回执目录。

完整可执行计划才有非空 definitionSha256；只审阅了未完整测试点可以保存确认范围，但不因此授予执行资格。待澄清规则仍禁止 verified/violation。

新版本复用旧确认时，读取该审阅对应的原用例，重算所选点的定义指纹，与当前定义/必要计划逐项匹配。原依据缺失或有变化就不能假装已复用；AI 修订、补充来源或审阅受影响范围。用例共享参数约束变化视为可能影响该用例中的目标，不依赖关键词猜语义未变。

核对指定 cases 目录内的实际相关审阅，不能遗漏已登记的较新明确修改要求而单独选择旧批准。comment_only 不自动撤销确认；changes_requested 对其实际范围暂停复用，后续明确确认可解决；冲突或来源顺序不清时不由代码投票，AI 需澄清。

纯 HTML 主题、折叠和阅读附注不进入定义指纹。团队一次确认可覆盖全部目标，不要求按点逐次审批；实际确认只覆盖部分时，其他点仍保留在范围与缺口里。

本地文件/哈希不认证人的真实身份，不能宣称防止有宿主权限的主体直接调用浏览器。实际暂停由 Skill 和 AI 遵守，工具检查可执行范围与相应记录的一致性。

## 5. 选择与绑定

```ts
interface RunRef {
  runDir: string;
  runId: string;
  baselineSha256: string;
  resultsRevision: number;
  resultsSha256: string;
}
interface SelectionRequest {
  regressionVersion: 2;
  casesFile: string;
  cases: CasesRef;
  mode: 'points' | 'status' | 'full';
  pointIds: string[];
  sourceRun: RunRef | null;
  statuses: ('verified' | 'violation' | 'inconclusive' | 'not_tested')[];
  includeUnassessedCases: boolean;
}
interface ExecutionPlanRef {
  caseId: string;
  pointIds: string[];
  conditionIds: string[];
  stepIds: string[];
  includeRequiredPath: boolean;
}
```

points 仅在给定版本解析非空编号；status 要精确源运行和状态，保持命中整场景语义；full 不接受状态过滤。未命中返回空范围，不变全量。旧缺评估选项只影响 status 的范围，不是第五种状态。

selection 输出所选/未选编号、命中原因、候选执行引用和明确缺口，附内容指纹；它不执行测试，也不代表所有目标已获人工确认或当前资源已就绪。

start 保留 --cases 与 --binding 入口。绑定请求包含 selection、实际 reviewFiles、plans、deferred、parameterBindings、currentConditions 和 history。每个选中目标必须恰好进入一个 plans.pointIds 或 deferred 项，不静默遗漏。

plans 只列源基线中的引用，不复制步骤正文。工具对各计划所含 pointIds 重新计算 requiredRefs/dependsOn 闭包并核对原顺序、条件和路径；准备动作不增加正式目标。所有实际计划须有匹配确认，unprepared 或未确认点只能明确暂缓，不能 reserve/派发。

当前条件沿用身份、环境、对象/数据、授权、路径与来源的明确声明；参数值与等价关系留在本轮。decimal 用十进制字符串，账号只保存引用，不把凭证放进用例。程序校验类型和引用，AI 核验业务关系与授权，不增加模板表达式或规则解释器。

完整且已确认、只是资源待补的目标可以保留 plans，并在 currentConditions 明示 pending；条件在原语义内恢复时，AI 可追加当前事实后继续同 run。缺计划/缺确认而进入 deferred 的目标不原地改成可执行，准备齐后新建关联运行；资源变化本身不要求新增用例版本。

## 6. 运行格式与结果约束

baseline.json 保存所选用例版本的完整原件，不剪掉目标或重新编号。run-binding.json 保存：CasesRef、选择快照、执行引用、暂缓项、已经核对的审阅及目标指纹、本轮条件/参数和历史引用。所需内容冻结进本轮，正常读取不依赖外部项目库。

这是“完整定义＋本轮范围”，不是两套规范。由于基线物理上包含未选点，core 检查、计数、source context、工作包及报告都必须按 selectedPointIds 限定正式评估；不能只在 HTML 中隐藏未选点。

record 继续使用 caseId、mode、operationId、expectedRevision；assessment 仍通过 goalId 定位，再由基线解析 pointId。observations、contexts、actionEvents、findings 和 evidence 的职责不变，不新增独立目标账本或 executionId。

- 只允许为本轮选中的目标入账，工作者还须在所属用例/assignment 范围内。
- 未准备或明确未执行的目标由 AI 显式记 not_tested，缺记录仍是缺评估；不自动产生状态。
- verified/violation 需要有依据的实际观察及证据；verified 还须覆盖全部必要引用且无未解决缺口；未澄清标准不能判 verified/violation。
- unprepared 不能因 requiredRefs 为空获得 verified；纯未执行不伪造观察。有相关实际发现时，AI 分清它支持的事实与尚未履行的原语义，额外发现另列，不能宣称完成完整目标。
- attempt 不替换正式结论，final 可以增量登记或重评。新一轮复测必须另建 run，数据事务修订不计成新轮。
- 证据来源、所有权、同组共享范围及跨运行原件继续严格核对。旧图不因同哈希成为新采集。

sourceCaseCount/源目标数来自完整基线；selectedCaseCount/goalCount 来自本轮选择；executionGroupCount 来自实际计划。四态仅统计选中目标的正式评估，另列缺评估、未准备/暂缓和未映射需求。保留源场景→目标层级。

默认并发仍为 1。用户启用并发时继续按用例共享状态与 Space 管理，不按每个 point 新建 Space。下载观察用现有 execution 事务扩展一个 activeDownload 在途标记，具体见下载设计，不建立资源租约服务。

## 7. 历史与原问题

manifest/binding 内的 history 保存 parents:RunRef[]、primaryBaseline 和 reason；无父运行就是首次。每个源 run 选择一个精确结果修订，结果登记历史仍在该 run 内查看，不把同 run 两个 revision 算两轮。

父引用核对项目、基线、结果前缀及证据，拒绝重复、明显环路或错误指纹。不维护 series 库、独立运行索引或自动缺陷归并；AI 可在指定 runs 目录定位 manifest，基准选择必须明确。

原问题优先用 `{run:RunRef, caseId, findingId}` 定位；没有独立 finding 时，用 `{run:RunRef, caseId, goalId, operationId, phenomenonId:null|string}` 定位精确原评估。两种定位只选其一，不能按相似标题替代。

本轮 assessment 可附 problemChecks：原问题引用、reproduced/not_observed/unclear/not_checked、当前 observationIds、理由和缺口。新 finding 独立保存。它们不是新的业务四态，也不自动证明根因或修复提交。

历史报告按 pointId 关联源目标，显示旧/新定义及当前条件差异，可比性由 AI 说明。历史缺失或校验失败标 partial，不展示未经核验正文；本轮已登记证据仍按严格规则验证。

旧 v8 报告不通过兼容解析器接入。确需引用时，AI 在本轮报告上下文中保存明确来源、指纹、pointId 映射、原报告记载与整理局限，作为历史参考，不注册为 v9 run 或当前四态。

## 8. 命令与模块

| 命令 | 输入与结果 |
| --- | --- |
| validate-cases | 只读检查 v9 用例，不表示已审阅或可执行业务 |
| cases save | 完整草案＋预期前版，原子发布一个新版本并返回编号映射 |
| cases render / verify | 读取用例文件生成/核对 vNNN.html、vNNN.md、交付清单 |
| cases serve / export-review | 私有本机审阅入口及原生意见HTML/JSON保存；不登记正式确认、不执行业务 |
| cases review | 记录一次实际意见或确认到相邻审阅文件 |
| regression select / context / compare | 用例版本及精确运行引用，返回范围、规范/事实分栏和对照 |
| start | 用例文件＋绑定，冻结基线并创建空账本，不自动点页面 |
| evidence-add / record / execution / packet-seal | 复用当前事务并适配选中 pointId 与计划引用约束 |
| files inspect | 实际文件与读取选项，输出有边界的解析事实，不输出业务通过 |
| report / verify-report | 同源三格式及原件/历史附件核验 |

不增加通用 asset 命令。当前规则/任务 read/validate/commit 的规范整理能力由用例文件保存与正常校验承接；新版删除不再使用的独立对象入口，不保留两套可写规范或旧请求兜底分支。旧资料不删除，当前 0.1.7 的能力说明仍保持历史准确。

新增代码控制在 core 的用例版本/审阅帮助函数、既有回归/执行/报告调整及 files/ego-helpers；不新建 src/assets。内部复用锁、writeNew、哈希、原子发布与既有回执保护，不把这些实现细节暴露为业务对象。

错误至少区分版本不符、编号未知/退役、版本冲突、投影不符、确认缺失/不匹配、文件变化、读取受限、历史缺失/不符。错误说明已完成与未知事实，不替 AI 选择重试或替代路径。

## 9. 数据影响与验收

新数据采用 v9/v2，版本改变来自必要字段与选择语义，不来自通用资产体系。所有旧用例、规则、任务、运行、报告与证据保留；不原地转换、不只改版本号、不自动删除目录。

验证重点是一次保存分配编号、写冲突/回执恢复、退役编号、审阅版本/范围、定义未变确认复用、三种选择、完整基线中的未选点拒绝入账、未测试与缺评估、历史原问题与新发现及三格式一致性。

Schema、运行校验器、生成类型、CLI help、示例、Skill 与当前文档随实现同步；设计和工程检查不能替代实际行为验收。目录移动的显式映射通过 report --history-locations 输入，只解析明确 runId/目录并核对原身份与指纹，不建立运行注册表或扫描其他目录。
