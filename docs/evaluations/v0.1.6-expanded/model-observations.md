# 当前对话模型接入经验后的受控演练

日期：2026-10-26。依据最新开发分支构建后的 references 正文；没有调用其他模型，没有启动 Ego 或测试真实网站。本会话参与过设计，下面是使用经验后的实际生成与判断记录，不是独立盲测，也没有接入前对照。

## 第一轮 用例设计

针对 scenarios.md 的合成标签需求生成 cases.json，共 10 条、18 个业务步骤。实际调用当前构建的 validate-cases，结构检查成功。

读取设计入口与方法正文，采用边界、权限范围和持久化思路：

- 3、5 位长度上下边界，4 位内部代表，2、6 位无效相邻值；非法小写、数字和空输入代表。
- 有效样本要求重新读取同一对象，不能只看提交提示。
- 只读角色用例仅验证查看详情与编辑入口，不扩大为服务器授权证明。
- 同名问题另列 hypothesis 草案和 clarificationQuestions，不擅自规定允许或拒绝。
- 保留“从标签管理页创建”这一明确路径，不编造按钮、选择器或提示文案。

自审限制：这不是字符空间穷举，没有测试所有空白、标点或字符混合；这些可依风险补充，不声称覆盖率 100%。需求也未定义输入自动转换规则，控件若修正/截断输入，不能把转换后合法值的成功当原无效样本通过或产品缺陷，需要记录实际转换并确认其是否符合要求。生成的固定名称需要受控环境避免碰撞，不能宣称已具备执行条件。没有实际创建标签。

## 第二轮 六个执行场景判断

A 历史关联删除：选择 E-DELETE-DATA。暂停依赖历史关联数据的删除动作，请求符合原条件且获准使用的对象；可以继续独立目标或准备草案，不能拿刚建的无关联记录替代后判通过。这说明“自建自删”被作为有例外的策略，而非不分情况的禁令。

B 提交后转圈：选择 E-UNKNOWN-SUBMIT 与 E-ASYNC。保留第一次观察，先在授权范围内查看同一对象或已可用的结果渠道。当前不能判断是否生效，不再次提交碰运气。无规定时限时也不凭三秒直接判产品失败；需要结束观察时明确未知。

C 数据已存但 UI 超时：选择 E-EDIT-SAVE 并参考 E-UNKNOWN-SUBMIT 的边界及判断指南。数据持久化目标和 UI 时效目标分别呈现；明确时限被违反，整体不能因后端保存成功而全通过。结论基于题设，未推断真实根因。

D 筛选列表未见对象：选择 E-LIST。先核对过滤、页码、排序和对象标识，再决定进一步观察；目前仅能说“本次列表视图未显示”，不足以报告数据被删。

E 偶发错误：选择 E-EVIDENCE。保存已有截图、当时条件与一次性现象，说明无法安全复现和证据范围，不删除记录，也不为复现扩大副作用。是否能判定违反仍依明确要求和证据，不能仅凭截图标题认定。

F 纯格式转换：按 case-authoring 保持来源和意图，不强制加载整套设计方法或改写预期。发现实质歧义可单列问题，但不自动补成新的需求。

## 第三轮 不适用与阶段切换

G 静态帮助页：不机械生成输入边界、角色差异和状态迁移。围绕实际内容与已明确要求设计；“静态”也不等于无需验证，但不能凭空新增权限规则。

H 软删除恢复设计：选择 D-STATE 与 D-RELATION；重名冲突无规则，作为待澄清候选，保留可确定目标，不强行写恢复成功或失败。这里是设计问题，不直接套执行阶段自建自删。

I 仅整理报告：读取已有证据与报告规范，保存事实和限制，不重新设计、重跑业务或补造执行前基线。经验只辅助表述结论边界。

J 修复后复测：参考 D-REGRESSION / 既有测试策略；保留原版本失败和新版本复测记录，对受影响功能选择有依据的回归范围，不用新绿灯覆盖历史，也不毫无取舍重测全站。

## 观察结论

本次产出体现了预期的行为方向：边界和负向场景没有只剩成功路径，未知规则没有被补成断言，执行判断区分现象与结论，例外场景没有机械套用经验。以上是当前模型依据已知样例进行的人工语义走查，不应称作独立自动评测的“全部通过”。

无法据此证明这些改善由新增经验导致：没有隔离上下文、没有接入前输出，也没有其他模型或真实环境对照。因此不能给提升百分比、漏检率或统计显著性。此次价值是发现明显接入/表达问题，确认指南可被读取并用于具体决策；后续陌生实际任务仍可能暴露漏检、误用或额外阅读成本。
