# v0.1.5 开发验证记录

本页是可公开的验证摘要。真实项目名称、内部需求编号、账号、站点、对话标识、原始截图及日志仅保留在仓库外私有验证目录，不随源码或安装包发布。公开摘要不替代原始证据，也不将事后整理冒充执行前记录。

## 当前状态

当前为 `0.1.5-dev / resource-clarification-3`。资源澄清与事实一致性修订已完成限定场景专项验收；仍是开发版，尚未正式发布。专项结果不能外推为全部业务、模型或资源场景的可靠性保证。

- 资源缺口必须转为实际沟通，写入前提或 blocked 不算已经询问。
- 用户答复只解决明确覆盖的条件；只暂停依赖缺口的动作，独立已授权目标可继续。
- 同一资源事实复用可追溯来源，区分历史观察和当前状态；已提供但未核验不能写成未提供。
- 继续复用结果、证据、交付包和报告工具，没有新增资源状态机、业务分类器、固定流程或模型服务。

## 真实对话专项

两个独立任务对话实际使用 gpt-6-luna / max，输入仅包含业务目标、必要资料和授权，不提供评分表或预期澄清答案。两条对话使用同一只读权限入口任务：一条初始资料完整；另一条分批补充第二身份资料。浏览器操作串行。

| 目标 | 状态 | 观察与边界 |
| --- | --- | --- |
| 资源充分时不重复索取 | 已验证 | 使用已给身份和登录资料完成页面操作，没有重复索取账号或授权；新出现的 UI 身份冲突保留为独立问题。 |
| 部分答复保留已知与缺口 | 已验证 | 收到身份标识后承认已收到，同时仍请求缺少的登录信息，未执行依赖缺口的登录。 |
| 补齐后核验并实际恢复 | 已验证 | 补齐资料后实际登录并核验身份，再观察目标入口；不是只宣布计划恢复或收到资料即报通过。 |
| 当前摘要与资源事实一致 | 已验证 | 对话、当前结果及最终报告未再次将后续已提供的身份写成未提供；初始缺口保留为历史。 |
| 全量业务、其他模型及通用稳定性 | 未测试 | 本轮是一个 UI 目标的两个输入条件，不是总体成功率估计。 |

正向身份会话中的入口可见，但页面身份文字冲突，执行 AI 保留无法判断，没有弱化目标取得通过。负向身份的入口目标已有实际截图支持。该业务不确定性与 Skill 资源行为分别评价；未推断站点显示问题的根因。

两个任务均使用正式工具生成并核对 HTML、JSON、Markdown 报告；browserOpen=not_checked，不声称浏览器已打开验证。一个任务的执行记录包含显式目标评估；另一个任务保留首份报告，并在新目录用 retrospective context 补充现有证据上的事后目标复核，不重跑页面或改写原执行台账。

最初窗口最小化及恢复失败保留为历史尝试。用户恢复正确窗口后在同一测试 Space 继续，没有换 Space 绕过。账号操作遵从既有授权，未修改既有业务数据/权限或发送真实通知；测试自有 Space 结束后另行读回，原用户 Space 受保护。

## 较早修订的观察

早期资源指南已被读取，所需条件也被识别，但存在仅记缺口、未实际询问的执行遗漏。后续修订集中强调记录与沟通的区别、部分答复和收尾核对。

较早指南也出现过主动提问成功样本。其他样本受只读准备边界、浏览器等待、版本选择、环境和观察预算影响；预算截止本身不证明漏问。一次技术协助后的续测补齐了提问证据，但不能改写为同等条件的首次多次盲测成功。

后来还发现手写准备说明保留了旧资源状态。原记录和基线未覆盖，另存注明来源与时点的事后更正，再实施当前事实来源与派生摘要的修订。观察者更正不计作原执行 AI 已正确处理。

双语版本总览图及既有 SVG 可由仓库中的 TypeScript 生成器再现。PNG 使用构建环境中的图形库导出，不是 Skill 运行依赖。图示是能力说明，不是真实测试截图。

本地桌面及窄视口的文档、合成报告、筛选/搜索和历史显示已做过检查；不能将本地预览当作 GitHub 实际渲染验收。合成报告中的状态不代表真实资源已齐备。

完整安装包包含 Skill、引用、脚本、schema、必要文档和清单。源码 ZIP 不等同于可用安装包；构建后须检查实际版本、revision、文件完整性和指纹。公开文档整理可能改变包指纹，不能凭同名菜单或相同软件版本判断具体包。

## 限制与复核

- 输入通过原生任务委派传递，部分协作消息在本机原始参数中加密；明文交互另有注明性质的观察者副本，不冒充可直接读取的原始明文。没有读取或保留模型隐藏推理。
- 必要窗口协作、已有浏览器状态及文档选择形成比较限制，不是严格受控的人工首轮消息 A/B。
- 未验证更强模型、广泛业务资源类型、长期稳定性或全部资源均及时问全。
- 文件哈希证明留存字节一致，不认证截图、来源身份或业务判断；公开检查为启发式扫描，真实项目资料必须继续留在私有目录。

使用者可按[本地验收步骤](v0.1.5-local-acceptance.md)在自己的授权环境复核。后续合并、Tag 和 Release 遵从另行授权；开发分支或专项通过不等于正式版本已发布。
