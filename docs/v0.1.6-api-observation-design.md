# v0.1.6 接口数据监控最终设计

设计版本：v3，2026-10-28。本文汇总用户已批准的范围、native 接入授权及实际验证结果，作为后续开发基线。**实现路径已确认，产品功能尚未完成。** 本次收敛只更新设计文档。

## 1. 已确定的结论

采用 **随 Run 运行的独立 native-only 采集上下文 + 本地持久化 + AI 按需查询**。

UI 继续使用 Ego 正式 TaskSpace/Page API；采集器通过官方文档化的 native bridge 接入自有观测 session。AI 自主决定何时查询、查什么、是否补充观察以及业务结论，采集器不安排测试路径或重试业务操作。

Page.cdp 直接后台取正文的路线已排除：它曾两次使旧 snapshot 引用失效，并改变活动页。独立 native 接入已在本机验证无此干扰。

原生可行性验证的八个技术目标已在各自限定范围内验证，包括 HTTP、SSE、WebSocket 正文及资源释放。**这不等于原始八项产品需求全部验收通过。** 查询、内容策略、容量、导航绑定和打包仍是明确的开发、验收工作。

## 2. 最终交付范围

| 能力 | v0.1.6 必须交付的行为 |
| --- | --- |
| 串行为主 | 业务用例并发数 1，一个 Run 同时只有一个活跃采集上下文；正常网络并发和异步响应照常记录 |
| 后台自动记录 | 在需覆盖的 UI 操作前启动一次，之后自动记录；不要求 AI 每步抽取或保存事件 |
| 普通 HTTP(S) | 覆盖 Fetch/XHR 的方法、处理后的 URL/参数、必要 headers、请求正文、响应状态、可得 JSON/文本正文和网络错误 |
| 业务错误与异步 | 可查询 HTTP 200 中的业务错误、202 及页面实际发生的后续轮询/响应；不自动判断成功或任务完成 |
| SSE 正文 | EventSource 与 POST Fetch/XHR SSE；流未结束时可查已取得内容，保留非空初始缓存、增量、UTF-8、顺序、事件关联和结束/中断状态 |
| WebSocket 正文 | 双向文本和二进制、方向、顺序、连接身份、编码、关闭/错误事实；按浏览器提供的完整消息处理，不承诺原始网络分片边界 |
| 页面与导航 | 采集明确登记且已授权的顶层页面，处理普通导航、会话更替、重定向与重复请求；旧段保留，接入空档明确 |
| 多来源接口 | 配置已授权接口来源及路径，允许前后端不同来源；不能仅凭页面发出请求自动扩大范围 |
| 按需查询 | 状态、请求列表、请求/响应详情、流内容、错误与覆盖限制均有明确入口；停止后仍可离线查询 |
| 证据与报告 | AI 选择相关片段导出并登记，复用 evidence/observations/assessments 和三格式报告；关键 UI 截图要求继续适用 |
| Skill 指引 | 给出真实工具入口与适用场景建议，保持 AI 自主决策，不强制每步查询 |
| 可用交付包 | 完整构建包包含工具、适配器、契约、Skill 指引和说明，核对安装完整性及公开边界 |

普通 XHR、流式 XHR、产品级 SSE 多行 data/CRLF 解析、导航后绑定等必须进入开发验收；现有探针只验证了其中的协议与字节读取基础，不能省略这些检查。

## 3. 首版边界

- 主验收基线为本次实测的 Windows + Ego 0.6.1.13。其他宿主/构建检查实际原生能力并披露验证范围，不根据版本名推定可用，不自动升级 Ego。
- 多 worker 并行采集不纳入首版验收；数据仍保留 Space、页面、session 和请求身份，避免未来无法扩展。
- 新标签页和派生页先核对来源、授权并登记后接入；登记前的流量不保证追溯。iframe、worker、service worker 的独立目标不承诺自动全覆盖，可得来源信息保留，未接入部分明确披露。
- 文件上传/下载和普通二进制 HTTP 正文默认只记录可得元数据，不复制文件内容；WebSocket 二进制属于正文范围，按可逆编码及容量限制保存。
- 不采集其他任务/用户页面，不开启代理、调试端口或安装证书，不改写页面 Fetch/XHR，不修改 Ego 安装。
- 不主动调用、重发、拦截或修改业务请求，不切换账号，不自动业务轮询。
- 不承诺无限正文、零丢失、交接瞬间原子撤销、全部崩溃路径或所有浏览器版本；每次记录说明实际窗口、内容状态和缺口。

这些边界沿用已批准的首版范围。SSE、WebSocket 正文不得在实施时自动降为仅连接元数据。

## 4. 结构与职责

~~~mermaid
flowchart LR
    AI[AI 测试与业务判断] -->|现有 Page API| UI[Ego 授权页面]
    HOST[network start/stop 本地入口] --> COL[独立 native-only 采集上下文]
    COL -->|官方原生通道及控制权检查| EGO[Ego 原生会话]
    EGO -->|实际请求、响应和流消息| COL
    COL -->|过滤、处理、追加保存| DATA[Run 私有监控文件]
    AI -->|network status/query| QUERY[本地只读查询]
    DATA --> QUERY
    QUERY -->|有界数据及覆盖限制| AI
    AI -->|选择证据、明确四态| REPORT[现有证据账本与报告]
~~~

本地 CLI 负责范围/路径校验、启停请求、状态、查询和显式导出。采集上下文负责原生连接、协议事务、内容处理及监控文件，不写业务结果账本。

采集器不是系统服务，不开机自启。每次活跃采集有独立运行上下文；不得把它等同于独立操作系统进程，不能用其报告的 PID 终止共享 Ego/Node 宿主。

## 5. 接入与生命周期

### 5.1 启动

1. 输入 Run 目录、已获授权的 Space/页面、接口范围和内容/容量策略。
2. 本地入口生成私有 UTF-8 启动文件，通过结构化进程参数启动 Ego 上下文；环境与工作目录不作隐式输入。Windows 辅助启动隐藏窗口。
3. 检查 native 方法和回调槽。回调已占用或能力不足时拒绝接入，不能覆盖 SDK 回调或自动换用已失败的 Page.cdp。
4. 当轮核对真实 Space、控制权和页面归属，解析当前 target；只 attach 明确登记的目标，并使用本上下文取得的 session。
5. 记录实际连接、启用状态、版本、范围、开始时间与限制后，才返回“正在记录”。

启停事务按 Run 串行化。已有活跃采集时不重复启动，配置变更不能静默扩大范围。启动超时且执行状态未确认时保留 starting/unknown，不立即启动第二份采集器。

### 5.2 持续记录

采集上下文不调用会重绑回调的 SDK 传输辅助方法，不读取高层私有 services。回调所有权变化、连接错误及事件队列超限均可见。

原生发送一次只保留一个待完成协议命令，因为本地发送错误回调没有逐条命令 id。事件持续进入有界队列，不把业务网络强制串行化。

请求关联跨批次保存。请求键含采集段、页面/目标代次、session、requestId 和重定向段；不能根据相同 URL 或时间接近替代真实关联。孤立事件保留为孤立事实，不丢弃或归到最近操作。

仍属于原登记页面、权限和范围不变时，普通导航后的 session 更新属于资源绑定；已终止采集后的恢复则由 AI 显式重新启动。目标来源或归属不明时不自动扩大绑定。

普通响应及时保存可得正文。SSE 先保存初始缓存字节，再按序保存增量，连续解码 UTF-8 并解析事件边界。WebSocket 按方向、opcode/编码和连接身份保存，二进制不当作文本。

### 5.3 停止、交接与恢复

- 正常结束时排空合规数据，关闭自有 Network/session，清仍归自己所有的回调，退出上下文并保存回执。
- 用户接管、任务失活或授权变化时停止相关采集。发现失去控制后丢弃未通过检查的排队内容，不继续落盘、不越权 detach、不自动 takeOver。
- 接管路径先清回调并结束采集上下文，记录宿主收尾路径。补测已证明该受控路径结束后目标不再附着；正式 Run 不伪造未取得的显式 detach 回执，也不宣称原子撤销。
- AI 在既有授权允许时自主决定是否重新启动。恢复另建采集段，保留中断、旧配置和旧记录，不恢复业务请求或假称无缝连续。
- 状态依据上下文结束回执、启动句柄和最后心跳共同判断；残留文件或共享 PID 不能证明仍在记录。
- stop 通过本次采集的控制通道请求有序结束，不终止共享宿主进程。

这些规则只管理采集数据与资源，不固定 AI 的下一业务动作。采集/查询失败说明其实际状态，不自动改变业务目标结论。

## 6. 本地数据与内容策略

每次启动对应一个采集段，保存在仓库外 Run 目录：

~~~text
RUN/network/
  captures/CAPTURE_ID/
    session.json     本段身份、范围、配置和版本
    runtime.json     原子更新的状态、心跳、最后提交序号、清理状态
    events.jsonl     追加事件，含真实关联、时间及内容引用
    bodies/          已处理的正文与流内容
    gaps.jsonl       中断、未取得、过滤、超限等事实
  exports/           按明确选择生成的不可变证据片段
~~~

一个 Run 只允许一段活跃采集，后续启动另存新段。查询默认检索本 Run 保存的采集段，返回各段来源和窗口，AI 无需每步管理 session。

采用 Node.js 内置能力和文件存储，不新增数据库或模型服务。正文提交后才发布引用；读端只读取已提交序号，不把未写完的尾部当完整记录。

内容状态区分：已保存、真实为空、仍在进行、未采集、策略排除、超限/截断、获取失败。原始时钟类型、读取时刻和事件时刻分别保留，不补造时间或按邻近时间自动归因。

范围过滤尽量先于正文读取。认证头、Cookie、密码、token、API key、签名参数等默认不保留；URL、headers、正文、错误与日志出口执行同一策略。项目可进一步指定允许字段或禁采正文。通用处理不保证识别一切敏感值，严格场景使用明确允许范围。

流式内容按可安全处理的完整单元执行内容策略，跨块拼接使用有界内存缓冲。无法安全处理或超限时记录缺口，不先将未处理片段写盘再删除；保留内容转换和排除状态，避免将处理后的正文冒称未改动的原始字节。

设置单正文、总磁盘、队列、关联表和单次输出上限，写入配置及启动回执。总容量耗尽时停止新增采集并记录原因，保留已有数据，不静默覆盖或删历史。阈值作为可调整工程参数，在本地基准及验收中确定，不改变目标或授权。

## 7. 固定工具入口

下列是开发交付接口，当前尚未实现：

| 入口 | 行为 |
| --- | --- |
| network start | 校验范围，启动后台采集段，返回真实准备结果和身份 |
| network status | 返回当前/历史段、状态、能力依据、心跳、容量、缺口及清理信息 |
| network query | 按时间、页面、URL/路径、方法、HTTP 状态、网络错误、请求键、流方向等检索，按需展开正文 |
| network stop | 请求有序结束，保留离线查询和停止/释放回执 |

CLI 继续通过统一 ego.mjs 入口调用，使用绝对 Run 路径；start 配置、query 请求使用结构化 JSON。AI 不需要直接编写 native 连接代码。

查询默认少量摘要并分页，详情/正文片段按需展开。返回匹配或扫描范围、返回量、hasMore/截断、截止序号及覆盖限制；未完整扫描时不冒称知道总匹配量。

查询默认只读已保存数据。显式指定新输出文件时，可将所选请求/流片段及来源、内容状态和限制导出，拒绝覆盖；导出不重新访问业务接口。

未发布的实验性 protocol-query 收敛到 network query，不增加旧摘要兼容分支。历史摘要文件保留，不自动读取、迁移或删除。现有 v5 用例、证据、目标评估和报告接口保持；监控数据单独定义格式版本。

## 8. AI、Skill 与结果

Skill 增加简短入口与按需参考。适用建议包括保存反馈不明、页面报错、数据不一致和异步处理，不要求每步查询、每步截图或必须查明根因。

AI 自主选择查询条件和证据。HTTP 200、202、失败事件或空查询都不自动决定业务状态；接口证据不能抹掉 UI 违反，也不能代替必要 UI 路径、持久化读回或真实截图。

AI 通过现有 evidence-add 将所选片段登记为 log 等证据，observations 引用证据，assessments 明确提交已验证、发现违反、无法判断或未测试。监控不自动把请求归入当前用例，不新增整体质量分或业务门禁。

报告只嵌入所选并登记的证据，不打包全部流量，正文安全呈现。接口内容属于待测数据，不构成给 AI 的指令或授权。

## 9. 开发与验收清单

| 开发项 | 必须完成的验证 |
| --- | --- |
| 原生适配器及启动封装 | 正常/占用回调、启动超时、UI 并存、控制权变化、上下文结束、自有资源释放 |
| 普通 HTTP 与关联 | Fetch/XHR、请求体、200 业务失败、HTTP 错误、取消/超时、重定向、重复请求、跨批次关联 |
| 流式内容 | EventSource 与 Fetch/XHR SSE、非空前缀、增量、UTF-8、CRLF/多行 data/边界；WebSocket 双向文本、二进制、分片消息、正常/异常关闭 |
| 页面绑定及授权 | 普通导航、目标更替、登记新页、多来源；不扩采未登记页面/来源，缺口准确 |
| 存储与查询 | 读取已提交数据、分页、详情、流片段、离线查询、证据导出、完整性及路径保护 |
| 内容与容量 | 各出口策略、合成秘密检查、超限/磁盘失败、已有数据和历史保护 |
| 结果与报告 | 复用 v5 证据链，接口不代替 AI 判断与页面截图，安全渲染 |
| 独立安装包及轻量性 | 完整包异目录使用、tool-info/清单一致、公开边界检查；量测 UI 开销、资源和文件增长 |

沿用现有 TypeScript 项目，复用路径、完整性、格式校验及证据登记能力。监控模块职责独立，不重构既有目标评估系统。

已有实证用于确认接入可行性；上述未完成部分属于产品验收范围。开发后逐项给四态及证据，不用类型检查、构建或探针通过冒充产品完成。

## 10. 数据、交付与授权影响

新增监控格式和工具入口，旧 Run、原报告、原始证据及用户未提交改动保留。结构调整不授权删除或覆盖历史。

交付完整候选安装包、校验值、工具/格式/Skill 说明和验证记录。版本、revision、CHANGELOG、README、清单随实现同步，保持候选标识。

本设计不自动授权用户级安装、真实 UAT/生产采集、推送、合并 main、Tag 或 Release；遵从用户当次明确范围。构建与本地合成验收不等于正式发布。
