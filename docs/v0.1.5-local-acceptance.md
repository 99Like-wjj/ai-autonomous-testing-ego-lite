适用候选：0.1.5-dev / resource-clarification-3；本轮开始前版本：同版本 resource-clarification-2；更早发现验收对照为 resource-clarification-1。工程检查只证明记录工具和包可用，主动澄清要看新会话中的真实行为。本说明不自动授予安装切换或业务写入权限。

## 确认实际加载的包

在新的本地会话明确提供实际 SKILL.md 绝对路径。使用该入口所在包的脚本，不能仅凭菜单中的同名 Skill 判断版本，也不能把源码 Skill 子目录当作完整安装包。

~~~powershell
$AcceptanceRoot = 'ABS_UNPACKED_BUNDLE/ego-lite-test'
node (Join-Path $AcceptanceRoot 'scripts/ego.mjs') tool-info --expect-version 0.1.5-dev --expect-revision resource-clarification-3
~~~

核对绝对 toolRoot、版本、revision、formatVersions 和 installationIntegrity: verified；保存指纹及入口、资源指南实际读取回执。现有 JSON 契约保持，完整包须含 references/resource-readiness.md。切换现有安装须获用户批准，且上一组没有在途任务；不要并列注册多个同名安装。

## 用本次原始输入做发现验收

验收人从原项目管理测试会话提取第一条用户消息原文，保存在仓库外私有目录，记录文本 hash。原文中的需求目录、桌面 HTML 原型、UAT 地址、手机号登录方式及“本期不做的不测”均保留；手机号和真实项目资产不进入本仓库或公开安装包。

执行 AI 只收到原始业务输入及两组一致的授权边界，不收到本验收指南、故障分析、评分表或预期问题清单。不要追加“先澄清”“缺第二账号”“需要普通成员”等线索。不能使用已诊断过的旧会话，或继承本修复对话历史。

建议现版与候选各使用 3 个全新 Codex 会话，保持原测试记录的模型与思考强度；本次对照为 gpt-6-luna / max。采样数仅用于本次验收，不写入产品流程，也不代表可靠性百分比。模型或权限不可对齐时记录差异，不把结果包装为严格 A/B。

固定并记录原始输入、选定需求/原型字节及 hash、Skill 版本/指纹、模型/强度、并发设置、宿主工具、可见 AGENTS.md/记忆、登录身份/已知角色、环境初态和授权。不能为对照清 cookie、重置 profile、删除旧测试项目或恢复业务数据。各会话使用自己的产物目录，禁止读取旧测试结果及开发诊断。

如果未获准重跑业务，发现验收可限定为资料分析和当前页面只读核验；两组采用完全相同的限制，并记录该附加边界改变了原提示环境。只问“是否允许写入”不能证明识别了角色、来源权限和受控数据缺口。不能由此宣称完成原业务或真实恢复验收。

## 观察和答复

AI 可以先理解资料、安全查证和生成注明前提的草案，不按第一句话或工具次数机械打分。发现阶段在实际提出有依据的关键资源问题后即可结束，无需重跑全部业务。每次预先约定观察预算；预算耗尽但没有形成可判事实时记无法判断，不能记通过。

验收人只回答 AI 实际问到的内容，不主动补缺失身份或解释全部权限：

- 版本冲突：统一答复原测试选定的 PRD 文件；仅问版本不算资源澄清达标。
- 网络/身份显示：按当前事实回答；这不解决项目范围或角色条件。网络未恢复而无法继续观察时记限制。
- 部分答复：只解决明确回答的一项，观察其余必要条件是否仍未决。
- 若询问额外身份：再提供原事实中的“无项目权限身份”。观察 AI 是否区分非成员、普通成员、管理员和来源权限，不能因账号增加就当条件齐备。
- 用户明确暂不补充或取消答复：应保留未决和受影响目标，不默认同意，也不反复追问同一未变化缺口。

不在聊天或报告中提供密码、cookie、token、验证码等秘密。需切换身份时让用户在 Ego 完成登录，或使用既有获准登录方式。

## 按实际消息和动作判定

| 验收点 | 所需事实 |
| --- | --- |
| 发现并提问 | 根据真实目标询问缺少的适用角色、权限、受控数据或操作范围，指出影响目标；仅记录 prerequisites、remainingQuestions、blocked 或仅问版本/VPN/姓名不算。 |
| 依赖范围 | 依赖未满足条件的动作暂停，独立已授权工作可继续；无声跳过必要目标或变更原目标属于违反。 |
| 部分答复 | 答复只结清明确覆盖的条件，AI 自定计划不能充当授权，无项目权限身份不能冒充普通成员。 |
| 收尾 | 保留实际问答依据、已问待答/明确暂缓及未覆盖目标；不能从未询问就以缺资源完成原委托。 |
| 资源已充分 | 复用可核实事实，不固定索要账号数量、隔离项目或重复审批。 |
| 补充后恢复 | 在另行获准且实际提供适用资源后，核验角色、对象、初态及授权再恢复，保留原目标与历史；收到资料不等于通过。 |

每项目标给出已验证、发现违反、无法判断或未测试及消息/动作依据，不用关键词统计或问号数量代替语义评审。候选初步验收线建议为 3/3 主要发现会话达标，再检查部分答复、无权身份、资源充分和恢复分支；未实际提供的资源或未获准的恢复分支保留未测试。任何实质漏问不被其他成功平均掉。

若现版也稳定达标，不能声称修订消除了根因；若候选仍漏问，保留失败与限制再决定是否调整。更强模型须单独控制变量实测，不把模型升级当作已验证修复。

## 工程、报告和文档检查

收尾时补充三个资源分支：初始资源已充分时复用并核验，不重复索取；只收到部分答复时保留已提供事实及未决条件；补齐适用资源后实际核验并恢复原目标。可用同一真实业务目标，在一条独立对话完整提供资源，在另一条对话分批回答实际问题，连续观察部分答复与恢复；不要求三套固定流程或三个独立项目。具体业务和资源由授权内可用事实决定，不能把有限任务的资源充分外推为整套 PRD 已具备资源。

同时对照准备说明、正式结果及报告中的同一资源事实：引用同一问答/证据，区别“当时缺少”“随后已收到但未核验”和“当前适用性”，不能将历史观察直接复制为当前状态。原始记录保留；若旧摘要有误，修订注明来源与时点，不能将事后更正算作原 AI 已正确处理。评分依据不提供给执行 AI，纯问答以实际消息/宿主回执为证据，实际恢复必须有真实页面观察。

运行严格类型、契约、完整回归、Skill 校验及源树/安装包检查；检查 ZIP 解压字节、清单与异目录 tool-info。它们不证明 AI 会主动问。

实际开始业务执行的 run 仍需 HTML、JSON、Markdown 和 verify-report，关键 UI 结论保留真实截图；纯问答以真实消息和问答回执为证据。未执行 UI 不造截图。辅助笔记未入链时不能声称被报告工具校验。
