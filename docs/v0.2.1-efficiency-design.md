# 0.2.1 执行效率：接口、事务与验证设计

状态：已实施的开发约定，验证范围见[开发自测](v0.2.1-development-validation.md)。总体范围见[0.2.1设计](v0.2.1-design.md)。本文件示例均为合成资料。

## 1. 将模型决策边界与工具步骤分开

推荐组合：当前事实足以确定脚本时，在一次宿主编排中顺序写入新UTF-8文件、检查成功、运行该文件、返回最终观察。不要仅为了发出已知运行命令再请求一次模型。脚本的唯一文件名、动作前提、失败回执与取证仍保留。

必须保留的新决策边界：中间结果会改变下一动作、身份或对象待确认、授权待答、业务副作用未知。工具不得因“批量”越过这些边界。工具执行异常不自动重放脚本。指南采用一个合成正例和一个需要中间观察的反例，不制造通用固定步骤树。

这里只指导调用组合，不新增自有浏览器驱动。继续使用实际安装的Ego官方能力。原文保存、简短回执和有界执行摘要已经存在。[VERIFY: src/ego-helpers/capture-text.mts:16-41] [VERIFY: src/execution/views.mts:7-37]

## 2. 当前运行与历史读取

### 2.1 CLI提案

```text
ego.mjs progress --run-dir ABS [--view summary|goals|point]
  [--case-id ID] [--point-id POINT] [--offset N] [--limit N]
  [--max-bytes N] [--expected-results-revision N] [--output-file ABS_NEW_JSON]

ego.mjs regression context --run-dir ABS [--results-revision N]
  [--view summary|goals|point|full] [--case-id ID] [--point-id POINT]
  [--offset N] [--limit N] [--max-bytes N] [--output-file ABS_NEW_JSON]
```

- progress默认summary；不支持full，已有check可返回完整检查结果。
- regression context默认summary；完整历史输出必须显式full或导出。属于CLI输出行为变更，更新示例与调用者，不保留旧默认全量输出分支。
- point用稳定pointId，避免不同case复用局部goalId时串项；只能一个point。case-id仅筛选goals视图，其他组合拒绝，不能静默忽略。
- 当前运行只返回冻结选择范围；point存在但未被选中时返回明确`POINT_NOT_SELECTED`，未知point返回`POINT_NOT_FOUND`。历史full仍可包含原始规范，但明确规范与本次已选事实不同。
- `expected-results-revision`只做读取前提，不回滚。变化则返回`SNAPSHOT_CHANGED`，由AI决定重读。历史精确revision使用既有前缀校验，不编造该时点的当前授权。

现有pointDetails可复用目标与证据闭包，但其steps选择需补核对dependsOn的传递依赖；sourceContext现有全量结构保留为显式full，不继续作为默认上下文。[VERIFY: src/regression/sources.mts:70-81]

### 2.2 输出契约

新增`contextReadVersion: 1`，主要字段：

| 字段 | 含义 |
|---|---|
| scope | current或historical；requested view/filter、runId、baselineSha256、resultsRevision、resultsSha256、evidenceRevision；历史不声称核验当前执行状态 |
| integrity | 实际检查的规范、结果、物理证据范围；引用既有检查结果，不能仅因输出简短就标metadata |
| counts | 冻结范围四态及unassessed数量；筛选后数量另列，不混用 |
| items | 目标索引，包含pointId/caseId/goalId/title、是否已评估、状态或null、最近观察/来源定位、真实记录的gaps摘要 |
| point | 单目标原预期、依据、必要条件/步骤/顺序/requiredPath、最新评估及事实索引；不重新解释业务要求 |
| unresolved | 原动作事实的未决项索引、run级总数、分页及精确读取入口；与目标关联不明确时保留run级提示 |
| pagination / omissions | offset、limit、returned、nextOffset、total、omitted reason；所有省略可精确定位 |
| limitations | 历史不是当前事实、缺证据、未检查项和输出边界 |

`unassessed`只表达没有评估，不新增第五种业务状态。gaps、资源原因及恢复依据仅取原记录；工具不自行把目标标成阻塞/暂缓，不生成“下一步建议”。

### 2.3 预算与大对象

- 默认limit 20、上限100；默认maxBytes 24,000、上限200,000，按实际序列化UTF-8字节检查，计入包装字段。
- goals视图可以省略摘要，但保留ID、明确省略和展开入口。不能静默截断原预期或必要路径后标成完整。
- point的原预期及必要语义作为不可拆散的核验单元；超预算时返回`POINT_EXCEEDS_OUTPUT_BUDGET`和精确导出方式，不返回空列表并反复指向同一offset。
- `--output-file`将所选内容完整保存在新文件，stdout只返回位置、hash、字节数、scope和限制。full必须指定output-file；预算只约束回执，文件完整性另核验。
- 不以模型token数假装字节预算，不把摘要当作已经读过原件。AI必须按原目标补读必要材料后才能判定。
- 去重以实际对象ID/证据ID为准，索引关联多个目标；不能因为同case或同标题就自动共用支持事实。

### 2.4 一致性和读取副作用

首版复用现有严格检查，不新增弱化证据核验的快通道。投影是纯函数，不能在投影中修复、调度或采集。progress现有底层包含本地证据事务恢复，这一行为应明确说明，不宣称整条命令绝对无磁盘写入；本版不借效率改造扩大恢复范围。historical沿用readSourceRun的不恢复语义。稳定读取在既有run锁内完成，返回实际revision。[VERIFY: src/core/records.mts:447-453] [VERIFY: src/regression/sources.mts:14-24]

## 3. 入账反馈

### 3.1 保留内部收据，改变CLI输出封装

ResultReceipt被并行工作包提交日志复用，不能直接向其塞入动态提示。`recordResult`/`recordResultUnlocked`的内部收据语义保留，CLI输出改为独立封装。[VERIFY: src/contracts/model.mts:83] [VERIFY: src/execution/commit.mts:96-102]

```json
{
  "recordResponseVersion": 1,
  "committed": true,
  "receipt": {"operationId":"synthetic-record-1","revision":3,"caseId":"case-a","mode":"final","replayed":false},
  "feedback": {
    "status":"available",
    "asOfResultsRevision":3,
    "scope":"commit_prefix_without_retrospective_notes",
    "affectedPointIds":["SYN-000001"],
    "caseUnassessedCount":1,
    "hints":[{"code":"missing_reading","pointId":"SYN-000001","observationId":null,"actionId":null}],
    "total":1,
    "truncated":false
  }
}
```

只读反馈的提示默认最多20条、预算8KB；完整提示可经目标读取接口定位。允许`--feedback none`仅关闭提示计算，但仍使用同一新封装，不增加另一套输出兼容层。提示code语言无关，报告层继续本地化。

### 3.2 提交、重放、提示失败

1. 原校验、revision冲突、来源约束照常执行；不因省token省略检查。
2. 从已校验数据及候选记录构造提交时投影，复用纯提示逻辑，避免入账后再执行一次完整check。
3. 原结果原子提交；receipt是唯一提交事实。反馈失败单独返回`status: unavailable`与简短原因，不能让已成功提交看起来是业务写入失败。
4. 同operationId/相同payload重放返回`replayed:true`。反馈绑定该操作的原revision前缀，不能偷用较新的状态；不改变旧记录或旧收据。
5. 进程在提交后、回执前中断时，保留“结果未知”的实际情况；使用原operationId按现有幂等机制核对本地事务。不得由此重放浏览器动作。

纯结构检查提取到`src/core/review-hints.mts`，供record和报告调用。范围仍为原有缺标题/实际现象、重复文案、阶段不符、对话摘要缺失等；不自动补内容，不把提示当新增业务失败，不拒绝有依据的四态。报告有retrospective注释时与原提交提示可不同，必须说明使用的上下文。[VERIFY: src/report/reviewability.mts:1-18] [VERIFY: src/core/records.mts:317-341]

## 4. 可选用量摘要

### 4.1 最小入口

```text
ego.mjs usage summarize --request ABS_REQUEST [--output-file ABS_NEW_JSON]
```

request指向一份已由宿主或调用者整理的非秘密usage文件，并声明精确分析范围。工具只读取指定文件，不扫描全量会话目录、不读取凭据/模型配置、不调用模型或计费API、不采集页面。

首版不建设后台代理、数据库或自动任务状态机；跨多段输入由调用者显式合成同一来源文件，工具在本次聚合中去重。原始日志不得为归并而重写。无可信token来源时可输入明确的工具事件，但输出只报代理指标。

### 4.2 规范化输入

独立`usageVersion: 1`，包含source声明、范围和records：

- 来源：稳定sourceId、类型`host_export|provider_export|operator_normalized`、原件定位/hash（如有）、采集区间与完整性。来源标签是声明，不是工具认证。
- 模型记录：responseId、时间、`purpose: model|compaction|unknown`、input/cachedInput/output/reasoningOutput/total；未知字段为null，不能写0。已知cacheWrite另列，但不跨提供方猜计费语义。
- 工具记录：独立eventId、toolName、durationMs、outputBytes、是否截断；不保存命令正文、提示词或页面数据。
- 可选关联：runId、pointIds、stage、operationId及关联依据。没有显式依据时归unattributed；不得靠时间邻近或文件名前缀冒充精确因果归属。
- 模型请求数与本地工具调用数分开。一次模型请求可以包含多个工具；不能把exec_command数量直接当模型请求数。

源文件首版上限16MiB、100,000条记录，超限明确拒绝；不读取一半后给出完整总额。工具可以只流式聚合所需字段，避免原件进入模型上下文。

### 4.3 聚合和错误约定

- 模型键为`(sourceId,responseId)`，工具键为`(sourceId,eventId)`；相同键且内容一致只计一次，冲突则拒绝合并并列出键，不擅自取最后一次。
- 不求和累计计数器。input已包含cachedInput，output已包含reasoningOutput；子项只分列，不二次加总。
- 非负整数采用安全整数校验；超出安全范围拒绝，不静默舍入。已知子项不得大于对应总项；已知total应等于input+output。
- 缺失字段使对应总计标记partial，返回knownSum、unknownCount；不能由缺少output推断0。
- purpose可区分压缩与普通请求，输出both totals及区间边界；不把压缩为下一任务产生的费用并到上一任务。
- point/stage标签可能重叠，归属分组不得再次相加当总额；主总额按唯一记录求和。
- 摘要不输出原始prompt或凭据。没有提供方价格/账单时不计算金额，不把token总量等同实际费用。

输出`usageSummaryVersion: 1`，包含来源指纹、覆盖范围、唯一请求/工具数、分项用量、平均/分位输入、工具输出字节与截断数、缺失/冲突/未归属信息；默认只返回合计和有界分组。默认不把此文件加入业务报告，也不改变业务四态。

## 5. 验收矩阵

| 编号 | 合成或工程验证 | 必须成立 |
|---|---|---|
| E01 | 保存成功/失败及运行异常 | 已知准备+运行可一次编排；失败不继续；未知不重放 |
| E02 | 多case同局部goalId | pointId精确选取，无串项；未选/不存在区分 |
| E03 | 必要步骤多级dependsOn | 原预期、依赖闭包、顺序与路径完整，未使用摘要替代必要语义 |
| E04 | 大运行、长目标、低预算 | 摘要有界、总数准确、省略可定位；大单元不空转分页 |
| E05 | revision变化/历史前缀 | 变化明确返回；历史读取不修复或借用后续事实 |
| E06 | 新提交、重放、冲突 | 业务记录与原内部receipt语义保持；提示绑定正确revision |
| E07 | 提示计算失败/提交后进程中断 | 成功不伪装失败；未知可用原operationId核对 |
| E08 | 入账与报告结构提示 | 相同事实/上下文下结果同源；四态不变 |
| E09 | usage重复、冲突、子项、空值、超限 | 去重准确、冲突拒绝、子项不重加、缺失不当0 |
| E10 | 等价任务的基线与优化指导 | 记录请求量、实际token、证据与目标覆盖；不预设效果 |

扩展现有goals、facts、conversations、CLI、regression及report测试；新增纯usage/投影边界测试。固定合成任务覆盖正常操作、长回复、缺资源、未知提交，基线与新指导各重复观察。工程测试验证确定性逻辑；模型行为与真实业务效果另有证据，不互相替代。
