# 测试经验维护规范

本版由一个 Skill 的设计与执行两个入口提供 Markdown 经验。普通测试运行不自动写回、提炼或积累候选知识。运行时不引入 SQLite、向量 RAG 或额外模型服务；只读为行为约定，不是 OS 写保护。

## 索引约定

入口为 case-design-guide.md 和 experience-guide.md。每条索引用连续 Markdown 列表：标识、阶段、主题、触发线索、检索别名、正文位置；条目之间留空行。标识为全库唯一的 D- 或 E- 大写语义名，正文使用对应小写显式锚点。阶段为设计或执行；别名无合理内容时写“无”，不留空字段。

正文链接只指向同目录 Markdown 和稳定锚点，不指向运行产物、绝对路径或第三方页面。标题变动不改标识；拆分或合并时同步所有引用。每条正文标明适用阶段与“不适用与边界”，避免只有正面建议。一个主题一个责任位置；两阶段相同词可以对应不同职责，不能机械去重。

触发词描述场景，不直接断言缺陷。AI 起草后由维护者审核通用价值、事实/假设、反例、阶段、重复、许可与敏感数据，再进入版本。静态校验只能检查结构和导航，不证明方法有效。不得把公司专属业务规则当通用规范。

## 开发与评估

npm test 中的 experience 测试检查源文件与分发字节、标识、必需字段、阶段、锚点及异常样例；开发检查器不打包为运行时查询工具。实际工具能力仍以安装环境为准，不假定存在接口监控。

语义评估应分开考察找到资料、正确使用、结论边界和额外成本。用直接/同义/不适用表达测试，避免把期待答案写进输入。当前会话已读方案，只能做主模型受控走查，不是无经验基线或独立盲测；不能从样例通过推导缺陷发现率提升。用户本次不要求真实 Ego 驱动，不将它列为本次演练的完成条件。
