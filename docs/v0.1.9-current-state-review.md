## 2. 现有数据流与可复用位置

以下只描述已读实现；右列是本轮提出的设计方向。

| 已存在的数据处理 | 源码依据 | 可复用方向 |
| --- | --- | --- |
| `saveCases` 接收已有 sources，保存整份用例新版本；写入前检查来源文件 SHA，并拒绝前驱指纹不一致 | [VERIFY: src/core/case-versions.mts:48-56] [VERIFY: src/core/case-versions.mts:68-75] | 把知识查询的不可变摘录作为正式来源文件，无需把整座知识库塞入用例 |
| `SourceRef` 已包含 id、locator、file、sha256、excerpt、limitations；file/hash 必须成对 | [VERIFY: src/core/validation.mts:38-43] | 知识原始来源与状态保存在摘录正文中，通过现有 SourceRef 追溯 |
| `Basis` 只有 explicit、interpretation、hypothesis；它表达测试依据类型 | [VERIFY: src/core/validation.mts:34-36] | 知识状态与测试依据必须另行映射，不能把“查到知识”一律转换为 explicit |
| 用例项目 ID 初次由工具生成，后续沿用 | [VERIFY: src/core/case-versions.mts:69] | 不强迫知识项目 ID 等于用例资产 ID；应明确两种命名空间 |
| `start` 校验用例、范围/审阅/当前条件绑定，并把原用例和绑定写入 run | [VERIFY: src/core/cases.mts:19-28] | 接入知识不能跳过原来的用例审阅、当前条件核验与冻结 |
| 运行绑定读回校验 run 自己保存的文件及 SHA，不重新读取可变外部资产来修复它 | [VERIFY: src/regression/run-binding.mts:8-12] | 知识更新不应倒改已冻结运行；新增情况需独立记录 |
| 已验证或发现违反必须有关联观察和证据；存在验收澄清的目标不能提交这两态 | [VERIFY: src/core/records.mts:84-92] | 知识是上下文或预期来源，不能直接变成执行证据或通过结论 |
| 经验校验器检查索引字段、阶段、重复 ID、正文锚点和边界说明 | [VERIFY: tools/check-experience.mts:5-43] | 保留其结构检查，但不能据此证明经验能改善 AI 决策 |
| 现有经验测试检查分发字节一致和索引错误拒绝 | [VERIFY: tests/experience.test.mts:11-49] | 需要另做有区分力的行为场景验证 |
| 经验和指南通过显式清单进入运行分发 | [VERIFY: src/contracts/layout.mts:134-154] | 后续新增指南必须同步分发与本地引用检查；本轮不生成安装包 |

现有相关主链为 `CLI → saveCases → 带 sources 的不可变用例 → start/prepareBinding → run 内冻结副本 → observations/assessments`，入口与冻结/判断依据分别见上表。知识查询拟作为这条链之前或执行期间的独立只读能力，不成为自动执行器。
