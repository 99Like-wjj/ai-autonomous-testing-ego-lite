# v0.1.4 本机能力验证结果

日期：2026-10-23。范围：用户批准的能力验证，合成页面，最多两例并发。基线分支 `feat/v0.1.4-parallel-testing`，提交 `ae2ce6b40ad96a4e02593767964c3e52c262cf6b`。新增验证脚本及说明，未实现正式并行执行器，未修改用户安装，未提交、推送或发布。

**结论：双 Space 的基础调用路由有实测支持；当前原生子代理不能满足工具硬隔离。受限宿主候选仅通过部分协议探针，尚不能作为完整实现的已验证基础。**

## 冻结目标与结果

试验前冻结五个目标，原始方案和原始错误均保留在仓库外的私有证据包。该包包含实际轮次脚本、CLI 回执、服务端屏障记录、真实截图、用户确认、安装 hash、清理读回，以及 HTML／JSON／Markdown 报告。结果文件工具的 v3 baseline 在执行后整理，报告明确声明，不冒充试验前创建的账本。

| 目标 | 状态 | 实际依据及结论边界 |
| --- | --- | --- |
| H-NATIVE 原生子代理不能直接执行通用 shell／Ego CLI | **发现违反** | 一个实际原生子代理通过 shell 成功执行 `ego-browser --version`。这证明原始 CLI 入口可达；没有让它创建或操作 Space，也不声称发生了跨 Space 行为。 |
| H-RESTRICTED 受限宿主只有 case-scoped 工具且无法绕过 | **无法判断** | 独立 Codex App Server 会话中的真实模型完成两次模拟工具调用，身份来自宿主 `threadId`，模拟错 Space 参数被拒绝。模拟工具未连接 Ego；完整工具面和子代理继承尚未得到足够验证。 |
| ROUTE-A 同一 Space 多轮执行并与 B 重叠 | **已验证，限本机合成范围** | A 始终为 Space 9／p1。两轮页面标记、输入和提交结果正确；独立读回和真实截图一致。 |
| ROUTE-B 同一 Space 多轮执行并与 A 重叠 | **已验证，限本机合成范围** | B 始终为 Space 10／p1，结果未串为 A。两轮均与 A 完成双成员屏障，续跑有真实截图。 |
| PROTECTION 初始 Space 全部仍在且仅精确清理自有 Space、安装未变 | **无法判断完整场景；子检查已验证** | 用户确认手动关闭了两项既有 Space，改变了原清单前提。保留原场景的无法判断状态。本次只关闭 9、10，剩余三项既有 Space 的列表元数据一致，安装及用户配置 hash 一致。 |

这些状态不是业务系统验收结果，也不是 AI 测试准确率或性能基准。

## 双 Space 路由的可复核事实

- 本机版本：Ego `0.6.0.16`、Chromium `154.0.8037.44`、Ego Node `v24.21.0`，Codex npm CLI `0.163.0`。
- 只使用绑定到 `127.0.0.1` 的合成页面，没有登录、退出、清 Cookie／缓存、业务账户切换或后端数据操作。
- 初轮两个外部 CLI PID 为 `29188`、`39900`，开始时间相差 12ms。服务端先收到 A 的屏障请求并保持等待，约 522ms 后 B 到达，随后才释放两路响应，证明存在实际在途重叠。
- 首轮截图因窗口最小化失败，CLI 错误被保存。后续先独立读回确认合成提交已完成，再在原 Space 续跑，未重建空间或盲目重放未知动作。
- 续跑 CLI PID 为 `38788`、`17268`。A 的值为 `A-resume-30fc96ca`，B 为 `B-resume-30fc96ca`；对应提交结果和两张真实截图已人工查看。两例仍为原来的 9、10。
- 每个脚本都报告宿主 Node PID `36892`。因此只能说两个独立 CLI invocation 已重叠，不能据此声称底层 Node 进程完全隔离。公开源码中的 gate 与本机多个 invocation 的实际隔离域不能仅凭 PID 推断。
- 实测最大同时 Ego CLI invocation 为 2。没有做串行／并行耗时基准，不能据此次屏障证明“更快”或承诺加速比例。

验证夹具在续跑屏障处有两条相同的释放通知，原因是两个异步处理器均记录释放；原始请求仍只有 A、B 各一次。本报告按同一轮处理，不增加成功轮次。

## 受限宿主得到什么证据

候选会话只作临时进程参数覆盖，不写用户 `config.toml`。关闭 shell、应用／插件、已配置 MCP、计算机控制等入口，声明只读工作区，提供一个不执行浏览器操作的合成动态工具。

第一候选还关闭了 `code_mode_host`，100 秒内没有收到动态工具调用，不能据此判断隔离通过。停止 RPC 首次缺少 `turnId` 被拒，相关进程随后结束；此验证代码问题已在脚本中修正，首轮原始记录保留。

第二候选保留工具传输通道后，真实模型完成 `identity` 和 `wrong_space` 调用；宿主回调记录了线程、turn、call ID，模拟拒绝返回 `FORBIDDEN_OPERATION` 和零浏览器派发。模型还报告工具表中没有通用 shell，但可见 `apply_patch`、`view_image`、`web__run` 等入口。该枚举是模型读取工具元数据后报告的结果，不是宿主提供的完整安全证明。

因此已验证“真实模型能调用带可信线程身份的动态工具”和“合成入口能拒绝模拟越界参数”；尚未验证“只有所需工具可达”“所有嵌套子代理同样受限”“实际 Ego 只能操作自己的 Space”。原生桌面子代理可执行 CLI 的反例仍然成立。

## 保护、清理与交付

创建前只读登记既有 Space，本次没有 claim 或操作它们的页面。用户在验证期间手动关闭两项既有 Space，经询问得到明确确认。本次没有自动恢复或重新创建它们。

关键证据与清理前报告保存后，只对本次创建回执确认的 9、10 各执行一次 `finish({keep:[]})`。另一次调用读回：9、10 已不在清单，剩余三项既有 Space 的所有返回元数据与初始同 ID 条目一致。所有已执行轮次的 numeric Space 选择仅为 9、10，无无法解释的既有 ID 缺失。合成 loopback 服务已停止。

用户级 Skill 和用户配置文件前后 hash 一致；原有 Git 跟踪文件、原设计草案保持不变。验证代码、实际产物和用户安装分开保管，私有原始记录不放入仓库。

清理前 HTML 已在原 Space 的另一个 Page 实际打开，读回了五条结果和可解码的截图；报告截图再次因最小化失败。最终报告在清理后生成，只完成三种文件的读回和 hash 校验，没有再新建 Space 打开它。不能称最终报告完成视觉验收。

## 未满足项与下一步建议

1. **工具硬隔离仍未满足。** 先确定严格的宿主工具面及可信 worker 身份来源，不能把普通原生子代理加提示词当作安全边界。
2. **尚无两名受限子代理 → 真实 case broker → Ego 的完整链路证据。** 本次路由由受控的本地 CLI 测试进程发起，模拟宿主探针和真实浏览器探针分开验证。
3. **完整 Space 生命周期与保护仍待验收。** 人工干预改变了原清单条件；取消、超时副作用、worker 替换、崩溃、浏览器重启及 ID 复用未测。
4. **业务隔离及性能没有结论。** 同账户、profile、后端记录、队列、限流和剪贴板／popup 竞争未测；没有代表性性能对照或可靠成本统计。

建议下一次仍限于宿主工具面与受限子代理的合成验证，待用户决定后再开展。当前不进入正式并行执行器开发，也不把本次结果作为 0.1.4 发布验收。
