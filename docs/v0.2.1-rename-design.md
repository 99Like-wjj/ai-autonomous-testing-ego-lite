> AI 自动化测试 / AI testing with Ego Lite：由 AI 自主分析需求、设计用例、执行 Web UI 测试并验证结果，提供证据报告与回归复用。

中文README仍以“AI 自主自动化测试”为名称，首段可写“面向 Web 应用的 AI 自动化测试（AI testing / test automation）Skill”。不改成AI模型评测框架，也不暗示已经支持未实现的浏览器或平台。

## 3. 影响结论

**更名不改变测试业务逻辑，但会改变安装/发现/调用及身份校验，不能只做字符串文案替换。** 同步完成下表后，可使新名称版本保持相同业务能力。

| 位置 | 已确认耦合 | 拟处理 |
|---|---|---|
| package.json / package-lock.json | 根包名为旧名 | 同步新名，依赖版本不因更名升级 |
| Skill源目录及frontmatter | `skills/ai-autonomous-testing-ego-lite`和name字段 | 移为`skills/<new-name>`，name同步；描述保留真实能力 |
| agents/openai.yaml | default_prompt含旧`$`调用名 | 改为`$<new-name>`；中文display_name保持；不改隐式调用策略 |
| toolchain.mts | 显式检查旧pkg.name和Skill name，返回旧name | 引用统一身份常量，名称不一致仍拒绝 |
| stage/clean/bundle/generate工具 | 检查旧包名，stage读取旧目录 | 统一身份/源路径；不取消路径和完整性保护 |
| 分发目录与ZIP | 包内顶层目录和安装示例使用旧名 | 新完整目录/附件用新名，manifest由构建重生 |
| 当前中英文README/安装/架构/示例/图示 | URL、路径、调用名和标题 | 当前说明同步；图示改源文件后重渲染，保留适用内容 |
| 历史设计/验收/Release | 记录当时旧名及hash | 保留历史原貌，必要处加迁移入口，不全局替换 |
| 其他仓库链接 | knowledge-maintainer的README等引用旧URL | 更名实际完成后同步当前入口；固定历史commit资料保留出处 |
| 用户源码目录/已安装目录 | 工作区与部分元数据可持有绝对路径 | 安装按替换方式；源码目录独立安排，不在被占用工作区强行改名 |

## 4. 代码与包身份方案

- 在`src/contracts/layout.mts`提供唯一`TOOL_NAME`和Skill源目录常量。toolchain、stage、clean、bundle、contracts生成及身份测试引用同一来源；package与frontmatter仍分别核对，不能仅互相照抄就跳过身份验证。
- 业务内部的`ego.mjs`、`egoLiteTest`元数据键、Ego浏览器API、runId/pointId、v9资产结构不因品牌更名而改。内部技术标识不必和品牌字符串逐字一致。
- 不手改`.build`、runtime-manifest或已发布ZIP。开发实现使用新身份的0.2.1-rc.1完整构建，正式版另走发布流程。
- 历史保护列表中旧安装目录仍是需保护的真实路径，不能为“全仓库旧名清零”删掉。旧名允许保留位置应按用途明确记录，区分历史出处、迁移说明和仍有效的保护边界。
- 已编译development-context含绝对sourceRoot/runtimeRoot；未来本地源码目录移动后需重新构建开发产物，不能继续拿旧绝对路径的产物运行。[VERIFY: tools/stage-runtime.mts:25]

## 5. 用户侧采用替换安装

按用户选择，不保留旧调用别名，不同时分发两个可发现Skill。

1. 下次获得完整新名称安装包后，校验包的身份、文件集合及完整性，安装到实际Skill搜索根的`<new-name>`目录。
2. 确认新包工具可运行后，将已识别的旧名称Skill退出发现路径并删除；用户已明确允许旧Skill删除。只处理该安装，保护其中不属于安装包的数据或用户修改。
3. 新会话验证实际加载新Skill，显式调用`$<new-name>`，从实际ToolRoot执行tool-info。最终发现列表只有新入口。
4. 新安装失败时，不先删除唯一可用的旧安装；处理失败原因。删除旧安装不重写旧历史、旧引用或运行证据。

这不是双名称兼容，也不需要把旧Skill内部文件逐项迁移到新目录。旧的`$ai-autonomous-testing-ego-lite`及粘贴过的绝对脚本路径不再承诺可用。新安装文件校验通过与客户端真正加载新版本分别核验。

自包含历史HTML/附件保留即可阅读；少数旧run若引用旧安装中的绝对来源文件，移除安装可能影响后续hash复核。先识别实际引用并报告限制，不自动创建兼容别名、符号链接或改写已冻结来源。普通独立私有测试目录不随Skill删除。

## 6. GitHub与本地仓库

GitHub对原仓库更名后通常保留网页及Git操作重定向，仍建议更新origin。不要新建同名替代仓库搬走历史，也不要重新占用原仓库名，否则重定向会被覆盖。项目Pages及他人`uses: owner/repo@ref`调用的Action有例外；当前has_pages=false且本地没有.github目录，但不据此推定所有外部使用方均不存在。[GitHub更名规则](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository)

拟执行顺序：

1. 最终确定短名称并完成代码、当前文档及新包身份验证。
2. 在实际更名阶段修改现有GitHub仓库name，读回repository ID保持一致，确认新URL与旧链接重定向。
3. 原checkout更新origin，不重新clone、不移动既有Tag、不改写历史附件。新分支名称无须随仓库更名再改。
4. 更新当前安装下载入口、徽章和知识维护项目的当前链接。旧版ZIP文件名属于历史，不伪装为新名包。
5. 本地源码文件夹若也需更名，关闭使用旧路径的工作区/终端后单独执行，再从新路径打开和重建；本设计阶段保留现有工作目录。

当前任务仅创建开发分支并详细设计。未来安装替换已按用户方向纳入；当前不立即删除已安装Skill或修改GitHub设置。

## 7. 更名验收

| 编号 | 验证 | 标准 |
|---|---|---|
| N01 | 新包身份 | 包名/frontmatter/default_prompt/tool-info/目录一致；混搭旧元数据会明确失败 |
| N02 | 构建链 | clean、contracts、bundle、stage及tool-info均用新身份正常运行；路径保护仍有效 |
| N03 | 文件集合 | 完整包无缺失、额外文件和指向旧源码目录的当前引用；历史说明例外有依据 |
| N04 | 新安装 | 完整新包可用、新会话加载新调用名、旧入口不再被发现；Ego官方Skill未改 |
| N05 | 合成业务回归 | 同一v9合成用例的冻结、记录、证据、报告和读取结果保持一致；不借更名迁移历史格式 |
| N06 | 文档与历史 | 中英文当前说明/图片一致，历史Tag/Release/报告/hash未改 |
| N07 | 仓库身份 | repository ID保持、remote正确、新URL可访问；历史重定向实际核验 |
| N08 | 检索信息 | 简介含中文/英文目标词，Topics相关；能按repo精确定位；普通关键词收录另作观察，不设排名保证 |

新增测试应验证真实身份校验、实际构建与发现路径，不只检查文本中是否出现新字符串。README中文名称保留，不将用户的“AI 自主自动化测试”误改为其他定位。
