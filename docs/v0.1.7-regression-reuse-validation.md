## 实现与结构变化

- 规则与任务在项目私有目录按精确修订保存；规范原文、确认状态与实际观察分源，失败和未完成项不按成功过滤。定义成熟度、适用性、本次条件及业务四态分别表达。
- `regression read/context/validate/commit/select/compare` 提供本地数据事务。状态模式固定原运行及结果前缀，任一目标命中即选择整条场景；full 保留完整指定范围及缺口。工具不调用模型、不选择业务路线、不重放业务动作。
- `start --binding` 将任务/规则、选择快照及本次条件冻结到独立新 run。未选中目标不生成本次结果，选中但受阻或尚未编入的部分必须显式保留。
- 同一结果账本追加 contexts/actionEvents；意图、发出、结果知识、只读核对及处置分开。未知动作不自动重试，动作实际尝试与本地事务回执重取使用不同语义。
- worker 可续交已导入事实；`reuseEvidenceId` 显式核验同 run/case 原证据及全部来源元数据，不按哈希自动合并或重登记成新采集。
- 报告显示选择范围、任务/规则版本、当次条件、动作及未决事实；比较显示逐目标差异、AI 可比性说明与精确依据。旧结果和旧报告不改写。

旧 v5/v6 数据不原地迁移、不只改版本号；历史原件保留。当前工具拒绝旧格式，重整旧来源须另建新资产并说明事后整理范围。实际命令与数据边界见[回归资料说明](regression-reuse.md)。

## 验证中发现的问题与诚实更正

**BA-01：执行 AI 来源元数据误标。** 首轮十份 AI 资源说明被复用的 helper 标为 tool_receipt/接口原始输出，与实际内容不符。关键业务事实另有原始回执，误标说明未被用于任务来源或改变目标结论。原证据/结果/报告保留，另写更正附录列出真实来源与影响；后续说明正确分类。

针对该问题补充指南，并由另一名无历史背景的 Agent 完成独立 R11 只读专项：仅一次 `inspect S01`，7 份证据逐份核对，原始输出为 tool_receipt、前后 AI 资源说明均为 other，明确未核验真实身份/权限或保存过程。专项支持修订后的来源分类行为，不能说首轮原本正确，也不是重跑十场景的全面证明。

**BA-02：比较声明的精确来源不完整及可读视图遗漏。** 状态比较的一部分 rationale 虽可从行内实际证据核对，但 comparability.sources 未覆盖其中的动作/结果事实。新目录补齐 23 条相应引用，不改结论或原文件。随后修复 MD/HTML 没有展开该声明字段的展示问题：最终两份比较各 11 个来源表，48/61 条来源逐表匹配 JSON 的运行归属、类型、ref、顺序及数量。原比较保留，新目录只重渲染比较，未重跑业务。
