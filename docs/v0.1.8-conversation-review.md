# 四层测试质量优化与通用对话阅读器详细设计

状态：用户已确认四层优化和布局方案2，开发候选为 **0.1.8-rc.2 / conversation-review-1**。先以本地提交 `262fe62` 保存用户已自测基线；本轮仅开发、自测和获授权的安装同步，不重跑业务UAT、不改写原目标/结果、不发布正式版本。

## 目标与边界

1. 用例把业务能力、交互、文案和内容说明分开，明确预期、来源及检查阶段。代码只提示结构缺项或已声明的阶段不一致，不解释业务规则或改变四态。
2. 当前AI按实际页面/协议选择取证和结束依据。工具保管原文、时间、采集完整度和来源；没有固定站点选择器、工具名称、固定秒数或自动重试路线。
3. 实际动作分别保留输入记录、输入摘要、回复摘要及对应消息。原文缺失要能读出缺口；摘要不能冒充逐字原文。
4. 在已确认方案B上增加完整对话侧栏/全屏。每步先显示输入与回复摘要，再查看消息、截图和原始来源；关闭后保留阅读位置。场景总览、目标四态、原始历史和八主题继续保留。

## 数据合同

主资产继续使用schemaVersion 9；本次为同版本的可选事实/展示字段扩展，不建立旧格式转换分支。未提供新事实的历史记录显式显示未采集或未关联。独立对话文件使用conversationVersion 1；历史原件不删除或覆盖。

### ConversationEvidence v1

- `conversationVersion`、`id`、`title`、`messages`、`limitations`。
- 消息有稳定`id`、`role=user/assistant/tool/notice`、`format=text/markdown/json/code`、`content`。
- 每条消息明确`presentation=verbatim/normalized/summary`、`completeness=complete/partial/unknown`、`state=final/streaming/interrupted/waiting_confirmation/unknown`和原始来源引用。时间仅在来源已知时提供；结束依据由AI说明，不等同业务成功。
- `sourceRefs`引用文件内局部`sourceId`，可给JSON Pointer与原文片段。协议字段到此消息结构的解释由AI完成。
- 附件引用局部sourceId，不把不可读取附件替换成虚构文本。只有实际保留的像素能作为截图。

局部sourceId与外部证据ID分离：登记时在`metadata.conversationSources`声明映射，工具核对原文件、引用及原文片段。派生展示不算第二份独立原始证据。并行封包只映射metadata的外部ID，不重写对话文件字节；原hash不变。

### 实际动作及阅读描述

- `ActionFact`增加`inputSummary`、`replySummary`、`conversations[{evidenceId,messageIds}]`和可选的输入保真说明。
- 对话关联须属于该动作的证据，消息须真实存在；同一条消息可以被多步明确引用，不按内容相似去重或猜测分配。
- `Observation`可声明目标检查阶段和实际观察阶段。不同阶段只产生复核提示；业务判断仍由AI提交。
- `Assessment`可提供面向读者的标题、实际现象、影响与检查维度。冻结预期仍原样展示，不以阅读摘要覆盖原验收要求。

## 原始运行只读的整理入口

正式执行通过`evidence-add kind=conversation`保存对话，`record`引用已登记消息。

已有报告需要补齐可读展示时，可在带SHA来源的`report --context`中提供对话声明：对话文件的sourceLabel、局部sourceId到当前目标证据或已核验上下文源文件的映射，以及真实observationId/actionId到消息的绑定。必须关联当前目标已有实际动作，不从计划补动作、借用其他目标事实或提供独立状态。外部文件只读核验；生成新的输出目录，原run和报告保持不变。

## 代码职责

| 层 | 实现 |
| --- | --- |
| 设计/判定 | Skill及经验增加可核对的正反例、检查维度和阶段；合同保存这些声明，复核提示不自动判通过/违反 |
| 取证 | 通用文件/网络取证仍由AI显式组合；明确结束依据、完整度与实际Space/Page来源，避免固定辅助脚本把页面文案当通用协议 |

| 展示 | `src/report/conversations.mts`构造只读视图；`src/report-ui`统一Markdown渲染和对话侧栏；原图不变色，外来HTML不作为可执行页面 |

对话阅读使用固定的通用Markdown与净化组件，构建时打包，用户安装无需npm依赖。不会按被测项目添加字段解析分支。

## 报告与校验

- 每步显式显示输入/摘要、AI回复摘要或未取得回复的说明；关联完整消息可打开侧栏并定位。
- 侧栏显示本目标已关联的对话；用户输入在右、AI回复在左，工具与通知独立标识；支持完整轮次、全屏、定位和关闭返回。
- 截断、仅摘要、未知结束和原文缺失分别标识。文件完整不等于消息完整；AI所说的错误原因不等于后台根因。
- 检查维度在四态旁显示；功能部分正常与文案差异可同时说明，不新增第五种业务状态。
- 文件/引用/阶段/可读性问题单独列复核提示；`verify-report`不认证AI语义或真实业务正确性。

## 自测与安装

1. 合同/解析：来源归属、重复消息、错误引用、JSON Pointer、逐字/整理/摘要边界、部分消息与未知结束。
2. 串行/并行：消息ID映射、源文件hash不变、幂等、失败回收和其他目标不借用。
3. 离线通用夹具：DOM、SSE、WebSocket原始记录由AI提供为同一消息合同，再走同一个报告生成器；没有被测项目适配器。
4. 浏览器：Ego实际打开正式命令生成的HTML，核对步骤原文/摘要、长回复列表表格、侧栏/全屏/关闭返回、来源/图片、主题和缺口。
5. 全量工程检查：类型、测试、公开内容及diff检查。独立前向测试仅用离线合成资料，不触及UAT。
6. 构建完整runtime后同步用户已指定的Skill安装根。只替换受管文件，保护未受管历史；比较清单和hash，运行安装根tool-info及离线报告冒烟。安装完整性与新会话是否刷新分别报告。

## 工程与离线验证记录

2026-11-01，新增10项对话相关工程检查，覆盖逐字伪造、摘要冒充完整、错误JSON Pointer、消息绑定、串行原件保管、并行ID映射、只读context、真实附件、历史缺口及长文本采集。全量测试记录为219项（218通过，1项Windows权限条件跳过，无失败）；类型、公开内容和差异检查分别执行。工程通过不表示真实产品目标通过。

独立离线前向验证使用三份合成来源（事件流、分帧记录、当前DOM节点），实际执行17次CLI与4次API调用，保留3次拒绝与修订理由。统一消息及正式报告全部被接受，三格式/清单/6份附件校验通过；仅有文字证据的目标与缺少结束/业务结果的目标分别判断。发现的指南歧义（report输出目录必须先创建、dimension精确枚举、verified/gaps与范围限制）已修订；原前向报告明确保留其构建版本，不冒称验证后续修改。

Ego实际验证正式生成器产物：步骤摘要及本步消息高亮、侧栏/全屏、完整原件来源、关闭返回步骤/截图及位置；通用标题/列表/表格/代码、120段长回复及末段、在途/部分消息的明确提示。合成攻击HTML未产生script/img，危险链接无href，合法https链接有noopener/noreferrer，未加载外部图片。实际Page辅助采集保留长回复末段，不从可访问性快照推断全文。

浏览器自测发现并修复历史冲突：返回事件处理期间，保存位置曾把旧conversation参数重新写入目标历史条目。现在位置保存不保留正在退出的对话参数；重复关闭、前进重开及来源子弹层返回通过。旧历史原件损坏或缺失时不借用当前同ID文件，也不生成可信聊天视图；当前原件仍严格校验。

真实运行仅在私有目录生成新的只读阅读报告，为两个已有目标整理六条消息，保留原35场景/117目标与原四态；其他目标未因此重测、通过或修订。完整性未知的快照消息明确标识。新报告含既有证据及本次引用的来源附件，原运行、用例与原交付不覆盖。

## 升级影响与限制

主v9可选字段与独立conversationVersion 1不提供旧格式转换；未填新字段的旧记录显示原始观察或缺口。auto含注册对话或事后对话时使用bundle，原件随attachments交付；移动时保留整个报告目录。显式inline未交付事后来源原件会标不完整。

sourceRefs存在、引文匹配及文件hash正确不证明normalized语义或AI填写的完整性/结束声明正确，仍须AI逐条核对。流停止、消息齐全、助手自述成功和真实业务结果保持独立。已安装文件完整性不证明当前会话已重新加载Skill；后续执行先检查实际安装根tool-info。未推送远端、未创建Tag/Release，未生成额外候选安装ZIP。
