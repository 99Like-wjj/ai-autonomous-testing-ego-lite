## 1. 调研结论

12 项需求均有可实施方向。稳定编号、目标级范围、历史报告和审阅文档可以基于现有资产与记录机制继续开发；**下载以 Ego 官方能力为基础，受限场景需要额外补证，AI 测试效果仍需实际对照验证**。不能将本次调研写成所有需求已实现或已验收。

最有价值的实践结果是：

- 当前 Ego 可以通过下载事件和 `saveAs()` 保存实际文件，合成 CSV、JSON、XLSX 的字节及内容核对成功。
- 临时新页直接下载时，父页监听两次分别等待 6.5 秒、4 秒均超时；但浏览器下载记录可以定位原操作实际生成的文件。补证后读到了正确的 144 字节文件和两条数据，没有重发第一次下载。
- 同一下载 URL 再次执行时，用动作前后的下载记录 ID 差集区分新旧条目取得了文件，不能只按文件名或 URL 取最后一项。
- 空文件可以完成下载却不满足业务预期；传输中断有下载事件，却不能成功保存完整文件。下载发起、传输完成、文件取得和内容正确必须分开表达。
- 离线用例文档、检索、审阅意见导出、内容指纹绑定和三轮历史展示已通过合成原型实践；它们还没有接入产品，也没有完成真实团队审阅或真实多轮回归。

可核对的通用实践数据见[合成调研摘要](evaluations/v0.1.8-feasibility/summary.json)。原始脚本、回执、下载文件和截图保存在本机独立调研目录，具体路径随本次交付提供；不将私有项目资料、历史对话或账号写入仓库。

## 3. 用户反馈的历史下载场景

用户补充的具体问题是：测试点击下载后，Ego 右上角出现下载条目，后来仍需要用户手动点击才能完成保存；报告却写无法判断。本轮不将此直接归因为临时新页。

只读核对发现：

1. 原目标要求取得本次下载文件，并核对它与上传文件内容一致；只看到下载条目不足以完成这个目标。
2. 原报告和脚本记录下载事件等待超时，未取得文件；复测记录等待 30 秒、没有新增页，也没有保存实际字节，因此保留无法判断，没有将超时归为产品下载失败。
3. 当前下载管理页仍有一个相关历史合成文件记录；实际文件为 71 字节，与原上传合成文件逐字节指纹一致。这证明文件最终保存过，不证明哪次点击使它完成，也不证明当时 AI 已取得可用证据。
4. 尚缺用户手动点击前后的下载条目状态、按钮文字与准确时间，也未在本轮重现该真实页面。因此不能确定是观察漏收、原生保存/确认环节、浏览器拦截、临时文件访问或其他原因。

结论：原报告在当时证据下保留无法判断有依据；可改进之处是继续观察下载管理状态、识别是否需要人工处理、关联实际文件并说明缺口。此次事后读取另行留证，**不回写原报告或把原轮次改成已验证**。

## 4. 下载能力实践

### 4.1 实际观察

下表评估观察方法，不是对真实产品下载功能的验收。普通路径的文件指纹与实验前生成的合成预期一致；有数据的 CSV、JSON、XLSX 均核对两条记录，金额合计 303.75。

| 实验 | 实际结果 | 对方案的影响 |
| --- | --- | --- |
| 普通页面附件 CSV | 原生事件、保存和内容检查成功，138 字节 | 可作为默认工具能力 |
| 稳定子页面内下载 | 在实际子页预置监听后成功，150 字节 | 应在真正触发下载的页观察，保留 opener/页面关系 |
| 临时新页直接附件 | 父页提前监听两次均超时，临时页消失 | 父页下载监听不能覆盖全部新页下载；单纯增加等待不足以解决 |
| 临时新页事后补证 | 下载管理记录定位已生成文件，取得 144 字节、两条记录 | 有不改变原下载入口、不重发请求的补证方向 |
| 重复同一临时页 URL | 新旧记录 ID 可区分；取得新记录对应文件 | 前后快照和唯一归属重要，文件名/URL 单独不够 |
| 页面生成 Blob | 原生事件与保存成功，134 字节 | 不必依赖服务端存在独立下载请求 |
| 延迟触发导出 | 等待预先就绪后，700ms 延迟触发下载并保存，136 字节 | 可观察异步触发；未验证真实长任务、轮询或导出队列 |
| 两个同名附件 | 均名为 same.csv、同为 138 字节，但内容与指纹不同，各自独立保存 | 禁止靠同名或文件大小合并归属 |
| JSON | 实际取得 115 字节，解析记录与金额正确 | 结构化内容检查可行 |
| XLSX | 实际取得 4968 字节，工作表、字段、两条记录及金额正确 | XLSX 内容检查可行，正式运行依赖还需选择 |
| 0 字节文件 | 原生事件、保存和 failure=null 均成立；缺少预期两条数据 | 传输成功与业务内容正确是两项事实 |
| 声明长度大于实际传输并中断 | 已有下载事件；saveAs 报 download failed: canceled，failure=canceled | 取得事件不等于完成；错误原文不能当作已确认根因 |
| 不返回附件的 404 | 下载事件等待 3 秒超时，页面实际显示合成 404 | 联合页面事实可区分异常；超时本身仍不足以判产品失败 |

另外两项边界观察：

- `download.cancel()` 在当前环境报 `'Browser.cancelDownload' wasn't found`，该实验脚本因此中断，后续 404 检查通过新脚本单独完成，没有重放前面的下载。慢速下载随后在服务端发送完全部 200 个分段。**本环境不能依赖这个 API 取消下载，也不能把停止等待等同停止传输。**
- 指南称临时文件随轮次结束清理；本轮在脚本结束后的独立读取中，检查的 7 个原生临时文件仍存在。后续应及时保存自有证据，并独立核对生命周期，不能依赖文档描述推定文件已删除或永久保留。

中断附件由一次页面点击触发，但服务端观察到 6 次请求。本轮脚本没有追加点击；据此推测存在浏览器内部重试。具体内部归因未确认，工具不得承诺网络请求恰好一次。

### 4.2 候选方案比较

| 方法 | 适用性与证据 | 取舍 |
| --- | --- | --- |
| 原生 download 等待，加同轮 saveAs | 普通页、稳定子页、Blob、延迟导出已实测 | 优先方案；分别保存事件、完成结果、文件及内容检查；不把等待超时自动变成业务失败 |
| 读取浏览器下载管理状态并关联实际文件 | 临时新页两次实践取得原 UI 操作的实际文件；第二次通过前后 ID 差集排除旧条目 | 可作为受限补证能力；依赖内部页面数据、文件权限、唯一关联和安装版本，不是稳定公开 SDK 契约 |
| 用户协助处理浏览器原生确认 | 安装指南明确浏览器权限/原生提示需要用户处理；本次历史案例是否属于此类尚未知 | 需要时准确交接同一 Space，取得答复后继续取证；不绕过浏览器拦截或替用户批准未知提示 |
| 单独 fetch 下载 URL | 可以检查服务响应，但不是原 UI 下载完成证据 | 不作为用例要求的 UI 下载替代；带鉴权、签名和副作用的链接尤其不能盲目重发 |
| 扫描默认下载目录，按最新文件判断 | 易受旧文件、同名、并发和不同保存位置影响 | 不宜作为默认成功判据；本次成功补证没有使用“最新同名文件”猜测 |
| 原始 CDP 修改下载目录、全局接管 | 安装指南要求由 SDK 管理共享下载设置 | 本次未采用，不作为绕过现有边界的方案 |

建议向详细设计阶段带入“原生能力为主、明确的下载管理补证、必要时人工协助”三种可组合能力。由 AI 依据事实选择何时补证或交接，不在工具内部自动换路径或重试业务。

安装指南与公开代码参照：[Ego 使用指南](https://github.com/citrolabs/ego-lite/blob/12407167f84a58af24044f072868051952131491/package/ego-browser/skill-body/SKILL.md)、[公开下载实现](https://github.com/citrolabs/ego-lite/blob/12407167f84a58af24044f072868051952131491/package/ego-browser/src/driver/downloads.ts)。公共代码的页面事件、等待与文件处理有助解释设计；其版本差异和实际安装限制仍须保留。

### 4.3 文件内容检查与运行依赖

- JSON、UTF-8 文本、字节与指纹可以利用 Node 文件能力处理。规范 CSV 需要正确处理引号、换行、编码等规则；本次使用标准 CSV 读取器，不将简单 split 实验当成完整解析方案。
- XLSX 本次通过已安装 openpyxl 实际读取成功；当前产品只要求 Node 22+，不能因此默默增加 Python 必装条件。
- Node 侧存在候选读取依赖。核对官方包元数据时，csv-parse 为 MIT、声明无运行依赖；ExcelJS 为 MIT、声明 9 个直接运行依赖。本轮未安装、集成或测试这两个候选，不据此选择最终依赖。[csv-parse 官方源码](https://github.com/adaltas/node-csv/blob/master/packages/csv-parse/package.json)、[ExcelJS 官方源码](https://github.com/exceljs/exceljs/blob/master/package.json)
- 详细设计应比较项目内读取能力、宿主辅助能力和可选依赖，明确格式、编码、公式/缓存值、大小和内容覆盖。PDF、图片、压缩包及大型/加密文件的语义检查未验证；指纹一致仅能证明约定字节一致，不代表所有业务检查都已完成。

### 4.4 官方能力与本项目开发的边界

建议以 Ego 已开放的下载能力为基础，本项目补齐测试所需的关联、校验和证据处理。普通下载路径不需要等待官方新增接口，也不需要自行实现浏览器下载引擎。

| 能力 | 责任与依赖 |
| --- | --- |
| 在页面操作前监听下载 | 复用官方 `page.waitForEvent("download")`，本机已实际取得事件 |
| 等待下载并保存实际文件 | 复用官方 `download.saveAs()`，本机已取得可读取文件；完成/失败信息也可使用官方对象核对 |
| 识别本次文件、独立保存、检查内容并进入报告 | 本项目补充少量封装、文件读取与证据记录；AI 按业务预期判断，不让下载 API 代替内容验收 |
| 事件漏收后的下载管理补证 | 本项目可增加取证适配；浏览器管理页确有实际记录，但其内部页面结构不是稳定的公开 SDK 接口，需保留版本与权限限制 |
| 浏览器原生确认、取消及其他官方能力限制 | 保留官方边界与真实限制；需要时由用户协助。SDK 本身的能力缺口能否彻底修复取决于官方，本项目不宣称已修复上游 |

因此，主体依赖和复用官方，测试闭环由本项目补充；下载管理补证是候选适配方向，尚未确定最终实现。若官方将来提供覆盖这些场景的稳定接口，应优先评估官方接口，而不是长期维护内部页面适配。用户历史案例为何需要手动点击仍未重现，不能保证仅调用现有下载 API 就消除该具体问题。

## 7. 测试效果与方案质量

效果研究采用相同目标与条件、已知缺陷及正常对照、逐目标复核，分别检查需求覆盖、有效问题、误报/漏报、证据充分性和完成情况。保留改善、退化与波动，不以单一通过率证明效果。

方案评审结合是否充分复用可靠的现有能力、职责是否清晰、证据是否可信、必要依赖是否合适，以及后续维护是否合理说明取舍。下载方案应明确哪些是 Ego 官方能力、哪些是项目取证适配，不能将内部页面适配写成官方稳定接口。

本轮实践支持所列本机能力及限制，没有进行优化前后的对等 AI 测试效果评测，也没有完成真实团队审阅或多宿主行为验收。这些仍需后续验证。

按 2026-11-01 用户指示，取消消耗计量和遥测接入方向；已有原始观察保留为历史，不继续调研、实现或作为验收项。

## 8. 建议审阅的实现方向

1. **下载：**优先利用已验证的原生等待与保存；允许 AI 显式调用下载管理补证能力；遇到浏览器原生确认时保留人工协作。下载事件、完成、实际文件及内容检查分别入账，不自动重发。
2. **文件检查：**先明确需要支持的格式及读取能力来源。不能以本机已有 Python 推导所有安装环境均具备同样能力；不将未验证格式静默排除出用户业务目标。
3. **测试点与回测：**统一稳定身份、内容修订、必要依赖和运行映射；目标级回测贯通整条资料链。具体标识、结构和契约版本留待详细设计。
4. **报告历史：**复用现有不可变运行与比较基础，增加可阅读的历史关系和来源证据；选择基准、分支复测和体积策略仍需设计。
5. **人工审阅：**采用同源离线可分享 HTML/Markdown、实际意见/确认记录和版本绑定。代码验证引用与一致性，AI 负责设计与业务判断；不以模拟操作或程序状态代替真实评审。
6. **测试效果与方案质量：**用实际预期、输出及人工复核检验效果，并说明官方能力复用、项目职责、依赖和可维护性的取舍。质量改善进入后续对照验证。

这些是带实践依据的候选方向，不是已冻结的接口、存储、依赖或 UI 设计。用户审阅后再细化实现方案，不提前更改业务契约或建立兼容层。

## 9. 仍需配合或后续验证的部分

- 用户已提供历史对话，本轮完成只读核对；**尚未在原业务页面重现“右上角需手动点击”的过程**。需要时由用户指出条目的实际按钮/提示，并在相应浏览器原生确认环节操作；随后在同一任务中核对下载记录、文件及内容。无需提供账号密码、Cookie 或 token。

原始失败、后续补证、合成原型和未验证范围均保留。需求文档已确认；具体实现方向以本调研审阅结果为下一阶段依据。
