# Ego项目知识v2接入与按阶段使用详细设计

本文保留v2阶段设计历史；当前源码的轻量格式v3见[优化方案](project-knowledge-lightweight-integration-design.md)。

日期：2026-11-03。状态：**设计已批准；已实现并完成合成回归，未安装或发布。**

实际验证见[开发自测](v0.1.9-development-validation.md)。四类数据结构的唯一设计源为相邻project-knowledge-maintainer仓库的 docs/v0.1.9-project-knowledge-v2-detailed-design.md。本文规定Ego如何接收、选择和读取这些资料，不复制另一套格式定义。所有场景、项目、地址和账号示例均为完全合成内容。

## 1. 当前事实与目标

本次优化前的知识模块支持v1 inspect/query/read；本次已实现[v2分类读取](../src/knowledge/commands.mts)。CLI入口在[ego.mts](../src/scripts/ego.mts)，当前使用指南在[project-knowledge.md](../skills/ai-autonomous-testing-ego-lite/references/project-knowledge.md)。设计/执行阶段的适用性、来源冲突和现场核对提示也已按本设计细化。

目前的限制是：入口和URL多在陈述正文中，账号与多环境页面没有专门结构，角色规则也可能只有概括性边界。源码工作区还存在其他未提交开发，不能reset、覆盖或把本设计顺带变成无关重构。

目标是在不改变AI自主测试方法的前提下，使用四类资料降低页面探索和公共规则补读成本。知识仍是可选上下文，程序不承担业务路线选择、账号授权推断或结论判断。

用户已明确不要求旧有资源兼容：维护端、Ego读取端及其合成验收统一按新格式v2设计，不增加旧格式解析、双轨读写、自动转换或旧资源映射流程。后续知识文件可由AI按新格式原生生成；本轮仍仅优化Skill，不执行真实知识重建。源码中合理的事务、证据及校验能力可以复用，业务来源历史与冻结结果仍按原授权边界保留。

## 2. 一次任务如何指定知识库

### 2.1 用户交互

用户可在调用Ego时给本地根目录、项目和目标环境，例如：

> 使用Ego Lite测试完全合成图书协作项目，知识库位于C:\synthetic-work\knowledge，目标环境为示例测试；根据本次需求设计并执行允许的目标。

知识维护仍调用维护Skill。测试时Ego直接读相同数据，不要求先运行维护Skill、不读取HTML作为机器入口，不把真实资料复制到Skill。

支持本地绝对目录。Coding等远端先通过独立获准的同步得到本地副本；读取命令不自动clone/pull、不扫磁盘匹配项目。

### 2.2 任务上下文

AI保留一个本轮逻辑KnowledgeContext：knowledgeRoot（可空）、expectedProject（已知ID/名称）、environmentId（可空）、applicationIds（可空）、revision选择及实际读取回执。它是任务上下文，不新增全局注册中心，不写入AGENTS或Skill安装目录。

- 用户本轮已经给的根目录不重复问；恢复同一任务时保留目录及所用快照。
- 新任务显式附路径即可；不承诺未提供地址的新对话自动发现知识库。
- expectedProject来自需求和用户任务：优先稳定ID；只有项目名时按名称核对并明确只是名称匹配。
- 只有目录而没有独立项目身份时，可先inspect/读取带not_checked标记的准备资料；用作正式预期前应结合本次需求确认项目，不从库里抄ID来假装完成独立身份校验。
- 环境未指定则返回可选环境摘要，AI结合目标选择或保留未知；不默认第一个环境或从域名字符串猜环境。
- “账号有权限”与“本轮获准执行该操作”分别判断。

不为每个测试CLI命令都增加knowledgeRoot参数；通过knowledge子命令按需取资料，使用到的来源进入现有用例/运行事实。主链仍是AI显式调用。

## 3. 可选知识的运行行为

### 3.1 availability

| 场景 | 只读返回 | 对主任务的影响 |
| --- | --- | --- |
| 未提供根目录 | not_configured，items=[]，不探测文件系统 | 正常继续，通常不必专门打断用户 |
| 合法空库或选定类别未配置 | available，empty=true，类别标not_present/empty | 不造数据，不强制补库 |
| 请求的内容有效 | available | 按实际需要使用 |
| 选中类别及其关联内容中部分损坏/坏引用 | partial，保留独立有效项与影响诊断 | 仅停止使用受影响资料 |
| 根不存在、头损坏、项目不匹配、版本不支持、文件读取不稳定 | unavailable，items=[] | 说明本次来源未使用，继续需求/代码/页面已支持的目标 |
| 工具参数非法或请求JSON语法错误 | 调用错误，非零退出 | AI修正调用，不伪称业务失败或知识不存在 |

其中available/partial/unavailable只描述本次请求的数据可用性，不是测试四态。单类别本身不可用时返回unavailable；同类或关联内容中仍有可用部分时返回partial。头身份无法成立、项目不匹配或在途写事务无法保证快照时，整个来源unavailable。

缺少可选文件不是损坏；明确存在但格式坏了的文件不是空集合。不能用静默空结果掩盖错误，也不能因为accounts未配置就让rules读取失败。

### 3.2 工具和AI的分界

底层严格解析器仍拒绝非法结构、越界路径和不支持版本。消费CLI将已知知识来源错误封装成上述可用性结果，正常返回；不向用户暴露技术堆栈，也不因此中断全部测试。

AI决定是补资料、继续独立目标、进行授权范围内探索，还是对受影响目标记录无法判断/未测试。没有知识库不意味着业务条件齐备，更不意味着目标通过。

## 4. inspect / query / read 请求

CLI形状保持：

```text
ego knowledge inspect [--knowledge-root ABS]
ego knowledge query [--knowledge-root ABS] --request ABS_JSON [--output-file ABS_NEW_JSON]
ego knowledge read [--knowledge-root ABS] --request ABS_JSON [--output-file ABS_NEW_JSON]
```

上面是设计中的接口，当前v1尚未支持省略根目录的调用。省略根目录优先返回not_configured，不读请求文件；根目录已提供时query/read仍要求合法request。

### 4.1 参数约定

| 字段 | 约定 |
| --- | --- |
| expectedProject | 可含id/name；ID匹配优先，名称差异如改名要明示；无期望身份返回not_checked |
| category | query/read必填：project、modules、rules、accounts |
| query | 可选自然语言关键词；当前沿用关键词/别名/正文匹配，AI可改写查询，不承诺语义向量检索 |
| recordIds | read精确记录ID；可指模块、角色、规则、陈述、账号或配置记录 |
| kinds | 类别内类型筛选；例如rules中的rule/role、project中的environment/application/page/scope |
| moduleIds / roleIds / domainIds | 按已登记关系/分组过滤；不通过角色名称推断实际业务权限 |
| environmentId / applicationIds / scopeIds | 可选适用范围；未知状态可返回但须标清，不能解释成全环境适用 |
| includeRelated / maxDepth | 显式展开关系，默认false/1；深度上限仍为5 |
| offset / limit / maxBytes | 默认0/10/24000，limit上限50，maxBytes范围2048–200000；总输出含来源/诊断 |
| allowDraft / commit | 读取明确本地工作区或完整Git提交；不取远端、不checkout、不自动合并 |

合成请求示例：

```json
{
  "expectedProject": {
    "id": "synthetic-project"
  },
  "environmentId": "env-synthetic-lab",
  "category": "modules",
  "query": "示例馆藏",
  "recordIds": [],
  "kinds": [],
  "moduleIds": [],
  "roleIds": [],
  "domainIds": [],
  "scopeIds": [],
  "applicationIds": [],
  "includeRelated": true,
  "maxDepth": 1,
  "offset": 0,
  "limit": 10,
  "maxBytes": 24000,
  "allowDraft": true
}
```

### 4.2 类别选择及关联

- project：先查环境与页面摘要，需要时read稳定URL、openMode和局限；不自动打开页面。
- modules：摘要查模块、所属域与入口引用，read返回模块级路径；跨页时明确页面应用及环境。
- rules：按角色名、业务别名、moduleIds等定位，再读完整自然语言正文。父角色存在多种分段状态时逐段保留，不把其summary当完整权限。
- accounts：摘要显示alias、环境、声明角色、范围与限制；精确read才显示登录标识和逻辑凭据引用。工具始终不读取秘密。
- 默认关联：模块到页面/角色/规则，账号到角色，规则到显式引用。不会从角色反向拉取全部账号，不展开原始来源全文。
- 一个query摘要按顶层记录计数，不因模块有多条入口/观察就重复占页；read保留内部稳定ID和各自状态。较长子记录也受整体字节预算，真实返回省略与继续读取定位。

recordIds精确读取也不跨项目绕过身份检查。不同环境/版本的历史记录可供对照，但必须返回scope匹配状态，不能把不匹配陈述当作本次标准。

## 5. 读取结果与可追踪性

结果统一knowledgeReadVersion=2，包含以下信息：

| 部分 | 必备内容 |
| --- | --- |
| availability / empty | 第3节的来源可用性与选定内容是否为空 |
| selection | 实际root、knowledge/project身份、identityCheck、environment/application选择 |
| version | 完整本地Git commit或null，draft/unmerged、读取模式、remoteFreshness=unknown |
| snapshotSha256 / usedFiles | 当前受管数据指纹、实际使用文件与SHA；不以mtime代替内容 |
| categorySummary | 请求及实际展开类别的presence/数量/局限，不加载未选择类别的正文 |
| items | category、id、kind、title、summary或content、states集合、scope标记、定位、来源及关联 |
| diagnostics | 来源不适用、缺引用、内容损坏及未知条件的具体影响；默认不回显秘密或大段原文 |
| pagination | offset、limit、returnedCount、nextOffset、truncated及omitted定位 |

not_configured或无法建立可信快照时，knowledgeId、snapshotSha256和Git字段可为null，usedFiles为空；不生成假的身份或指纹。

scope标记至少分开environmentMatch、applicationMatch和versionNote。软件版本未知不让JSON读取失败，也不伪称版本已适用；版本条件的业务判断由AI做。

状态含义沿用主设计的confirmed/observed/pending和lifecycle。入口Check的verified只支持其coverage，不能投射到完整业务功能。账号meta.state=confirmed也不代表本轮已登录、当前角色有效或凭据可用。

## 6. 分阶段提示词设计

阶段提示是AI的资料使用建议，不是强制决策树，不要求每个目标重复查询。已取得且适用于本轮的知识可以复用，实际范围或版本变化时再核对。

### 6.1 Skill入口建议文本

> 本次若提供项目知识库目录，按目标需要查询项目配置、模块入口、公共规则和账号说明。先获取相关摘要，再读取必要正文；功能细则仍按本次需求阅读。未提供或无法使用知识库时，继续已有资料支持的目标，不要求先建库。来源项目、适用范围、确认/观察状态和局限分别保留。知识和账号配置不构成真实环境操作授权，历史入口与角色说明须结合本轮现场核对。

### 6.2 需求分析与用例设计

> 遇到角色、共享范围、数据归属、公共前提或多功能共用概念时，可查询相关规则及角色完整正文，核对本次需求是否明确替代旧口径。利用模块与规则关联判断影响面，按需要查账号权限组合和环境入口；不把知识库收录范围当作需求验收范围。缺账号资料时先保留测试资源条件，不反复催促用户已暂缓的事项。

规则正文需表达允许/禁止/范围/例外，而不是只检索“管理员”得到一句权限隔离原则。当前有效新需求有明确范围时按其设计，保留旧知识差异；不能选择更容易通过的预期。

### 6.3 执行与探索

> 按本次环境读取项目页面及模块入口提示，必要时查询适用公共规则。已有可信入口时减少无目的探索；页面入口失效或资料未登记时，可在本轮授权内自主探索。账号说明只辅助选择候选身份，实际登录、角色与对象权限仍按本轮事实核验；不得自动提权、改号配置或继承另一用户上下文。

openMode=via_ui时按产品入口进入，避免直接拼接一次性登录地址。菜单文字与记录不同时先观察实际页面，不执行录制式坐标脚本。功能地图没有入口不说明该功能不存在，也不说明可以跳过必要业务步骤。

### 6.4 发现差异与维护交接

> 保留当前观察、时点、对象、身份与证据，和现有规则分别记录。普通测试只读项目知识，不把一次现场现状自动写成规则；用户要求维护时再交给维护Skill整理并按确认范围更新。知识变化不自动改写冻结用例、历史结果或既有报告。

## 7. 用例、运行与证据对接

测试资产schemaVersion仍为v9；本次不因知识格式v2改变测试主契约。

实际用到知识时，可用现有output-file生成不可变知识摘录，并返回现有SourceRef的id、locator、file、sha256、excerpt、limitations供用例引用。摘录只包含本次用到的记录、必要来源与状态，不默认复制整库或账号登录标识，绝不包含秘密。

- 阅读回执/摘录是派生上下文，不是原始需求或本轮执行观察。
- 冻结时保留被用作依据的知识版本和条目定位；以后库变动不修改原摘录。
- 执行时需要额外知识可新建摘录，保留与原目标关系；有效预期变化仍按原审阅机制处理，不让新知识自动把旧失败变成通过。
- 对外报告默认显示账号别名、角色和必要范围，避免输出不必要登录标识或任何凭据。
- 文件校验、读取成功、页面可见、业务验证分别表达，不能互相替代。

## 8. 缺失、损坏和冲突的具体处理

| 情况 | 预期行为 |
| --- | --- |
| 无knowledgeRoot | 不报知识库缺失错误，不为此创建空库；继续需求分析和授权范围内工作 |
| 未知项目/环境 | 可inspect并保留未知，不自动套另一项目/环境的配置；正式预期从当前有效资料确认 |
| 模块没有入口 | 回原资料或现场探索，不造URL、按钮步骤或“功能不存在”结论 |
| 配置页引用损坏 | 仅该入口不能可靠定位，模块用途及独立规则仍可读；不默认套项目首页 |
| 无accounts或无匹配账号 | 不伪造可用身份；继续独立设计/观察，依赖角色切换的目标保留相应限制 |
| 一个角色陈述冲突 | 返回双方依据和影响，不因其同属一个文件就丢弃独立有效规则 |
| 在途写事务/内容读中变化 | 本次知识来源不使用，等待维护恢复或使用明确已知提交；不自动删事务标记 |
| 库版本不支持 | 清楚说明不支持该数据来源，不降级猜读；其他测试资料继续可用 |
| 本地草案或未合并 | 由AI明确选择工作区读取及allowDraft并保留标记；不再追加无依据审批流程，也不称团队最新 |
| 原始资料不可访问 | 保留已知定位和局限，不编造内容或SHA |

## 9. 源码、指南与分发影响

计划改动：

- src/knowledge/contract.mts、store.mts：消费维护端固定v2副本，覆盖四类受管集合和元数据。
- src/knowledge/commands.mts：类别查询、摘要/精确读取、稳定ID关联、预算与可选来源结果。
- src/scripts/ego.mts：knowledge子命令的可选root、参数及回执；不改业务执行路径。
- schemas/project-knowledge.schema.json及来源清单：共用v2合同；按既有生成方式更新类型，不直接改生成文件。
- Skill的项目知识段及project-knowledge、资源/设计/执行指南：按第6节细化，避免重复长篇；账号与入口条件读相关引用，不默认载入全部资料。
- 测试围绕知识读取与CLI扩展；与其他未提交功能保持清晰边界，不改无关报告/审阅逻辑。

运行分发只含实际读取代码、必要Schema和AI使用指南；真实知识、设计文档、审核稿、账号/配置及UAT产物留在库外。按真实源版本和SHA登记来源，未提交时不能伪造sourceCommit。

## 10. 验收场景

| 编号 | 合成场景与应见结果 |
| --- | --- |
| E01 | 只给需求不给知识路径：AI继续任务；工具省略root返回not_configured，不要求建库 |
| E02 | 目录不存在或头损坏：来源不可用且无堆栈；已有有效需求不因此被阻断 |
| E03 | 正确项目与错误项目：前者可读；后者不返回业务条目，不搜索其他目录“修正” |
| E04 | 同模块在两应用/两环境：通过pageId取得正确地址/路径；不默认第一项、不混登录信息 |
| E05 | 角色包含完整允许/禁止及部分待审段落：query摘要后可read正文，逐段状态不被summary吞掉 |
| E06 | 模块关联角色/规则：展开目标ID，分页和字节限制真实生效，不反向展开所有账号 |
| E07 | 无账号配置：只影响相应资源条件；手动登录/已有会话可按实际授权继续 |
| E08 | 声明角色与现场不符：配置不冒充实际权限；账号不被自动改权 |
| E09 | 逻辑credentialRef：不解引用，query不泄露登录名；read不返回秘密或环境会话 |
| E10 | 一个配置/主题损坏：返回局部影响，独立有效规则仍可读；validate不伪报全库有效 |
| E11 | 多模块索引和较长规则：默认只给摘要，完整读取有明确truncated/nextOffset |
| E12 | 新资料改变旧口径：保留版本差异和旧摘录，不改原目标/结果 |
| E13 | 检索未命中：允许AI改写查询、读原需求或现场探索；不把未命中当“不需要测试” |
| E14 | 暂缓账号准备：AI不重复索要；单身份观察不被报告为跨角色通过 |

先通过确定性合成联通，再使用合成任务检查AI是否实际选择了相关资料、保留原目标且正确说明缺口；不以固定措辞/标题匹配代替行为验证。真实UAT和安装升级按当次明确授权另行开展。
