# 用例设计方法与适用边界

这里提供判断方法，不新增业务标准、数据字段或固定工作流。

<a id="d-boundary"></a>

## 边界与等价类

适用阶段：设计。

先确认有效域、单位、字符口径和精度，再选择有效/无效代表及关键边界。明确的两端限制都应有对应检查；不是多造相同成功输入。

不适用与边界：连续值、浮点步长、Unicode 长度不能机械加减 1；规则未定义时提出问题，不补一个常见上限。

具体场景（合成）：数量规则为 1～20 的整数，只有数量 5 的成功用例不足以表达两端限制。可考虑 0/1/2、19/20/21 和 1.5，分别代表边界邻域与非整数类别；这些数字不是固定必选清单。

设计复核：说明所选代表覆盖哪条规则、预期依据和必要前提，按风险去重。空值或自动取整规则未知时单列待澄清，不从常见实现补规则。不适用例：金额精度或 Unicode 字符长度不能机械套用整数加减 1。此处只复核用例，不表示已输入或业务已通过。

<a id="d-combination"></a>

## 条件组合

适用阶段：设计。

识别会改变结果的条件组合、约束及相应预期，必要时用小型决策表帮助审查。优先覆盖明确规则与高风险交互。

不适用与边界：不穷举不可能组合；两两覆盖不能替代已知的三条件规则，不凭空指定覆盖百分比。

具体场景（合成）：只有“已生效、未过期、额度足够”同时成立才允许使用。可将全成立与各条件不成立的可达情形列成小型决策表，说明预期及条件依赖。

设计复核：检查明确的三条件规则是否被表达；按风险选择交互情形，不把两两覆盖当作所有高阶规则已覆盖。不适用例：业务上无法同时形成的状态组合不应强造；记录排除理由。条件是否可达或规则优先级不明确时保留问题，而非宣称已全覆盖。

<a id="d-state"></a>

## 状态转换

适用阶段：设计。

表达初态、事件、目标状态与必要拒绝路径，保留历史和业务依赖。区分操作已提交与状态真正达到。

不适用与边界：若目标要求历史或特殊状态，不能换成刚创建的普通对象；页面当前状态不是需求依据。

具体场景（合成）：待审记录可撤回，已批准记录不可编辑。用例应分别列出待审、已批准对象的前提及可行准备方式，表达动作、目标状态或拒绝结果。

设计复核：拒绝路径不仅写提示，还考虑按规则应保留的原状态与必要数据。需要历史审批链时明确它，不用新建草稿代替。不适用例：纯设计时账号或对象尚未提供，不必先操作系统；标明执行前待核实条件，不能声称真实数据已准备好。

<a id="d-relation"></a>

## 业务流程与数据关系

适用阶段：设计。

围绕独立业务目标保留必要连续动作与关系核验。删除设计要明确对象归属、关联状态、删除语义和批量部分结果是否有规则。

不适用与边界：自建自删是执行选数建议，不应删掉历史数据、他人对象或关联约束的设计覆盖。不要把多个无关目标塞成一个大用例。

具体场景（合成）：被订单引用的地址不可删除。设计应表达地址与有效订单引用这一前提，提供获授权后的准备方案，预期包含删除拒绝及按规则保留地址和引用关系。

设计复核：每个关系结论都有对应前提和可观察结果；只删除无引用新地址不能覆盖该规则。自建自删可用于准备合适对象，但不能改变关联条件。不适用例：已有历史订单关系不可安全构造时，保留资源缺口和用例草案，不擅自创建真实订单，也不把未执行写成通过。

<a id="d-permission"></a>

## 权限与对象范围

适用阶段：设计。

按明确规则设计允许与拒绝条件，说明身份、对象和观察层次。入口可见性和服务端拒绝是不同目标。

不适用与边界：不把隐藏入口当成服务端授权已验证；未授权接口测试不能因经验提示而自动加入执行。

具体场景（合成）：成员可查看本项目记录，不可查看另一租户记录。分别列出角色、成员关系、对象归属及明确的允许/拒绝规则，把入口展示与实际访问区分为不同目标。

设计复核：每个目标的身份、对象前提和观察层次对应，缺账号按资源指南澄清；可以设计负向用例，但设计不授予执行权限。不适用例：只有 UI 隐藏要求时，不强制扩展到直接接口攻击；换管理员运行也不能覆盖原成员目标。

<a id="d-recovery"></a>

## 异常与恢复候选

适用阶段：设计。

根据目标选择有价值的异常和恢复候选，写清触发条件、预期依据及副作用。未知重复处理策略应列待澄清。

不适用与边界：不能把通用经验变成业务契约；断网、超大输入、攻击或真实付费操作均需实际授权。

具体场景（合成）：需求明确提交失败后保留表单内容，恢复后可继续。用例可列出可控且获准的失败条件、关键输入、失败后保留内容、恢复前提和预期。

设计复核：触发方式可行、授权边界清楚、结果能被观察；未获准触发异常时保留准备条件，不虚构已具备。重复提交策略未知时单列待澄清。不适用例：不能为体验“恢复”而自行断开共享网络、触发真实付费或规定系统必须自动重试。

<a id="d-persistence"></a>

## 持久化与转换核验

适用阶段：设计。

明确同一对象、必要属性、集合或关系在操作后应怎样变化，选择实际可用的观察方式。

不适用与边界：不是所有导入导出都要求逐字节相同；不能要求未具备的数据库查询，也不把页面旧值直接当持久化失败。

具体场景（合成）：名称从 A 改为 B。除保存提示外，可设计离开后重新读取同一对象，核验名称 B 和需求明确要求不变的属性。

设计复核：对象稳定标识、属性与结果依据明确，观察渠道在实际能力范围内；页面缓存可能影响读回，设计应允许区分缓存与持久化。不适用例：不能因为数据库查询更直接就假定有数据库权限；没有不变约束的动态字段不应一概断言必须原样保留。

<a id="d-regression"></a>

## 受影响回归

适用阶段：设计。

从变化的规则、共享组件和依赖识别邻近风险，说明选择理由，区分原缺陷复测和回归。

不适用与边界：不默认全站重测，不只验证新增入口；资料不足时说明影响范围不确定。

具体场景（合成）：修复编辑页名称长度校验，资料表明新建入口复用同一校验。先表达原缺陷复测，再按共享事实选择新建入口及相关边界回归。

设计复核：每项回归都有与变更的关系、独立目标和预期来源；影响范围资料不足时标注不确定性，并选择有理由的探索候选。不适用例：仅因两个入口看起来相似就宣称共享实现，或扩展为全站必测。复测成功也不覆盖原版本失败记录。
