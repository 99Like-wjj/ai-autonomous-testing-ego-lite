# 用例设计方法与适用边界

这里提供判断方法，不新增业务标准、数据字段或固定工作流。

<a id="d-boundary"></a>

## 边界与等价类

适用阶段：设计。

先确认有效域、单位、字符口径和精度，再选择有效/无效代表及关键边界。明确的两端限制都应有对应检查；不是多造相同成功输入。

不适用与边界：连续值、浮点步长、Unicode 长度不能机械加减 1；规则未定义时提出问题，不补一个常见上限。

<a id="d-combination"></a>

## 条件组合

适用阶段：设计。

识别会改变结果的条件组合、约束及相应预期，必要时用小型决策表帮助审查。优先覆盖明确规则与高风险交互。

不适用与边界：不穷举不可能组合；两两覆盖不能替代已知的三条件规则，不凭空指定覆盖百分比。

<a id="d-state"></a>

## 状态转换

适用阶段：设计。

表达初态、事件、目标状态与必要拒绝路径，保留历史和业务依赖。区分操作已提交与状态真正达到。

不适用与边界：若目标要求历史或特殊状态，不能换成刚创建的普通对象；页面当前状态不是需求依据。

<a id="d-relation"></a>

## 业务流程与数据关系

适用阶段：设计。

围绕独立业务目标保留必要连续动作与关系核验。删除设计要明确对象归属、关联状态、删除语义和批量部分结果是否有规则。

不适用与边界：自建自删是执行选数建议，不应删掉历史数据、他人对象或关联约束的设计覆盖。不要把多个无关目标塞成一个大用例。

<a id="d-permission"></a>

## 权限与对象范围

适用阶段：设计。

按明确规则设计允许与拒绝条件，说明身份、对象和观察层次。入口可见性和服务端拒绝是不同目标。

不适用与边界：不把隐藏入口当成服务端授权已验证；未授权接口测试不能因经验提示而自动加入执行。

<a id="d-recovery"></a>

## 异常与恢复候选

适用阶段：设计。

根据目标选择有价值的异常和恢复候选，写清触发条件、预期依据及副作用。未知重复处理策略应列待澄清。

不适用与边界：不能把通用经验变成业务契约；断网、超大输入、攻击或真实付费操作均需实际授权。

<a id="d-persistence"></a>

## 持久化与转换核验

适用阶段：设计。

明确同一对象、必要属性、集合或关系在操作后应怎样变化，选择实际可用的观察方式。

不适用与边界：不是所有导入导出都要求逐字节相同；不能要求未具备的数据库查询，也不把页面旧值直接当持久化失败。

<a id="d-regression"></a>

## 受影响回归

适用阶段：设计。

从变化的规则、共享组件和依赖识别邻近风险，说明选择理由，区分原缺陷复测和回归。

不适用与边界：不默认全站重测，不只验证新增入口；资料不足时说明影响范围不确定。
