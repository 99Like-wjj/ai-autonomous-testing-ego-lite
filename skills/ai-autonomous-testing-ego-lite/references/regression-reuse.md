# 首次成果留存与 AI 回归复用

实际测试及后续回归时阅读。本指南固定事实、规则、必要业务语义和授权边界；具体探索、取证、整理时机与执行方法仍由 AI 判断。所有资料属于当前项目，保存在仓库外的私有项目目录，不写回通用经验。

## 自动记录，分别保留规则与事实

首次测试不必等用户提醒才保存。关键输入、身份/对象初态、实际动作、独立读回、异常、阻塞、暂缓和恢复事实及时进入当前 run；不能到结束时从记忆补造整条路径。动作尚未完成、功能未实现、工具失败或结果未知同样有记录价值。没有记录的区间明确为缺口。

使用 v7 的 `record.contexts` 和 `record.actionEvents` 补充上下文与动作事实，观察引用 `contextId/actionEventIds`；原 observations、assessments、证据及业务四态继续使用同一账本。计划、实际动作、目标评估是不同内容。准备、测试、复现、恢复、清理分别标明目的，临时刷新/重登/换入口不自动进入标准回归路线。字段及可运行的合成数据事务示例见工具根 `examples` 与本地工具箱。

每个业务预期只来自可信需求或真实确认。`regression commit` 可保存带原文位置、原文件指纹和确认依据的规则修订；实际观察、历史通过/失败或产品现状不能作为规则来源。明确负向拒绝仍按要求判断，不能按“出现错误提示”机械定缺陷，也不能把同样错误再次出现判成产品通过。

AI 写的资源说明、授权摘要和判断笔记按 `other` 登记，source 明示 AI 编写；只有实际工具原文才用 `tool_receipt`，不能为所有文件套同一原始回执标签。误标时保留历史并另写来源更正与结论影响。

关键 UI 结果和缺陷仍须真实当次截图。旧截图、原型图及文字推测只能作为历史或设计参考；来源、截取范围、缺图和正文不足明确说明并复核结论。时间来源未知时不补造发生时间。

## 保存可复用任务

有足够事实时主动整理项目回归任务，暂停/交付前对照原目标检查是否已有任务映射或明确整理缺口。不要只保存成功项，也不要把全部探索点击转成脚本。使用 `regression context` 分区读取规范、历史事实与尚未整理目标，再由当前 AI 提交任务。

任务保存完整场景计划、独立目标、精确规则引用、来源 run/结果修订/证据、必要条件和顺序、数据关系、路径知识与缺口。某环节来自需求但未真正到达，应写 `required_unreached`；未知写 `unknown`，不能靠有一个文件或工具回执宣称页面已核实。失败路径可以完整且有复测价值；“定义完整”从不表示产品通过。

内容成熟度 `candidate/incomplete/defined` 与适用性、当次条件、业务四态分开。缺少正确判据时允许 `casePlan:null` 候选，并保留来源目标与缺口；不能为填满 expected 反推产品标准。任务中的 expected 是规则的任务化表达，参数化不得改规则含义。可信规则和充分资料可由 AI 自主整理，不要求所有任务逐条人工认可；不明规则、授权或用户指定审核的内容才实际澄清。

修订使用相同 taskId/ruleId 的新 revision，填写 supersedes 精确指纹与 reason，旧修订不覆盖。规则确认变化时保留新确认来源；任务误读既有规则的纠正也要另建任务修订并说明原因，不把旧运行失败改绿。原资料失效时报告来源缺口，历史快照仍保留。

## 有副作用的动作与未知结果

对可能重复创建、删除、发送或改变状态的动作，先记录 `intent`、稳定 actionId、对象、关键输入、授权来源及可能副作用，再进行获授权的实际动作；保存意图失败时暂停该动作。意图不是发出证明，意图之后没有回执也不能断言未发生。

后续分别追加 `dispatch`、`result`、`reconciliation` 或 `disposition` 事件。发出、请求接受和业务终态分开；处理中、观察窗口内未完成、明确失败及未知保留各自事实。观察窗口只是实际等待范围，业务时限必须来自规则。偶发失败后的成功不删除首次失败、环境和复现限制。

暂停/恢复和重跑前读取 `progress/check` 的未决动作。先按授权只读核对实际对象和状态，结合明确幂等依据及授权决定下一步；工具不自动重放，也不停止所有独立目标。核对仍未知或暂缓时保留风险。确认处置必须引用证据、说明核对范围/限制并关联相应事件；不能只写“继续测试”结清。

每个 actionId 只代表一次实际尝试。本地保存失败重取回执使用原 operationId；真正再次发起业务动作需新 actionId，关联前次尝试及重试依据和当前授权。代码的事务幂等不等于产品幂等。浏览器与本地文件没有跨系统原子提交，不能承诺业务恰好执行一次。

工具定位过期、误点、断连或截图失败保留为实际工具现象，不固化为正确业务步骤。无法归因就记录不确定性；业务违反已被有效事实证明时，也不必等查明后端根因才报告违反。

## 用户选择两种重跑范围

`case` 是场景/用例组，`goal` 是独立验收目标。当前约定以整条场景作为重跑单位。

| 用户选择 | 选择口径 |
| --- | --- |
| 按状态重跑 | 指定基准 run 的 baseline 哈希、结果修订/前缀哈希，可选一个或多个业务状态；任一 goal 命中则选中整个 case，重新评估全部目标。 |
| 全量回归 | 指定完整范围及版本，不按历史四态过滤；未整理、待补全和受阻项都保留在范围中。 |

四态是已验证、发现违反、无法判断、未测试。缺评估不是未测试，也不是第五种业务状态；按状态时可显式选择包含缺评估场景。四态全选仍可能漏掉缺评估项，不能自动等同全量。零匹配说明没有命中，不自动回退全量，不生成空范围通过。

用 `regression select` 根据明确条件生成固定选择快照；不要边运行边更改基准或把历史 attempt 当正式结果。事先说明命中目标、整条选中场景及实际计划重跑的全部目标。无法可靠映射的变化保留问题，不猜测新旧目标等价；全量保留完整范围及映射缺口。

重跑前按[资源指南](resource-readiness.md)重新核对身份、租户、环境、对象归属/关联状态、数据及授权。历史“可用”和历史授权不自动变成当前就绪。历史 ID 仅作参考；不能用不等价的新空对象替代有历史关联的对象。准备/清理也要按当次授权，不能默认清缓存、重建或重置从而掩盖待测状态。

本轮条件中的 `source.kind=current_evidence` 必须提供 file 与 SHA；`ai_declaration/current_user_statement` 使用真实 locator，file/sha256 保持 null，不把声明包装成已核验文件。declaredAt 使用真实声明时刻的 UTC 秒或三位毫秒 Z 格式（如 `2026-10-30T08:00:00.000Z`），不使用示例时刻代替实际时刻。

`start --binding` 接收本轮 binding request，校验选择快照、完整场景计划、任务/规则精确修订及本轮条件来源，再创建独立 run。条件由 AI 依据事实说明，工具不认证真实就绪。selected case 必须编入基线或显式列为 deferred，不得在查询可执行任务时丢掉。独立、信息充分且获授权的部分可继续；缺规则或资源的部分保留缺口，不能降低预期。

界面可重新观察和定位；用户要求的必要入口、顺序、对象关系和验收标准不能静默替换。必要语义变化需明确修订并保留映射。场景外依赖需要额外实际操作时说明新增范围并核对已有授权，不因筛选命中便扩大操作许可。

HTML 报告中的状态筛选只是浏览报告；开始重跑通过用户向 AI 指定范围，或调用本地数据命令准备资产，随后由 AI 按授权执行。

## 新运行、比较与交付

每次正式回归独立新 run；本轮续接可在同一冻结基线追加事实。原观察、评估和证据不覆盖，旧证据不登记成新采集。本轮未选中项只显示范围说明，没有本次结果；不能沿用历史通过，也不凭未选中制造 not_tested。

报告区分原范围、选中范围、本次冻结范围、受阻/待补全项和未选中项。选中范围都通过只说明该范围通过；全量选择不代表全量执行完成。缺评估仍是入账缺口。

`regression compare` 使用两次精确结果快照及显式目标映射，展示规则/任务、身份、环境、数据、授权、范围和路径差异。AI 另行给可比较、受限或不能直接比较的依据；历史通过、本次违反只是排查线索，不自动证明新版本引入缺陷。修复后核验原要求和必要关联影响，不能只看旧报错消失。

比较另存 JSON、Markdown、HTML，不修改任一源运行。文件字节相同不证明同一次采集；不同运行中真正独立截图可以同哈希。来源缺失或限制明确呈现，不用快照文本冒充原证据仍完备。

当前主契约 v7、回归资料 regressionVersion 1。旧 v5/v6 资料不原地转换、不只改版本号；已有来源若需重整，创建新资产并注明事后整理和原始来源，不冒充首次自动记录。历史资产保留，开发自测不自动安装或发布。
