# 用例复用与重测（regressionVersion 2）

主契约 v9。长期资料只有用例版本、实际审阅和各轮运行。首次测试及时留存关键事实、失败与未完成点；可信规则直接整理到用例依据，问题留在 findings、phenomena 与评估，不提交独立规则/任务对象。

普通复测直接复用用例文件，只创建新 run。定义确有变化才保存新版本。本轮环境、身份、对象、数据及授权重新核对，历史事实不是当前就绪证明。

- points：精确指定 pointId，保留必要条件、路径及已声明步骤依赖。准备动作不让未选点获得本轮结论。
- status：指定旧 run 的精确结果 revision/hash，按四态命中后重跑整条当前场景。旧运行未选点不当成缺评估，零命中不转全量。
- full：所选版本全部在期目标，包括未准备、待确认、暂缓及来源覆盖缺口。选择全量不证明全部执行。

select 固定范围，start --binding 冻结完整用例原件，以及审阅、当前条件、参数、执行/暂缓引用和父运行。run-binding.json 不重写用例定义。所选点恰好属于执行计划或明确暂缓；工具不自动赋状态，AI 如实登记有据四态。

新 run 显式保存父运行与主要比较基准：runDir、runId、baselineSha256、resultsRevision、resultsSha256。不按标题、时间或最近文件猜来源，不建项目运行注册表。移动目录时使用显式位置映射。

原问题用 problemChecks 引用旧 findingId，或旧 caseId/goalId/operationId 及可选 phenomenonId，记录 reproduced、not_observed、unclear、not_checked，以及本轮观察和缺口。旧问题未见但有新问题时分别留存。目标四态、原问题、可比性与修复归因独立，不能以一次通过认定每条问题或某个提交已修复。

context 分开提供规范与历史事实；compare 给出定义、计划、环境、身份、数据、授权和范围差异，AI 的可比性说明须有实际来源。首次报告纯净，后续按编号展示旧结果与原证据、本次结果和原问题检查。

历史证据保留原 run/证据 ID，不进当前证据目录和四态计数。auto 需要历史附件或下载原件时生成 bundle；缺失/损坏历史明确显示局限，不能改变本轮四态。旧资料保持原样，新版不自动迁移或兜底读取。
