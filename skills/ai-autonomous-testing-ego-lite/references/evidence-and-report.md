# 证据与报告

## 一个目标结果入口

串行 record 与并行 import 使用同形 record:{observations,assessments}，结果统一进入 entries。业务判断属于冻结 goals；前提、步骤和路径是必要语义，由观察的 coveredRefs 说明已观察哪些部分。计划步骤不是证据，不能由工具成功或父用例概况自动推导目标通过。

每条 assessment 明示 goalId、四态、rationale、observationIds、gaps；可选 diagnosis 单独表达根因确认程度。一个观察可支撑多个有关目标；不足以支撑另一个目标时不要扩大引用。AI 对原目标逐项判断，额外发现另外建立有来源目标，不能用探索填补原目标未测项。

final 按 goal 增量更新当前评估，attempt 仅留历史。entries 保留所有原始观察与评估，后续成功不抹掉首次异常。目标 clarificationQuestions 非空时禁止 verified/violation，后续澄清通过新基线 goal.followUpOf 关联，旧记录仍保留原口径。

## 必要事实与真实截图

在仓库外私有目录保留来源版本、授权、实际身份/初态/对象、必要路径和关键动作、观察及必要读回、首次异常和补测差异。具体时机与方法由 AI 选择，不要求每步独立 trace。

**关键 UI 结果及缺陷须有真实页面截图。** DOM、日志、回执和文字摘要补充截图，不能冒充截图。截图只证明可见内容，不单独证明完整业务流程或后台状态。不得用报告截图、占位图或事后重现场景冒充首次业务证据。

截图失败、访问受限或隐私限制时记录具体缺口和判断影响，由 AI 选择授权内补证、继续其他目标或保留无法判断。不通过其他通道绕过限制，不为了补报告擅自重跑业务。没有执行 UI 的未测试目标不补造图片。

evidence-add 保存普通文件副本并校验 hash/字节数；source、description 保留来源。capturedAt 仅在真实来源提供时填写，未知则省略。collectedAt/recordedAt 是登记时间，不是执行或采集时间。哈希一致只证明留存字节一致，不认证真实性或业务正确性。

### 用v8保存可供复核的事实

为相关操作提供可复用的 `record.contexts`：environment、identity、objects、initialState、authorization 分别用 `state:known/unknown/not_applicable`、summary 和 sources（来源类别、定位及 evidenceIds）表达。身份/对象变化时另建context；资料型目标不强迫填写不存在的UI上下文。不能根据冻结计划推断实际身份已核实。

观察可引用contextId，并用actions保存真正做过的关键操作、输入、读回和可选occurredAt；planRefs仅说明与计划的关系。一个动作不等于一个业务目标，也不要求逐鼠标事件录像。evidenceLinks说明每份证据支持什么事实、对应哪一步及其局限。首次异常先保留；后续补证、复测、整理另记来源，不覆盖首次现场。

对多个不同现象使用assessment.phenomena分别列实际事实和观察/证据引用；reproduction保存准备条件、对象现状、重复验证情况及限制。未知重复次数就写未知，不能从final条数推算复测次数。gapDetails说明缺什么、影响什么、后续需要什么；工具不据缺口类型自动更换四态。revisionReason/previousOperationId可说明同目标的评估修订。

finding只是带理由的观察主题关系，scope区分原范围与额外发现，reviewState说明是否审核。不能按标题相似自动归并为同根因，不能把违反目标数当独立bug数。额外发现不掩盖原目标未完成。

### 采集范围与正文

登记时metadata可说明scope、page、object、purpose、limitations及contextEvidenceIds。关键局部图不足以识别现场时，关联足够的上下文图或已记录上下文；否定结论须说明检查区域、加载和筛选状态。工具读取的像素尺寸只是客观信息，不自动判断截图充分性。

正文用metadata.contentState区分full、selected_fields、summary、truncated、excluded、failed、unknown，并记录redaction/omissionReason。源文件确实存在但未放入HTML，与现场根本没记录，是两种缺口。来源只有脱敏检查摘要就如实标summary；不能称完整HTTP响应。登记前完成获准的脱敏，工具不自动获得读取凭证或扩大采集范围的授权。

## 四态与记录完整性

报告默认按业务目标统计已验证、发现违反、无法判断、未测试。父场景展示分布，不把每个步骤、条件和路径算作业务目标。缺少 assessment 单列“缺少目标评估记录”，unassessed 属于记录完整性计数；不能从缺记录推出无法判断、未测试或已验证。

报告允许如实呈现部分记录，但缺评估时不能声称逐目标评估完成。已观察但尚无 final 的 attempt 可在历史中看到，不会自动取代当前评估。业务结果、证据文件完整性、缺图、执行资源状态、根因假设分别展示。

followUpOf 说明新目标延续哪个 run/case/goal 及原因。它帮助读者找到澄清或复测后的观察，不改变旧结果，也不自动证明问题解决；只有实际加载的关联记录才可展示其结论，未取得的后续内容仅列引用。

## 证据来源不得混写

登记前按每个实际文件分别确认 kind/source/description。`tool_receipt` 仅用于真正保留的工具请求或回执原文；AI 自写的资源摘要、授权理解、判断笔记和整理说明使用 `other`，source 明示 AI 编写及其所引用的原始来源。不要用一个固定元数据 helper 把所有文件都标成“接口原始输出”；description 中补一句“这是说明”不能抵消错误的 kind/source。

真实用户消息、规范文本和采集文件分别保留原来源。AI 摘要可帮助定位和解释，但不能被统计成新增独立原始证据，也不替代截图或接口读回。字节哈希只能核对留存内容，不认证来源标签准确。

发现历史来源标签误标时保留旧记录，另建有定位的更正说明，列出受影响 evidenceId、真实来源及对结论的影响；必要时用 retrospective context 生成新的注释版报告，不覆盖原运行、证据或报告，不为改元数据重跑业务。

## 资源不足与原目标

按[资源指南](resource-readiness.md)逐项对照原范围、资源依据及实际问答，说明受影响目标、截至时点、用户答复覆盖内容和剩余条件。分清未问、提问送达未知、已问待答、已提供待核验、核验失败或不适用、已替换及明确暂缓，不能统一写成“用户未提供资源”。自然语言补充同样保留来源，部分答复不结清整批问题，历史与当前分别表达。

观察与 gaps 保存事实依据，不能替代实际提问或证明提问及时。首次/恢复测试前的资源判断和之后新增依赖分别留存；收尾才补问时保留这一事实，不倒写成执行前已澄清。派生摘要引用同一依据或固定截至时点，问题回执只证明实际提交，不能证明答复已经解决目标所需条件。

未开展目标检查时记 not_tested 并解释原因；已有观察但不足以判断时记 inconclusive。资源缺口不直接判产品违反，也不隐藏已成立的违反。未集成的辅助笔记不属于 verify-report 核验范围；必要依据登记进证据链，派生摘要回读同一来源。

## 生成、核对与交付

默认交付独立 report.html、report.json、report.md，聊天摘要不替代文件。先按[工具箱指南](local-toolbox.md)核对实际根与版本。工具不可用则保留事实并说明交付阻塞，不能静默降级后宣称完成。

report 对冻结记录、引用及留存证据 hash/字节数核验后生成三个文件，任何目标文件存在都拒绝覆盖。HTML安全内嵌核验的PNG/JPEG/WebP以及可交付文本正文；主动内容只作文本展示。未知格式、缺失和解码失败分别提示，不生成替代图。正文超过内嵌预算时显示范围与缺口，完整交付可显式选择bundle附件模式；把整个交付目录交给获准读者，不能只发送HTML而漏掉附件。

人工主要阅读HTML：保留场景总览及场景→目标层级，在目标中核对预期、实际、上下文、操作及证据。右上角背景按钮提供八主题，颜色只是阅读偏好，不能改变目标、状态、证据原图。历史/未引用证据的可查看性不表示它自动支持当前评估。

生成后 verify-report 读回三种文件，与当前运行及证据核对。运行后续变化时旧报告不再匹配，应另存新报告而非覆盖。回执中的 browserOpen:not_checked 不代表实际打开；需要通过 Ego 实际打开并检查后才可声明已验证打开。最终提供三种文件绝对路径、未覆盖范围、证据与记录缺口。

清理/重置前保存关键事实、截图和可交付报告。实际清理按授权执行并独立读回，不因有报告就获得删除权限。

## 格式变化与事后整理

新版只接受统一 schemaVersion 8，不读取/转换旧 run。历史资料、报告、截图原样保留。需要基于旧来源重新整理时另建 v8 文件，明确为事后复核，标明来源与限制，不冒称执行前冻结，也不据旧摘要补造动作、时间或截图。新工具不能校验旧运行，不声称旧文件因新版构建而已验证。

真实材料均留仓库外。工具不自动脱敏或上传；避免登记密码、token、Cookie、签名下载地址及无关业务数据。资源笔记、经验查阅、文件校验不能代替测试证据。


观察中的 actions 保存当次已观察操作片段及证据用途；actionEvents 保存一次尝试的意图、发出、结果和核对/处置。两者用途不同，均进入同一账本，不自动互拷、不把片段当已执行的完整路径。未知或未发出事件不能靠附加动作文字变成通过依据。

证据用途的 evidenceLinks.actionId 只引用同一 observation.actions 中的片段 ID；动作尝试事件通过 observation.actionEventIds 关联，不混淆两个不同用途的标识。
