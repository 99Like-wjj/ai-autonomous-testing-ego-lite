# 跨宿主协作条件与交接

适用：准备使用子 Agent、换宿主运行、恢复已有分派，或核查并行执行声明时。本文固定信息、授权和证据要求；AI 自主决定拆分、具体调用、等待时机、补证和结束方式。它不提供宿主适配器，不启动 Agent，也不规定业务执行路线。

## 能力边界与已验证范围

项目负责冻结用例、名额与资源登记、独立交付、证据校验、复核入账和报告。宿主负责创建真实执行者、提供上下文及工具权限、消息、等待与生命周期。`reserve` 不创建子 Agent，`reconcile` 不停止后台调用，`tool-info` 不验证宿主兼容性。

以下官方资料于 2026-10-28 查阅，仅用于提示差异；实际工具名、字段、返回标识和限制以本次终端为准。没有在该宿主运行完整链路，不标“已兼容”。

| 宿主 | 选择协调方式时需要确认 | 本项目真实终端验证状态 |
| --- | --- | --- |
| Codex 本地 | 官方提供创建、指示、等待和收尾能力；子 Agent 权限继承父会话。提示词不是独立沙箱，桌面与 CLI 的实际工具面应分别确认。[官方资料](https://learn.chatgpt.com/docs/agent-configuration/subagents) | 当前修复只做本地 CLI 与数据事务验证，完整多 Agent 测试未验证 |
| Claude Code 本地 | 普通子 Agent 是新上下文，fork 有区别；工具受配置与运行方式影响。后台完成通知不保证它启动的命令已经退出。[官方资料](https://code.claude.com/docs/en/sub-agents) | 未验证本 Skill 的真实终端完整链路 |
| ZCode 本地（Z.ai） | general-purpose 与只读 Explore 用途不同；前台并行和后台回传不同。自定义白名单及项目指令注入的版本条件会影响工具和上下文。[官方资料](https://zcode.z.ai/cn/docs/subagents) | 未验证本 Skill 的真实终端完整链路 |
| 其他 / 远程 / 云端 / WSL | 另行确认文件与本机 Ego 是否可达；本机安装成功不证明远端能操作该浏览器 | 未验证，不作全面支持声明 |

Codex 可用 `$ai-autonomous-testing-ego-lite`；Claude Code 使用 `/ai-autonomous-testing-ego-lite`，通常安装于 `.claude/skills`；ZCode 支持自己的技能目录及外部复制/软链导入。应安装完整编译包并核对实际 ToolRoot，不能只复制源码 SKILL.md。包中的 `agents/openai.yaml` 是随清单保留的元数据，不是各宿主共用的子 Agent 定义。[Claude Skills](https://code.claude.com/docs/en/skills) [ZCode Skill](https://zcode.z.ai/cn/docs/skill)

目录链接入口修复限于 CLI 主模块识别，不放松运行/证据目录的防链接检查。使用默认 Node 调用链接安装目录后，以非空 `tool-info` 回执返回的真实 `toolRoot` 继续；特殊 Node 加载选项、各宿主的实际软链导入仍需另验。退出码 0 但没有预期回执或产物时应记录执行问题。

## 启动前应得到的事实

从本次可见工具、已知权限和已有回执确认以下条件；信息不足时只在既有授权范围内补充，不探测最大并发、不改全局设置、不另建模型服务：

- 可创建可执行测试的子 Agent，并能取得和继续识别本次实例；只读研究角色不等于能够操作 Ego、保存截图及封包。
- worker 可执行本机 Node/Ego、读取当前指南与冻结材料、保存并查看必要图片；工具名存在不等于调用获准。
- 协调者与 worker 对 ToolRoot、run 与交付文件有可访问的路径。仅给 worker 目录写权限仍不足以封包：还需读取工具包、run 的 manifest/baseline 和本分派 assignment.json。
- 能观察实例进度、接收结果、等待或中断，并知道如何核查它启动的命令/浏览器调用。没有这些能力时明确受影响环节，不把“任务已创建”报告为闭环完成。

如果用户只设置上限而非要求实际重叠，AI 可在现有授权内选择更小批次或串行，但交付应如实说明实际执行方式。若用户明确要求真实并行，串行不能满足该目标。宿主能力缺口与产品业务违反分别记录。

## 给 worker 的最小充分交接

交接可写进宿主任务消息，也可引用 worker 确实可读的文件；不要求新的固定数据格式。不默认继承父会话已读文件、已调用 Skill、内存变量或用户补充答复。

| 信息 | 必须明确的含义 |
| --- | --- |
| 原目标与事实 | 本次冻结 case、预期、来源、必要语义/依赖、已确认的资源与用户暂缓项；不能只传任务标题 |
| 授权与身份 | 环境、账号/租户/角色的核验依据，获准操作、禁止范围、共享数据与互斥资源；可访问不等于已授权 |
| 工具与路径 | 实际 ToolRoot、版本/revision/formatVersions、run 绝对路径及必要材料位置；Ego 脚本按安装指南使用绝对路径，不依赖 shell cwd/env 自动继承 |
| 分派身份 | run ID、基线 hash、case ID、assignment/attempt ID、专属目录及本分派 packetId 命名空间 |
| 浏览器范围 | 已确认的 numeric Space/Page 标识与所有权，或获准创建范围及回执交接方式；不凭名称认定身份隔离 |
| 交付与异常 | 新文件名保存截图和原始观察，交回 packet 路径、未完成项、实际 Space、在途调用；缺工具/上下文时交回缺口，不扩权或重做未知业务写入 |

worker 只写自己的分派目录，不修改共享 results/evidence/execution，不另派测试 worker。协调者合并必要问题并传回用户实际答复；恢复旧实例或复用空闲 worker 时，重新核对它收到的是当前 case 与权限。

## 宿主标识、等待与恢复

区分业务 case、分派 assignment、宿主执行者实例、该实例的一轮任务，以及它启动的命令/会话 handle。它们不是同一个标识。

真实执行时将宿主返回的实例标识记录为 `workerId`，并用现有 `note`/`evidenceFiles` 留存创建、交接、状态、等待或停止的必要回执；文件放在本 run 内，附分派关联。宿主没有提供的标识如实缺失，不用本地自编字符串冒充宿主身份。模型/推理配置已知时记录实际值，未知时不补造。

单个 worker 顺序执行多个 case 不能当成多个并行执行者。workerId、名额峰值和自行填写的执行区间都不是独立并发认证；只有实际观察到有来源的执行重叠才能说明真实并行，报告应保留证据范围。

超时先确认是等待超时、Agent 中断、命令仍在运行还是浏览器可能晚到生效。继续观察原 handle，未知业务写入先只读对账；不要把停止 Agent 当成所有副作用已经停止，也不因换实例/Space 就自动重放业务。`lost`/`stop_requested` 保留名额，确认无在途才登记暂停或终态。

宿主可通过通知返回，也可能提供等待或续接工具；按本次工具语义选择。包先返回但任务仍在途时，导入事实不等于可以回收资源。需要替换执行者时保留原实例与操作回执，使用新证据说明关联变化，不改旧历史。

## 收齐结果与收尾

协调者复核原目标、必要语义、实际对象/身份和关键截图，再显式 accept/revise。结果不完整可交付，但应分别说明任务终态、导入状态、逐目标结论、证据缺口和未完成项。不要只看“未完成分派为 0”或 `filesVerified:true`。

本地事务幂等只恢复记录，不授权重放业务。包 ID 冲突应按[并发指南](parallel-testing.md)保留原包并纠正交付；部分导入使用原请求对账；未测试和无法判断不能因别的任务成功而消失。

资源/文件范围只是协作约束。资源键必须覆盖实际共享对象，Space 不隔离账号或后端，同一系统用户的通用 shell 也不是每个 worker 的硬沙箱。记录越界偏差不意味着该动作获准；保留事实并停止越过原授权的后续动作。

保存必要证据和报告后，结合宿主任务、在途调用和 Ego 当前所有权决定收尾。按已有指南精确关闭本次可清理 Space 并独立读回，保留用户接管/错误现场；不关闭其他任务、清全局 Cookie 或改用户安装。

验证新宿主时，使用相同的目标/授权/证据标准，记录宿主版本与运行方式、Skill/Ego 版本及输入指纹。至少验证真实多执行者的创建、上下文/权限、实际调用重叠、独立结果与关键截图、部分失败/交付缺口、汇总和收尾；具体方法由 AI 选择。源码分析、模拟事务与真实终端结果分开陈述。
