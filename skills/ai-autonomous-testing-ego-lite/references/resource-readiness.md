# 测试资源充分性与主动澄清

理解目标并评估能否有效执行时阅读本指南；首次开始或恢复实际测试前、范围或资源出现实质变化时回看相关要求。这里固定资源判断、必要沟通及事实边界，不固定 AI 的推理顺序、页面路线或工具组合。

## 从目标推导条件

结合需求、原型、外部用例、项目资料及用户已有授权，为当前声明的整轮范围识别身份/角色、权限、环境/租户、数据/初态、外部依赖、隔离、观察及时间条件，并关联受影响目标。目标 ID 尚未形成时先关联需求条款，用例细化后补映射和遗漏。只分析相关维度，不要求每个项目填写相同清单，也不把示例中的账号数量或隔离项目变成通用前提。

区分“所需条件”“用户声明”“当前已核验事实”“尚未知”。写下某项前提不证明它已存在。先读取已提供内容，利用授权内可用的安全核验消除未知；实际登录成功不证明角色正确，配置名称不证明环境已部署，Space 不证明账号或后端隔离。已明确且能在原授权内安全准备的资源，可自主准备；不能为查证扩大权限或对共享数据试写。

初步理解范围后就沟通已知实质缺口，不等全部用例生成才开始问。只生成用例或明确转为离线准备时，可交付注明前提的草案，无需为了分析要求部署、登录或故障模拟环境，不创建虚假运行或结果。恢复实际测试时重新审视整轮条件，不能把能规划当作能执行。

## 整轮范围与执行边界

首次开始或恢复实际测试前，给用户一份简短、截至当前的资源判断：现有且适用的条件、已提供但待核验的条件、可在已有授权内安全准备的条件、需要补充或授权的缺口、用户明确暂缓或本轮时间内无法满足的条件，以及允许继续的目标。形式按复杂度选择；不要求统一表格、资源状态机或用户逐项审批。

完成这份判断表示已审视当前已知范围、完成必要沟通并划清执行边界，不表示所有资源齐备。独立、条件充分且获授权的目标可继续，依赖未决条件的动作保持暂停。开始其他目标不能成为已知缺口无限延后沟通的理由；执行中真正新发现的依赖仍需增量澄清。

故障模拟等条件需说明是否确有可控方式、隔离范围或专用身份，不能只写“可构造”。实际工作日、长期使用等时间要求须按需求识别，不以自建项目或短时模拟替代。提前沟通不保证资源一定可得，也不以任意分钟数规定提问是否及时。

## 实际提问与依赖范围

已有资料及授权内安全核验仍无法确认或补齐、且影响正确性、有效性或操作边界的实质缺口，要实际向用户提出可回应的补充问题，包含缺少什么、为什么需要、影响哪些目标及怎样补充。**仅写进用例前提、笔记、gaps 或 not_tested，不算已经询问。** 初期已知缺口在首次实际测试前沟通；后续发现的缺口及时说明，不能等到目标被跳过或最终报告才首次披露。

暂停依赖缺口的实际动作，仍可分析需求、准备标明前提的草案或继续独立且已获授权的目标。AI 判断实际依赖范围；不通过跳过必要步骤、换成高权限账号或降低预期来绕过。

宿主有适用问答工具时复用它，否则用普通对话。问题可合并或分批，第一批沟通也应让用户知道其余已知缺口及影响，不把“已问一个账号”表达成整轮就绪。已明确或可安全查证的信息不重复索取，不发与目标无关的泛化清单。同一已问且未变化的缺口不反复追问；新依赖或答复没有覆盖的必要条件仍需继续澄清。用户明确暂缓时保留影响，不逼问。

工具调用失败不算问题已送达；纠正调用前核对可得回执，防止重复发送已成功的问题。宿主提供受理回执时保留回执；普通对话保留实际消息位置。没有可用消息 ID 时不补造，送达仍无法核实时如实说明，不把未知当作已问。

用户答复只解决明确覆盖的条件。身份显示的解释不解决操作范围；另一个账号不自动具备所需角色、成员关系或来源权限；AI 自定策略不构成用户授权。取消、空提交、工具失败、无人回复不能当作默认答案、资源就绪或同意。必要条件未解决时，依赖动作保持暂停；其他工作按其真实前提判断。

不在普通聊天、用例、记录或报告中索取密码、token、cookie、storageState、验证码或可兑换登录链接。可以询问账号别名、角色和可用登录方式，让用户自行在 Ego 完成身份登录。

初期识别删除、撤权、通知、外部连接或故障模拟所需条件及影响。动作前仍核对具体对象、影响范围和已有授权；充分时不重复审批，超出时再提问。允许自建项目不自动授权任意删除、通知或外联；尚无安全模拟能力时不在共享环境制造故障。

合成表达示例（仅在这些信息确实缺失时，不规定账号数量或业务路线）：

> 当前只核实了高权限身份，无法验证普通成员只能读取的目标。请提供适用身份的登录方式或自行在 Ego 登录，并确认其在目标对象中的角色。已授权且不依赖该身份的检查可以继续。

如果答复只是“页面姓名是缓存问题”，只解决身份显示疑问；如果提供的是无项目权限身份，可以支持非成员目标，不能直接结清普通成员或来源权限目标。

## 补充、恢复与冻结

收到回答后先对照它实际覆盖的条件，未答部分保留未决，再核实相关身份、权限、环境、对象及初态；“已提供”不等于“已核验”。自然语言补充与乱序答复也按明确含义和来源承接，关联不明时不猜测。补到普通成员身份后仍需审视非成员、团队或来源权限差异，账号数量不能替代适用性判断。

资源变更或暂停恢复时回读同一资源依据和问答，更新受影响目标、仍待答事项及允许继续范围；按风险复查可能已变化的事实，无须每次重读全部资料。网络恢复、登录成功或空间接管只解决各自条件，不能顺带结清其他缺口。初期已识别但尚未沟通的事项，在恢复实际测试前补做沟通。

满足原冻结条件的资源补充，可在原 run 追加观察，保留受阻事实，无须仅因补资源修改验收字段。若变更冻结的具体角色、项目、对象、输入或其他必要语义，则保留变化依据，准备修订用例并重新冻结；不能借补资源悄悄改基线。

恢复前核对在途调用和可能已经发生的副作用。数据事务可依原操作 ID 重取回执，不代表允许自动重放页面写操作；事实不明时先只读对账，详见[判断与归因](judgment-and-diagnosis.md)。

## 记录与协作

简单场景复用对话和现有运行记录。多轮恢复或跨 worker 汇总确有需要时，可在仓库外的私有工作区维护简短 `resource-notes.md`。为同一资源事实选定一个可追溯的依据位置，复用实际问答、现有结果或该笔记，不在准备说明、进度摘要和报告中各自维护一份当前事实。保留足以说明目标需要什么、当前事实及来源、是否实际问过和消息位置、答复解决什么、仍缺什么及继续／暂停／恢复依据的简短记录；位置和形式由 AI 按复杂度选择，不新增统一表格或状态机。

事实变化按实际来源与时点追加，旧观察保留为当时事实。分清已提供待核验、核验失败、不适用、已替换待核验、已问待答和明确暂缓；不以一个 ready 布尔值混合存在、核验和授权。用户已提供资源后不能继续把当前缺口写成“未提供”，部分答复也不结清同批其他问题。记录只保留必要别名和条件，不保存秘密。

更新准备说明、进度或报告前，回读同一依据位置；派生摘要引用它或注明截至时点，避免复制旧句子后漏改另一处。以“执行时资源未提供；随后收到但尚未核验”表达变化，不倒改历史，也不把历史句子当作当前状态。实际执行已有 run 时，必要问答可沿用 `evidence-add` 留存脱敏文本/JSON 副本并关联现有结果或目标评估；纯准备资料保留在私有工作区，不为登记证据创建假运行。来源时间未知时不补造。工具校验副本和引用，资源是否适用仍由 AI 判断。

需要多轮表达示例时，可读 ToolRoot 下的 `examples/resource-review.example.md`；源码位置为仓库的同名路径。它提供可选表达，不是实际问答、固定清单或执行脚本。具体项目事实不写入通用经验指南。

三类问题通过 v7 目标契约表达，字段只是记录方式，不能替代实际提问：

| 问题 | 现有契约与处理 |
| --- | --- |
| 验收歧义：正确行为应是什么？ | 目标的 `clarificationQuestions` 仅承载该目标验收未决问题，非空时禁止该目标 final/attempt 的 verified/violation；澄清后修订并重新冻结，详见[用例编写](case-authoring.md)。 |
| 资源可用性：账号、权限、环境、数据等是否存在且适用？ | `criticalConditions` 表达所需前提，实际缺口、核验事实和问题写入 `observations/rationale/gaps`，必要时关联证据；资源缺失不自动改变验收。 |
| 操作授权：是否允许对该对象执行该动作？ | 查明用户已有授权，只暂停不具备授权的动作；不能用账号可操作、测试用途或空答补齐授权。 |

同一事项可能包含多类未知，分别说明。产品权限用词需按需求中的含义理解，不能误解为宿主权限或修改代码的授权。

协调者合并多个 worker 的相同问题，同时保留各目标不同的条件；worker 暂停依赖动作、交回事实和未决目标，只写自己目录，不并发覆盖公共笔记或结果。暂停/续接如实记录在途状态。资源齐备和并发安全分开判断，互斥键仍按[并发指南](parallel-testing.md)使用。

复用现有 `record`、`packet-seal/execution import` 和证据工具保存事实。`progress` 提供当前目标状态和记录缺口，`check` 按需读取完整记录；目标的冻结验收疑问不代表所有资源缺口。是否合并问题、补测或继续仍由 AI 决定。

## 结论与交付

已知外部障碍阻止目标检查时显式记 `not_tested` 并说明原因；已观察但身份、规则或证据不足时记 `inconclusive`。目标只使用已验证、发现违反、无法判断、未测试四态，缺少评估是入账缺口，不能由工具自动推断未执行。已核验一个前提不代表整个目标通过；不把资源不足直接判产品缺陷。

反过来，身份与明确业务规则已核实且有效证据显示低权限完成了禁止操作，可以报告违反，不能用资源问题掩盖。额外发现与原用例结论分开。

串行 `record` 直接提交 observations 与 assessments；并行封包使用同一结果契约，经协调者复核导入统一 entries。不为目标评估或提问强制创建 Space、分派或子代理。

结束或暂停时逐项对照原范围、资源依据和实际问答，分清尚未沟通、已问待答、已提供但失败/不适用、仍未知及用户明确暂缓。若发现漏问，补做必要沟通并保留此前遗漏，不能倒写成执行前已澄清。已问待答、明确暂缓或仍无法核实时可以如实交付部分结果，原目标仍保留；沉默不是同意，不把全部未完成都归咎用户或工具。

报告列出受影响目标、实际问答依据、已知事实、未测试/无法判断范围、剩余问题和历史。正式依据进入现有结果/评估/证据链；辅助笔记未集成时，不能声称 `verify-report` 已校验它。尚未执行时交付草案和问题即可；已开始运行后按[证据与报告](evidence-and-report.md)交付三格式报告。未执行 UI 不造截图，关键 UI 结论仍须真实截图。

## 可测试性与数据关系

有账号不等于具备目标角色，有对象不等于满足历史、归属或关联状态。浏览器上下文隔离不保证后端数据隔离；即使串行也可能遗留前次副作用。识别结果可观察性：现有 UI、文件或已授权工具能证明哪一层，不能凭计划假定数据库或接口工具已可用。未知资源仍按本指南实际澄清，不借经验换掉必要条件。
