# 证据与报告

## 默认交付与运行记录

除非用户明确指定其他格式，执行测试后交付可独立离线打开的 `report.html`、结构化 `report.json` 和 `report.md`。聊天摘要、计划或文件生成回执不能代替交付。先按[本地工具箱指南](local-toolbox.md)确认实际加载的 Skill、工具绝对根目录、版本、revision 与安装文件完整性；格式文档在已确认工具根的 `docs/asset-formats.md`。缺少工具时可继续保留事实，但明确交付阻塞，不能静默降级为 Markdown 并宣称完成。

测试过程中在仓库外保留以下事实，具体组织方式、观察时机和操作路径由 AI 自主决定：

- 用户目标、来源版本、验收预期、授权边界和源用例；执行前已有的冻结记录与之后新增的探索分开。
- 与目标相关的实际身份/环境/前提、关键输入、实际经过的路径与动作、观察结果和必要的持久化读取。计划步骤不是执行事实，不要求每步有 expected 或单独 trace。
- 每个目标的最终状态、判断理由、归因、未覆盖与待确认项；明确区分已验证、发现违反、无法判断和未测试，工具状态中的 blocked 也要解释原因。
- 首次失败、动作回执、结果未知的副作用、补测及其前提差异。不能因后续成功覆盖历史，也不能盲目重试未知副作用。
- 真实证据文件、关联目标、来源和用途。来源明确提供时间才写 `capturedAt`；未知时省略。工具的 `collectedAt` / `recordedAt` 是本地登记时间，不是业务执行或采集时间。

## 关键截图是必要证据

**关键 UI 结果及缺陷必须留存足以支持结论的真实页面截图**，使用本机 Ego 官方截图能力；DOM、页面快照、日志和观察摘要用于补充，不能替代截图。AI 根据判断需要决定关键节点和截图数量，不要求每次点击或每个步骤截图。状态变更需要保留能支撑前后差异及必要持久化结果的事实；截图本身也不能证明完整业务流程。

截图失败或访问受限时保存具体错误及影响；隐私限制应先考虑获准的取证范围，不能为了截图泄露无关数据，也不能直接把“担心隐私”当作证据齐全。由 AI 决定是否在授权内继续取证、继续其他目标或报告受阻。不得用其他通道绕过访问限制，不为补报告擅自重跑业务。

缺图必须在报告中显式标注，并复核该目标的结论是否仍有足够依据。依赖截图却无法复核的目标为无法判断；工具不因缺图自动判产品失败，也不把非截图摘要数量包装成独立证据数量。禁止假截图、占位图、把报告截图冒充业务页面证据，或事后重现后宣称是首次失败现场。

## 保留业务语义与历史

用例的 `basis`、条件、整体 `expected`、必经路径、步骤和顺序策略来自源基线。方法可调整，目标与必要语义不省略。步骤 `expected` 可省略，不产生隐含通过结论。

冻结 `clarificationQuestions` 非空时，最终结果和每一条历史尝试均不得 `pass` / `fail`。澄清后保留旧记录并创建修订基线，不能清除旧问题或补造预期绕过限制。

`mode: final` 更新当前结果；`mode: attempt` 追加历史，不改变当前结果。被替换的 final 留作历史快照。`not_run` 可能已有尝试；没有 attempt 仅表示尚无尝试入账，不能据此断言从未执行。原用例和新增发现分别展示，不用额外探索掩盖未测项。

## 生成、核对和交付

`report` 核验运行结构、证据关联、留存文件 hash / 字节数，再生成三个文件；目标文件已存在则拒绝覆盖。只内嵌真实登记且校验通过的 PNG/JPEG/WebP，未知格式或解码失败明确提示。缺图、首次失败、历史尝试、未覆盖和不确定性如实呈现。哈希一致不证明内容真实或业务判断正确。

生成后用 `verify-report --run-dir ABS_RUN --report-dir ABS_REPORT_DIR` 读回三个文件，核对它们与当前运行、已登记证据和整理来源一致；回执给出实际路径、字节数、SHA-256 和 `browserOpen: not_checked`。若运行后续变化，旧报告核对会拒绝，应另存新报告，不覆盖旧文件。

文件存在与实际打开分开说明。仅在浏览器实际打开并检查后才称已验证打开；无法访问时给出具体错误和未验证内容，不静默换通道。最终回复提供 HTML、JSON、Markdown 的绝对路径、证据缺口和需要用户验收的项目。清理或重置前先保存关键证据及可交付报告。

## 事后补报告

先核对原始来源能支持什么。可从已有记录补齐格式，但不能补造采集时间、执行步骤、截图、首次失败或业务结论。需要新建 run 才能整理旧资料时，必须明确这是事后整理，工具此时保存的 baseline 不能冒充执行前冻结。原始基线、报告、日志和证据不覆盖、不删除。

对有效 v3 run，可使用 `report --output-dir ABS_EXISTING_NEW_DIR --context ABS_CONTEXT_JSON` 另存三种报告。context 遵循工具根 `schemas/report-context.schema.json`，包含事后整理说明、限制、已存在来源文件的路径与 SHA-256、补充用例 ID，以及 AI 对每个目标提供的本次复核状态和理由。工具只验证格式、覆盖与文件字节，不从缺图自动推导复核结论。原记录状态原样保留，本次复核单独展示。来源文件校验也不认证其内容。

## 隐私

真实需求、站点、账户、截图、快照、日志、报告和 context 保存在仓库外私有目录。登记不会自动脱敏；不要保存凭据或签名下载 URL，也不要自动上传原始报告。私有 Git、哈希、ignore 与启发式扫描不保证无泄露。
