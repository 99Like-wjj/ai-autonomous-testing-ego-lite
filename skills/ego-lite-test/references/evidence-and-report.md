# 证据与报告

## 记录足以复核的事实

在私有工作区保留任务约定、需求来源及其版本、计划检查列表、执行时间与环境版本。每项检查记录实际前提、对应步骤 ID、实际步骤顺序、动作、观察、判断依据、状态与归因；证据以稳定标识或私有相对路径关联，不在报告里粘贴凭据或签名下载 URL。

对关键动作留行动前状态、动作后结果及必要的持久化观察。截图与语义快照互补：单张截图不能证明整个流程，DOM 可读也不代表视觉或权限正确。只有实际采集到的证据才能引用，缺失、采集错误、脱敏导致的不可判定区域均应说明。文件哈希可以帮助识别文件变化，但不能证明证据内容真实或结论正确。

若使用可选助手，先获得用户提供或确认的工具包仓库绝对根目录，再从该根目录读取 docs/asset-formats.md 及当前助手校验器；不可从安装 Skill 目录向上寻找这些文件。本参考不另建一套字段。若仓库不可用，继续使用现有 Ego 与私有 Markdown 记录，不伪造助手输出。证据索引必须指向本次实际存在的证据文件，不能凭空填写引用、哈希或采集时间。严格遵循仓库当前助手的实际接口；这些命令只初始化、校验和渲染本地文件，不能使状态自动变成“已测试”。没有执行 Ego 时所有检查保持 not_run，绝不填入模拟通过冒充实测。结果的 Markdown 手工记录同样有效；用例格式遵循 [用例接收与生成](case-authoring.md)。

用例统一使用 v2 格式；结果可用助手 JSON 或私有 Markdown。建议记录下列语义：

- run：标识、时间、目标环境、版本指纹、任务约定来源与范围。
- case：稳定 id、basis、不可变条件与 expected、requiredPath、stepOrder、steps（逐步动作与预期）。
- observation：实际 actor/tenant/role 的核验方式与结果、数据初态、动作与后果、证据引用。
- judgment：pass/fail/inconclusive/blocked/not_run、原因、事实与推断、未解问题。
- history：首次异常、独立补测记录、前提变化；不覆盖历史失败。

本仓库不附带评分裁判、固定测试 DAG 或 Agent 能力基准。用户项目 cases 是本次测试输入；helpers 的单元测试只能证明相应文件逻辑，不证明浏览器执行可靠或产品无缺陷。

## 最终报告

先回答目标覆盖情况，再给发现与限制。新功能测试应展示源需求段落 → 验收目标 → 检查 → 证据/状态的映射，分开列初始计划与后加探索，并交代部署前提。覆盖口径至少包含所有约定目标，以及 pass、fail、inconclusive、blocked、not_run 的数量与逐项去向。一个目标有多个检查时保留映射，不能用通过的探索项掩盖未完成的必需目标。

不要仅以 pass/(pass+fail) 给总体通过率，丢弃阻塞和未知项。若报告比率，说明分子、分母、依据类别与未覆盖数量。将“明确需求结论”和“解释/探索观察”分别展示。

每个重要发现应让读者看到：

1. 依据及分类、影响范围。
2. 实际前置条件和最少复现路径（仅已观察事实）。
3. 预期与实际，关键证据及时间。
4. 当前归因与替代解释，是否需要人工确认。
5. 首次失败与补测差异，下一步最小验证建议。

不得把未经授权的排查建议描述为已执行，也不得承诺 Windows/Ego 已兼容，除非本次确实有相应环境的执行记录。

## 隐私与未来公开

仓库分发物仅放原创 Skill、工具和虚构 .example 示例。真实项目说明、案例、站点地址、账户、截图、快照、日志和报告置于仓库之外的本机私有目录；不要把工作材料当示例提交。私有 GitHub 也不是秘密保管库，未来公开前仍需检查全部历史与发布附件。

不要记录原始密码、API key、认证 Cookie、Authorization、session/refresh token、签名 URL 或恢复码；不将浏览器状态打包。登录由既有安全流程完成，记录“已核验角色”而非登录秘密。优先不采集敏感字段，而不是先完整落盘再删。

截图可能暴露姓名、头像、邮件、业务数据；日志可能包含 request/response body、查询参数或文件路径。保存前控制范围和遮蔽，报告标注脱敏影响。脱敏扫描、gitignore 和自动检查都只能辅助，不能保证无泄露；发布前人工审查文件、历史、附件和生成产物。发现泄露时暂停发布，删除当前文件不能撤回历史泄露，需要通知持有人并走相应撤销/轮换流程。
