# 测试资源充分性与主动澄清

理解目标并评估能否有效执行时阅读本指南；执行中出现新依赖、资源变化或恢复受阻工作时按需重看。这里固定事实、授权和结果表达，不固定 AI 的推理顺序、页面路线或工具组合。

## 从目标推导条件

结合需求、原型、外部用例、项目资料及用户已有授权，判断当前目标需要什么身份/角色、权限、环境/租户、数据/初态、隔离和观察手段。只分析相关维度，不要求每个项目填写相同清单，也不把示例中的两账号或隔离项目变成通用前提。

区分“所需条件”“用户声明”“当前已核验事实”“尚未知”。写下某项前提不证明它已存在。先读取已提供内容，利用授权内可用的安全核验消除未知；实际登录成功不证明角色正确，配置名称不证明环境已部署，Space 不证明账号或后端隔离。已明确且能在原授权内安全准备的资源，可自主准备；不能为查证扩大权限或对共享数据试写。

只生成用例时可交付注明前提的草案，无需为了分析要求部署或登录。执行依赖动作之前，实质缺口必须处理，不能把能规划当作能执行。

## 实际提问与依赖范围

已有资料及授权内安全核验仍无法确认或补齐、且影响正确性、有效性或操作边界的实质缺口，要实际向用户提出可回应的补充问题，包含缺少什么、为什么需要、影响哪些目标及怎样补充。**仅写进用例前提、笔记、remainingQuestions 或 blocked，不算已经询问。** 决定因缺口暂停、跳过或结束某目标时及时提问，不能继续其他工作后到最终报告才首次披露。

暂停依赖缺口的实际动作，仍可分析需求、准备标明前提的草案或继续独立且已获授权的目标。AI 判断实际依赖范围；不通过跳过必要步骤、换成高权限账号或降低预期来绕过。

宿主有适用问答工具时复用它，否则用普通对话。问题可以合并，已明确或可安全查证的信息不重复索取，不发与目标无关的泛化清单。同一已问且未变化的缺口不反复追问；新依赖或答复没有覆盖的必要条件仍需继续澄清。用户明确暂缓时保留影响，不逼问。

用户答复只解决明确覆盖的条件。身份显示的解释不解决操作范围；另一个账号不自动具备所需角色、成员关系或来源权限；AI 自定策略不构成用户授权。取消、空提交、工具失败、无人回复不能当作默认答案、资源就绪或同意。必要条件未解决时，依赖动作保持暂停；其他工作按其真实前提判断。

不在普通聊天、用例、记录或报告中索取密码、token、cookie、storageState、验证码或可兑换登录链接。可以询问账号别名、角色和可用登录方式，让用户自行在 Ego 完成身份登录。

合成表达示例（仅在这些信息确实缺失时，不规定账号数量或业务路线）：

> 当前只核实了高权限身份，无法验证普通成员只能读取的目标。请提供适用身份的登录方式或自行在 Ego 登录，并确认其在目标对象中的角色。已授权且不依赖该身份的检查可以继续。

如果答复只是“页面姓名是缓存问题”，只解决身份显示疑问；如果提供的是无项目权限身份，可以支持非成员目标，不能直接结清普通成员或来源权限目标。

## 补充、恢复与冻结

收到回答后先对照它实际覆盖的条件，未答部分保留未决，再核实相关身份、权限、环境、对象及初态；“已提供”不等于“已核验”。事实有时效，恢复时按风险复查，执行中遇到新依赖同样处理。

满足原冻结条件的资源补充，可在原 run 追加观察，保留受阻事实，无须仅因补资源修改验收字段。若变更冻结的具体角色、项目、对象、输入或其他必要语义，则保留变化依据，准备修订用例并重新冻结；不能借补资源悄悄改基线。

恢复前核对在途调用和可能已经发生的副作用。数据事务可依原操作 ID 重取回执，不代表允许自动重放页面写操作；事实不明时先只读对账，详见[判断与归因](judgment-and-diagnosis.md)。

## 记录与协作

简单场景复用对话和现有运行记录。多轮恢复或跨 worker 汇总确有需要时，可在仓库外的私有工作区维护简短 `resource-notes.md`。为同一资源事实选定一个可追溯的依据位置，复用实际问答、现有结果或该笔记，不在准备说明、进度摘要和报告中各自维护一份当前事实。保留足以说明目标需要什么、当前事实及来源、是否实际问过和消息位置、答复解决什么、仍缺什么及继续／暂停／恢复依据的简短记录；位置和形式由 AI 按复杂度选择，不新增统一表格或状态机。

事实变化按实际来源与时点追加，旧观察保留为当时事实。用户已提供某资源后，即使尚未登录、未核验或不适用，也不能继续把当前缺口写成“未提供”；这些差异分别说明，不以一个 ready 布尔值混合存在、核验和授权。收到部分答复时，只更新其覆盖的事实，其他条件保持未决，不保存秘密。

更新准备说明、进度或报告前，回读同一依据位置；派生摘要引用它或注明截至时点，避免复制旧句子后漏改另一处。以“执行时资源未提供；随后收到但尚未核验”表达变化，不倒改历史，也不把历史句子当作当前状态。必要问答可沿用 `evidence-add` 留存普通文本/JSON 副本并关联现有结果或目标评估；来源时间未知时不补造。工具校验副本和引用，资源是否适用仍由 AI 判断。

三类问题沿用现有契约，字段只是记录方式，不能替代实际提问：

| 问题 | 现有契约与处理 |
| --- | --- |
| 验收歧义：正确行为应是什么？ | `clarificationQuestions` 仅承载影响本用例整体验收的未决问题，非空时仍禁止用例及 attempts 的 pass/fail；澄清后修订并重新冻结，详见[用例编写](case-authoring.md)。 |
| 资源可用性：账号、权限、环境、数据等是否存在且适用？ | `criticalConditions` 表达所需前提，实际缺口、核验事实和问题写入 `observed/rationale/remainingQuestions`，必要时关联证据；资源缺失不自动改变验收。 |
| 操作授权：是否允许对该对象执行该动作？ | 查明用户已有授权，只暂停不具备授权的动作；不能用账号可操作、测试用途或空答补齐授权。 |

同一事项可能包含多类未知，分别说明。产品权限用词需按需求中的含义理解，不能误解为宿主权限或修改代码的授权。

协调者合并多个 worker 的相同问题，同时保留各目标不同的条件；worker 暂停依赖动作、交回事实和未决目标，只写自己目录，不并发覆盖公共笔记或结果。暂停/续接如实记录在途状态。资源齐备和并发安全分开判断，互斥键仍按[并发指南](parallel-testing.md)使用。

复用现有 `record`、`packet-seal/execution import` 和证据工具保存事实。`progress` 提供状态与用例 ID，`check` 按需读取完整记录；`pendingClarification` 只统计冻结验收疑问，不是所有资源缺口。是否合并问题、补测或继续仍由 AI 决定。

## 结论与交付

已知外部障碍可记用例 `blocked`；已尝试但身份、规则或观察不足可记 `inconclusive`。逐目标仍只使用已验证、发现违反、无法判断、未测试：没有开展目标检查记未测试，已有观察仍无法支持结论记无法判断。已核验一个前提不代表整个目标通过；不把资源不足直接判产品缺陷。

反过来，身份与明确业务规则已核实且有效证据显示低权限完成了禁止操作，可以报告违反，不能用资源问题掩盖。额外发现与原用例结论分开。

需要 v4 逐目标展示时使用既有完整目标评估交付；串行可由当前 AI 封包并复核导入，无须子代理。只写旧 `record` 不会自动产生显式目标评估。不为提问强制创建 Space 或分派。

收尾前核对因缺资源未覆盖的原目标是否实际问过，答复覆盖了什么、哪些仍待回复或用户明确暂缓。未问时先完成必要沟通；已问待答、明确暂缓或仍无法核实时，可以如实交付部分结果，但原目标未完成，沉默不是同意。

报告列出受影响目标、实际问答依据、已知事实、未测试/无法判断范围、剩余问题和历史。正式依据进入现有结果/评估/证据链；辅助笔记未集成时，不能声称 `verify-report` 已校验它。尚未执行时交付草案和问题即可；已开始运行后按[证据与报告](evidence-and-report.md)交付三格式报告。未执行 UI 不造截图，关键 UI 结论仍须真实截图。
