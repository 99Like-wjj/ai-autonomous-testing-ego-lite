# 整轮资源澄清：合成多轮示例

这是表达与承接示例，不是真实运行、问答回执或测试结论。角色、目标和轮次均为虚构；不规定实际项目必须采用这些资源、问句、次序或表格。运行时以当前需求和真实消息、核验结果为依据，不复制本例状态。

## 题设与整轮范围

合成需求要求验证管理员维护、普通成员只读、非团队入口拒绝、外部来源读取和测试通知；另有获准隔离项目的删除检查、可控故障观察及五实际工作日试用。初始只提供账号 A 及一个可用合成项目，题设已给出 A 的管理员核验记录和在该项目读取、维护合成数据的授权。其他身份、外部来源、通知对象、删除范围、故障隔离能力及时间材料仍未知。

AI 初步理解后可这样沟通，不必等完整用例文件生成：

> 当前条件支持已有合成项目的管理员检查。成员/非团队权限、外部来源与通知、隔离删除、故障观察及五工作日试用仍有资源或授权条件需要确认。先请补充适用的成员和非团队身份及登录方式；凭据请在授权页面自行输入。其余已知缺口也会在首次实际测试前沟通，相关动作保持暂停。

如采用上述分批表达，首次实际测试前还要实际提出尚未覆盖的问题，例如：

> 外部读取需要可用测试来源及访问范围，通知需要明确接收对象和发送范围；是否有可用资料及授权？删除检查需要获授权的隔离项目，故障检查需要可控且不影响共享环境的模拟方式，是否具备这些条件或允许准备相应隔离资源？五实际工作日试用是否已有可核验材料，还是本轮暂不具备必要时间条件？

第一批披露其余已知缺口及影响，后续问题可按认知负担拆分；不能因为账号问题已成功提交就说整轮资源就绪。问题已沟通但尚待答复时，独立且获授权的目标可继续。无适用问答工具时使用普通对话，保留可定位的真实消息。受理失败的调用不记为已问，受理结果未知时先核对可得回执，避免重复发送。

## 多轮变化与承接

下表的轮次只是阅读编号，不能用作真实消息 ID；“页面核验”等均是题设提供的合成事实，不代表本例执行过浏览器。

| 合成轮次与新信息 | 应保留的当前事实 | 对执行范围的影响 |
| --- | --- | --- |
| 用户提供 B 作普通成员，仅回答身份问题；页面随后核实 B 的项目成员关系；用户确认 A、B 均属同一团队 | 成员条件已补充并核验；非团队条件仍缺；其他未答问题仍待答 | 可继续已授权的管理员和成员目标；不能用两账号数量结清非团队目标 |
| 网络暂不可用，用户要求先准备离线资产 | 业务执行暂停；已有账号、核验和待答问题保留 | 交付带前提草案，不为设计强索登录或创建假运行 |
| 用户说环境已恢复 | 只确认环境恢复；按风险回查身份、对象初态，并回读整轮问答 | 恢复实际测试前说明可以继续及仍待补的范围，必要沟通不推迟到收尾 |
| 用户在普通消息中允许另建隔离项目；同批外部来源和通知问题未回答 | 自建项目授权已补充；不扩张为外部读取、通知或任意删除授权 | 可在授权内准备隔离项目；其他依赖动作继续暂停 |
| 用户给非团队账号 C，但登录核验失败，随后替换为 D | C 已提供但核验失败；D 已提供待核验，保留替换来源 | 待核实 D 的身份、团队及对象适用性后，再决定非团队目标能否执行 |
| 用户明确外部来源本轮不测，暂无隔离故障方式 | 外部来源明确暂缓；故障目标缺少可控条件 | 保留原目标及原因，不催促、不删除目标，不在共享环境制造故障 |
| 用户说五工作日试用也由 AI 自建项目完成 | 自建只解决项目准备，不提供实际时间证据 | 说明本轮无法完成真实时长要求，不能用短时模拟报通过 |
| 删除检查到达具体隔离对象 | 核对对象归属、关联数据、实际影响和已有授权；授权不足才询问 | 已有充分授权不重复审批；仅有自建授权时不能直接删除 |

回复乱序时仍按其明确覆盖内容关联，无法确定对应问题时保留未决或澄清，不从回复位置猜测授权。与旧问题相同且条件未变时不重复追问。

## 恢复前摘要示例

假定题设进一步给出环境、A/B 身份及合成项目初态已重新核实，而 D 尚未核验：

> 截至本次恢复，管理员和成员条件已核实，可继续其授权范围内的检查。D 已提供但非团队适用性待核验；通知对象及发送范围已问待答；外部来源由用户明确暂缓；故障观察缺少可控隔离方式；五工作日试用缺真实时间证据。隔离项目自建授权不含最终删除，具体对象确定后核对影响并补充所需授权。上述缺口不阻塞独立的管理员和成员检查。

这一摘要不宣称业务目标已经通过，也不替代其中尚待完成的实际提问或核验。

## 单一事实依据与收尾

简单任务直接引用真实对话和运行记录即可。多轮任务可在私有项目目录按来源追加简短资源笔记，每项能回答：

- 需要什么条件、影响哪些需求条款或目标；
- 来源和截至时点是什么，用户声明与已核验事实有何区别；
- 问题是否实际提交、答复覆盖什么、仍缺什么；
- 可以继续或需要暂停什么，依据是什么。

笔记可以是短段落，不必复制本例表格；不保存凭据，不写回通用经验。准备说明、进度及报告引用同一依据或固定截至时点。已有实际 run 时可用 evidence-add 登记必要脱敏问答副本；纯准备阶段不为登记而造 run。

收尾逐个原目标按实际证据给已验证、发现违反、无法判断或未测试；不能从上述资源表直接推导业务结果。未开展检查的目标说明实际资源原因，已开展但证据不足的目标说明无法判断范围。保留首次失败和后续补充，不把“已提供但失败”“已问待答”或“用户明确暂缓”统一改写为“用户未提供”。收尾补问也应如实标明，不倒改成执行前已沟通。
