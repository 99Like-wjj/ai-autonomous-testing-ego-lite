# 虚构项目：共享书签目录

本目录仅演示如何用自然语言提供测试材料，不对应任何真实站点、组织或用户。地址 https://catalog.example 为保留示例地址，不是可访问的测试服务。这里没有运行结果或能力验收数据集。

## 本轮目标

验证测试目录中书签标题的必填约束，以及读者角色在条目详情不可编辑的要求。目标环境由实际使用者在其私有资料中明确；本示例不授权对任意站点执行操作。

## 明确要求

- R-01：通过“新建书签”表单提交空标题时，显示必填提示，且不创建书签。
- R-02：读者角色通过列表打开已有条目后，详情不提供可用的编辑入口。

要求版本：synthetic-v1。除上述规则外，不假定标题长度、排序方式、权限 API 行为或自动保存语义。

## 不可变条件

- R-01 的标题必须为空，测试角色为编辑者；不能为了提交成功补上标题。
- R-02 的真实角色必须为读者，已有条目必须属于本次授权测试数据；必须通过列表进入详情，不能以直接 URL 绕过路径要求。
- 关键动作前观察真实角色、目录和数据状态，不能只读取配置。

## 范围与授权待填写

示例中没有真实账号、凭据或写入授权。实际使用时，在仓库外的私有项目文件中明确测试环境、可用角色、fixture、允许的写入与清理范围，以及预算和停止条件。缺少必要授权时只准备计划。

不同角色是否有独立 profile、是否共享后端数据，需要实际核验。不要在这个公开示例中补充真实环境或个人信息。
