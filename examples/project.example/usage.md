# 如何提供私有项目资料

把项目说明写在仓库外的本机私有目录，提供自然语言需求及来源、目标环境、授权边界、关键初始状态、角色和必须路径即可。可以沿用 brief.md 的结构，也可以直接使用已有说明书；不要求用户编写业务脚本、固定 DAG 或完整 cases 文件；也可以直接提交已编写的 schemaVersion 3 用例。两种来源都可用于新功能验证与回归。

可向能操作本机 Ego 的 AI 会话提出：

> 使用 ego-lite-test 测试我指定的测试环境。先读取我提供的项目说明，接收外部 schemaVersion 3 用例，或从需求生成同格式的用例，包含关键前提、stepOrder、steps（id/action，expected 可选）及最终预期。列出明确要求、需要确认的解释和探索假设。先校验并冻结，再执行。保留目标、关键输入、角色、初始条件与规定路径；缺少权限时停止相关动作。依据实际观察判断，不把工具调用成功当成业务通过。按证据需要自行决定取证时机；关键结果优先通过 Ego 官方能力取得截图，再登记保存。报告全部目标的状态、实际观察、依据、证据、首次失败、补测和未覆盖项；区分已观察、已保存、已交付。清理测试数据前确认报告和必要证据已留存。

随后提供你的私有文件位置。不要粘贴密码、Cookie 或 token；使用宿主提供的安全登录流程。

../cases.example.json 只是上述虚构项目的 schemaVersion 3 用例格式样式，不是要在真实站点原样运行的测试集。它同时演示三类依据：明确要求可以形成验收结论；解释与探索必须保留未确认标签。助手不能从它自动获得环境权限、登录状态或浏览器执行能力。

首次本机试用应明确记录实际 Ego/系统版本、哪些操作确实完成、哪些受阻。云端文件校验通过不代表这次本机测试已经通过。

执行 `node scripts/ego.mjs report --run-dir ABS_RUN_DIR` 后，合成运行目录会包含 `report.json`、`report.md` 与可单独复制打开的 `report.html`。HTML 中只内嵌实际登记且通过 hash 校验的安全光栅截图，不生成样例图片；缺图和未验证目标会分开展示。

## 只有新需求，也可以开始

直接提供新需求/新功能说明即可，参见 feature-request.md。AI 将提取验收目标、分析影响范围并产生正向/反向/边界检查，保持每项来源与依据分类。无需你先把需求写成用例，也不逐项要求审批；只有关键规则歧义或权限问题才需要确认。部署与授权就绪后执行 Ego，否则交付待执行计划与阻塞原因。[生成用例示例](../generated-cases.example.json) 展示 F-01～F-04 的条件、步骤与预期。仅生成时无需浏览器或部署环境，交付 JSON 和待确认问题即可，不能称为已测试。可选 validate-cases 只读校验；start 接收 AI 整理后的 cases 并冻结基线，二者都不生成用例或执行浏览器。

步骤只需业务意图和必要输入，不必猜测界面细节。每步 expected 可省略，有明确依据的独立检查点才填写。整体 expected 与 basis 必填；缺失验收细节用 clarificationQuestions 明示，非空时结果与 attempts 禁止 pass/fail。AI 使用 Ego 探索具体路径，把实际行为写入结果，而不是把计划当证据。
